Sprint 1: Foundation Layer

Goal: Establish CLI skeleton, initialize Tree-Sitter integration, build basic STRUCT.xml output.
Duration: ~4 weeks | Steps: 8 | Exit condition: awos map generates STRUCT.xml for any language
1.1
Create .awos/ project memory directory
Initialize project soul storage. All persistent data (rules, patterns, decisions, cost history) lives here.
Exit: .awos/ initialized; XML templates valid; checked into repo
1.2
Add tree-sitter + language parsers to requirements
Pin Tree-Sitter Python bindings and language parser modules for initial scope (Python, C, C++, Rust).
Exit: Tree-Sitter + parsers installed; Python REPL can import language parsers
1.3
Implement TreeSitterCartographer class
Core parser class. Takes file path, language, returns AST + symbol list.
Exit: pytest tests/test_cartographer.py passes; fixtures extracted correctly
1.4
Build STRUCT.xml generator
Traverse repository tree, parse each file, produce hierarchical STRUCT.xml output.
Exit: pytest tests/test_struct_builder.py passes; STRUCT.xml output valid
1.5
Add file-watcher integration (Watchdog)
Detect file changes in real-time. Trigger incremental STRUCT.xml re-parse on modified files only.
Exit: File watcher detects modifications; updates STRUCT.xml incrementally within 1 second
1.6
Implement awos map CLI command
New entry point: awos map [--watch] [--output STRUCT.xml]. Generates initial STRUCT.xml from repo.
Exit: awos map works for Python + C/C++ projects; STRUCT.xml stable and parseable
1.7
Add language detection logic
Detect project primary language(s) by file count heuristic. Auto-select appropriate Tree-Sitter parsers.
Exit: detect_languages() accurately identifies primary languages; awos map auto-loads correct parsers
1.8
End-to-end test: Generate STRUCT.xml for AWOS_coding_agent repo
Dogfooding: Run awos map on this project. Verify it correctly indexes itself.
Exit: STRUCT.xml generated for AWOS_coding_agent; ≥20 symbols extracted correctly. Sprint 1 complete

Sprint 2: Intelligence Layer

Goal: Implement complexity scoring, model routing, HITL consent gate, pre-flight manifest.
Duration: ~4 weeks | Steps: 8 | Exit condition: awos run shows pre-flight manifest and routes to correct model tier
2.1
Implement complexity scorer
Tier 4 model (fast + cheap) scores task description → 1–10. Routing uses this score.
Exit: Scorer gives consistent scores for known tasks; scores match expected tier
2.2
Implement multi-provider model router
Maps complexity score → model tier → API provider. Returns (provider, model, estimated_cost).
Exit: Routing table matches published costs; all tiers testable without API
2.3
Build pre-flight manifest generator
Formats task + routing info into human-readable pre-flight manifest (ASCII art box).
Exit: Manifest renders correctly; matches spec example format
2.4
Implement consent gate (HITL)
Show manifest, pause for user input: [A]pprove, [S]witch, [O]mni-Mode, [D]eny.
Exit: Consent gate correctly parses user input; returns approval status
2.5
Add LiteLLM integration for multi-provider dispatch
Route API calls through LiteLLM. Supports DeepSeek, Claude, Gemini, etc. with fallback/retry logic.
Exit: LiteLLM client routes to correct provider; mock tests pass
2.6
Initialize COST_LOG.xml tracking
Log every API call: model, tokens, cost, cache hit %. Write to .awos/cost_log.xml.
Exit: COST_LOG.xml records test calls; totals calculated correctly
2.7
Integrate dispatcher into awos run command
awos run --task "..." → score → route → manifest → consent → execute.
Exit: awos run flow works end-to-end with mocked API; manifest displays correctly
2.8
Implement request escalation heuristic
If Tier 2/3 fails (build error, returned None), propose Tier 1 escalation with context.
Exit: Escalation detects failure; shows reason; user can approve higher tier. Sprint 2 complete

Sprint 3: Persistence & Optimization

Goal: Implement hydration protocol, prompt caching, SOUL.xml persistence, session dreaming.
Duration: ~4 weeks | Steps: 7 | Exit condition: Multi-task session shows 80%+ cost reduction; SOUL.xml learns patterns
3.1
Implement symbol hydration engine
Given STRUCT.xml + symbol ID, fetch source code for that symbol from disk.
Exit: Hydrator correctly extracts symbol source code; wrapper tags present
3.2
Integrate prompt caching wrapper (LiteLLM level)
Wrap API calls with Claude prompt caching support. Mark STRUCT.xml + system prompt as cacheable.
Exit: Mock tests show cache hits; cost reduction correctly calculated (90%)
3.3
Implement Hydration Protocol (Observe → Select → Hydrate)
Agent reads STRUCT.xml (observe), identifies needed symbols (select), fetches code (hydrate).
Exit: Protocol respects token budget; wraps code correctly
3.4
Create SOUL.xml schema and persistence layer
Define SOUL.xml structure (invariants, patterns, decisions, cost_history). Load/save to .awos/soul.xml.
Exit: SOUL.xml reads/writes correctly; XML valid; data round-trips without loss
3.5
Implement session dreaming cycle
On session end, extract logs → call Tier 4 → parse rules/patterns → merge into SOUL.xml.
Exit: Dreaming extracts + merges patterns; SOUL.xml learns from sessions
3.6
Add session checkpoint + dreaming to CLI
awos end-session → write checkpoint → call dreaming → update SOUL.xml.
Exit: End-session command works; checkpoints + SOUL.xml updated correctly
3.7
End-to-end multi-task session with caching + SOUL learning
Run synthetic 5-task session: score → route → manifest → execute → hydrate → cache. End session, dream, verify SOUL.xml.
Exit: Full flow works; demonstrates caching benefit + SOUL learning. Sprint 3 complete; v2 MVP ready
