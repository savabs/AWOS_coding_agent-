Planning checkpoint — completed in this session

Review result: The existing research and implementation outline are coherent. The first implementation gate is complete: claim scope, truth semantics, schemas, reports, and bundle layout are implemented and tested. The next gate is runtime evidence normalization.
Frozen rule: A proven observation is not automatically a proven root cause. Every finding must name its claim type, proof rule, evidence references, and bounded conclusion. Heuristics may rank hypotheses but cannot produce PROVEN.
STEP 1
Implement the frozen truth model, schemas, and bundle layout
Exit condition: The implementation represents claim type, PROVEN/HYPOTHESIS/UNKNOWN, evidence classes, versioned proof references, reports, and append-only bundles; round-trip and integrity tests pass.
Planning is complete in the governing spec. Implementation must now follow the claim-scoped contract: observation proof never silently becomes root-cause proof.
STEP 2
Normalize current runtime artifacts into debugger evidence
Exit condition: spans.jsonl, telemetry.jsonl, and events.jsonl can be read as one normalized evidence model.
Implemented in scaffold/agent/core/debug_adapters.py with source references, stable IDs, timestamp validation, and preserved payloads.
STEP 3
Unify legacy and current event vocabularies
Exit condition: Old and new sessions normalize to one canonical event taxonomy without losing meaning.
Legacy aliases are mapped while original event names remain in the evidence payload for auditability.
STEP 4
Implement deterministic proof rules
Exit condition: Recorded verifier/test/crash/edit artifacts can produce PROVEN findings through explicit rules.
STEP 5
Integrate verification and test outputs into the rule engine
Exit condition: Verification/test failures generate explainable proof artifacts in debug reports.
Implemented in scaffold/agent/core/debug_runtime.py for real Verifier dictionaries and TestResult records.
STEP 6
Integrate fault localization as attribution-only input
Exit condition: Localization can rank likely causes, but cannot produce PROVEN findings by itself.
Implemented in scaffold/agent/core/debug_attribution.py; all localization output is a ROOT_CAUSE hypothesis.
STEP 7
Add a ranked suspicion engine for unsupported cases
Exit condition: Unsupported cases become ordered hypotheses rather than hallucinated bugs.
Implemented in scaffold/agent/core/debug_suspicion.py with bounded weighted signals; it cannot emit proof metadata.
STEP 8
Add rerun/checkpoint requests for proof-by-rerun
Exit condition: The debugger can describe how to reproduce a suspected issue from a session/task/event boundary.
Implemented in scaffold/agent/core/debug_rerun.py; request validation requires a source boundary and frozen inputs.
STEP 9
Resolve findings after rerun
Exit condition: Rerun outcomes update findings explicitly without overwriting non-reproducible evidence.
Implemented in scaffold/agent/core/debug_resolution.py; proven observations are preserved and root-cause reproduction remains non-proof.
STEP 10
Add debugger CLI/API inspection surfaces
Exit condition: Reports and rerun plans can be inspected programmatically without the GUI.
Added read-only inspection via scaffold/agent/core/debug_inspection.py and awos debug-report <session_id>.
STEP 11
Add debugger UI surfaces to the Agent Console
Exit condition: The app distinguishes facts, hypotheses, and unknowns clearly for both success and failure runs.
Added the Evidence Debugger section to gui/static/agent.html and read-only /api/debug/<session_id> support in gui/server.py.
STEP 12
Build the benchmark/eval suite and optional OTel/OpenInference export
Exit condition: The debugger’s anti-hallucination contract is benchmarked, and external export is added only after native reports are trusted.
Added tests/test_debug_benchmark.py. External telemetry export remains intentionally deferred and is not required for native truth.

Blocked / Decisions

This task is currently in planning-complete, implementation-not-started state. The repo now has governing research and a detailed spec, but no debugger code has been added in this session.

Decision Log

2026-07-26: Chosen architecture is a custom AWOS debugger core built on top of existing AWOS JSONL journals and informed by OpenTelemetry + OpenInference. External systems may serve as viewers or exporters, but AWOS itself remains the authority on issue truth status.
2026-07-26: The debugger will separate truth classification from investigation ranking. Heuristics and confidence scores may order work, but they may not produce PROVEN findings without deterministic evidence or proof-by-rerun.
