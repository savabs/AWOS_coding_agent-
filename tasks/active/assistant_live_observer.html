Task: Assistant Live Observer

Status: active · Phase: 1 · Started: 2026-07-27

Goal: Build the durable, correlated live event bridge that lets an assistant understand AWOS UI actions and backend execution without screenshots or historical-session confusion.

Spec: assistant_live_observer_spec.html · Research: assistant_live_observer.html

Atomic steps

☑ 1. Define versioned event envelope — implemented in observer_protocol.py and validated by tests/test_assistant_live_observer.py.
☑ 2. Assign stable event IDs and sequence cursors — persisted by GuiEventBus and resumed after ledger reopen.
☑ 3. Add session/chat/trace correlation — chat stream, orchestrator, and task events now share correlation fields.
☑ 4. Classify and redact assistant-safe payloads — assistant projection drops internal events, redacts credentials, and bounds payloads.
☑ 5. Emit meaningful UI action events — semantic UI actions persist on the dedicated ui stream without raw prompt content.
☑ 6. Add cursor-based replay — bounded /api/observer/events replay reports gaps and malformed lines.
☑ 7. Add resumable filtered SSE — explicit session/type stream has SSE IDs, retry, keepalive, and resume support.
☑ 8. Add compact current-state snapshot — runtime-aware state projection includes correlation, work, evidence, cursor, and freshness.
☑ 9. Add read-only assistant observer adapter — CLI snapshot/events commands are read-only and cursor-aware.
☑ 10. Migrate renderer to the shared observer contract — renderer now loads snapshot/replay and follows explicit observer SSE.
☐ 10a. Instrument the actual Electron entrypoint — /agent serves gui/static/agent.html, which currently bypasses the semantic UI observer hooks.
☐ 11. Run Electron live listener proof — after the Electron entrypoint emits UI events, open Electron, submit a bounded coding task, follow the correlated backend session, and verify reconnect/replay.
☐ 12. Run focused tests, docs lint, quality gate, and checkpoint — focused tests, compile, diff check, and scoped docs lint pass; quality gate remains pending live proof.

Decisions

  • Structured telemetry is primary; screenshots are out of scope for the first observer.
  • SSE remains the live push transport; JSONL/cursor replay remains the recovery source.
  • The event contract is reusable kernel infrastructure, not chat-specific glue.
  • No hidden chain-of-thought is exposed; only observable actions, summaries, tool metadata, and evidence.
  • MCP may be added later as an adapter, not as the initial kernel dependency.
