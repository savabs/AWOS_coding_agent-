Task: Planner-Worker Orchestrator Implementation

Build hierarchical agent system for 93% cost reduction on token-based AI development

Objective

Implement a 4-module system (Planner → Worker → Verifier → Orchestrator) that reduces AI development cost from $40/month (Copilot) to <$25/month (direct API with intelligent model selection) while maintaining or improving feature delivery speed.

Success Criteria

  • All 10 specification steps completed and tested
  • End-to-end test: Execute a real feature request, complete all tasks, total cost <$0.10
  • Cost tracking accurate and visible in unified agent output
  • Error handling: Broken worker output caught by verifier, auto-retry succeeds

Progress

0 / 10 steps complete

Step Checklist

Step 1: Create planner.py module
Implement Sonnet interface that converts user goals into atomic JSON task blueprints. File: scaffold/agent/planner.py
Step 2: Add cost tracking to planner
Record Sonnet API calls (token count, cost) to token_tracker. Expected cost: ~$0.03-0.05 per planning call.
Step 3: Create worker.py module
Implement DeepSeek interface that executes micro-tasks (SEARCH/REPLACE generation). File: scaffold/agent/worker.py
Step 4: Add cost tracking and retry to worker
Track DeepSeek calls, implement fallback to Haiku on rate-limit. Expected cost: ~$0.001-0.002 per task.
Step 5: Create verifier.py module
Implement local compiler/lint integration that validates SEARCH/REPLACE changes. File: scaffold/agent/verifier.py
Step 6: Add error feedback loop to verifier
Return structured error context for worker retry. Enable auto-fix on compilation failures.
Step 7: Create orchestrator.py module
Implement task loop: plan → execute → verify → retry logic. File: scaffold/agent/orchestrator.py
Step 8: Integrate orchestrator into unified_agent.py
Add Planner-Worker mode to menu, wire cost tracking, display progress and final report.
Step 9: Write integration tests
Create tests/test_planner_worker.py with 5 core tests (valid JSON, SEARCH/REPLACE parsing, error catching, end-to-end, cost accuracy).
Step 10: Real-world validation
Use PW to build a real feature (e.g., add progress bar to agent menu). Feature must be live, cost <$0.10.

Implementation Notes

Order matters: Complete steps 1-2 (Planner) before 3-4 (Worker) before 5-6 (Verifier). Steps 7-8 can use all three modules. Only then do tests (step 9) and validation (step 10).

Cost tracking: All API calls go through existing TokenTracker (already built). Each module passes tracker instance and logs with request_type: "planning" (Planner), "execution" (Worker), "verify" (Verifier, cost=0 since local).

Error handling: Worker may fail if DeepSeek hallucinates syntax. Verifier catches and returns structured error. Orchestrator retries worker call (max 2 retries). If all retries fail, mark task as failed and continue (don't stop entire feature).
