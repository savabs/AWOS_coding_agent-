# User Communication Preferences

- Explain technical results in plain language first.
- Avoid unexplained jargon. If a technical term is necessary, define it immediately in parentheses.
- Always answer three practical questions: **What happened? Why does it matter? What happens next?**
- Use concrete examples when explaining failures or trial results.
- Be clear and direct rather than overly formal or abstract.
- Before asking the user to authorize or run something, state exactly what it will do, whether it costs money, and what risk remains.
