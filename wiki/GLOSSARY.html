Core Workflow Terms

AWOS (Agent Workflow Operating System)
The living doctrine document defining how agents and humans collaborate on complex projects. Covers planning, memory, tool use, math, security, and session management. Canonical file: AWOS.md.
See: AWOS.md
Research → Spec → Task Triad
The three mandatory artifacts before any implementation: a research note (docs/research/), a specification (docs/specs/), and a task file (tasks/active/). Together they form the implementation contract and execution checklist.
Preflight Gate
The check that all three triad artifacts exist and are current before any implementation code is written. Fail-closed: no triad = no implementation.
Atomic Step
A step so small it changes one thing, tests one thing, and proves one thing. If the description contains "and," it is probably not atomic. Apply the one-line test, "and" test, and revert test before executing.
Leaf Node
A component that nothing else depends on. Ideal target for agent-owned implementation because the blast radius is small if it is wrong.
Write-Gate Protocol
The rule that a decision is not complete until it exists in a canonical file in the same turn as approval. Deferred writes are forbidden — if the session ends first, the decision is lost.
Single-Owner Rule
Each fact lives in exactly one canonical file. All other files link to it; copies are forbidden. Prevents fact drift.
Fact Drift
When the same fact is copied to multiple files and the copies diverge over time. Prevented by the Single-Owner Rule. Detected by scripts/fact_lint.py.
HTML-First Artifacts
All output artifacts (research notes, specs, task files, ADRs, wiki pages, checkpoints) are primary HTML files with a thin Markdown stub for Obsidian indexing. Plain MD remains OK for: README, stubs, append-only logs, doctrine docs.
See: AWOS.md §5.7

Memory Terms

Working Memory
The current context window — everything the agent "has in mind" right now. Finite (typically 8K–200K tokens). Cleared between sessions unless serialised. The most expensive resource in an agentic system.
Episodic Memory
Immutable timestamped log of events: what happened, when. The history layer. AWOS canonical files: checkpoint files, debug log. Never edited after writing.
Semantic Memory
Named fact store: what is known, with confidence levels (verified / inferred / uncertain). AWOS canonical files: memories/repo/project_structure.md, runbooks. Updated when facts change.
Procedural Memory
Numbered, atomic, executable instructions for recurring tasks. AWOS canonical files: protocols/*.md, docs/<platform>_runbook.md. "Do the usual thing" is not a procedure.
Checkpoint
A session summary written at the end of a work segment. Immutable after writing — it is a historical record, not a living document. Must include: what changed, what is blocked, source of truth for next session.

Tool Terms

Tool Result Envelope
The standard wrapper all tools must return: {success: bool, text: str, data: dict, error: str, latency_ms: float}. Non-conforming results must be normalised at the boundary before the agent processes them.
Tool Registry
The component that registers, validates, and dispatches tool calls. Tools are not called by raw name string — all execution flows through the registry. Tool descriptions must be unambiguous.
Cache TTL
Time-to-live for cached tool results. Default: 6 hours. Prevents redundant external API calls while allowing freshness.
Idempotent Tool Design
Tools that modify state must produce the same result when called twice with the same arguments. Non-idempotent tools must use a check-before-write pattern to prevent duplicate side effects.

Agent Architecture Terms

ReAct
Agent loop that interleaves Thought → Action → Observation in a single context window. Default for single-agent task execution. Traces exceeding 5 tool calls must be checkpointed.
See: AGENTIC_CONCEPTS.html §1.1
Plan-and-Execute
Architecture separating a planner (creates full task graph) from executors (run each step). Maps to the Research → Spec → Task triad. Planner re-evaluates on executor failure.
See: AGENTIC_CONCEPTS.html §1.2
Reflexion
Post-attempt self-critique written to episodic memory, prepended on retry. Operationalised by the DEBUG_PROTOCOL two-failed-attempt rule. Limit to 3 cycles before escalating.
See: AGENTIC_CONCEPTS.html §1.3
LATS (Language Agent Tree Search)
Monte Carlo Tree Search over the agent action space. Requires a well-calibrated value function. High compute cost — k=5, depth=4 = 625 LLM calls. Never run locally (P1 — compute rule).
See: AGENTIC_CONCEPTS.html §1.4
Critic-Actor
Two-role pattern: Actor generates output; Critic scores with structured feedback ({score, blocking_issues, suggestions}). Actor never self-approves. Maximum 3 revision cycles; escalate if score does not improve.
See: AGENTIC_CONCEPTS.html §1.5
Orchestrator-Worker
One orchestrator manages the plan; stateless workers run subtasks. Workers communicate only through the orchestrator — never directly. Orchestrator validates worker output before passing downstream.
See: AGENTIC_CONCEPTS.html §6.1
Context Budget
Token allocation across system prompt (~500–2000), task instructions (~500–1000), retrieved knowledge (~2000–5000), tool results (~1000–3000), reasoning trace (~1000–4000), output buffer (~500–2000). Tool results exceeding 1000 tokens must be compressed before appending.
See: AGENTIC_CONCEPTS.html §7.1
Ratchet State
A persisted record of the best-known metric that blocks any checkpoint regressing it. Canonical file: data/ratchet_state.json. This is semantic memory — update after every successful training run.
See: AGENTIC_CONCEPTS.html §5.5
Evaluation Gate
Boolean criterion blocking stage progression until a falsifiable, reproducible metric threshold is met. Defined before training begins — never adjusted post-hoc. A gate that always passes must have its bar raised.
See: AGENTIC_CONCEPTS.html §5.4
Chain-of-Thought (CoT)
Reasoning pattern: agent writes step-by-step reasoning before producing the final answer. Required for all non-trivial decisions. Decisions that required multi-step reasoning must be checkpointed (Write-Gate).
Tree-of-Thought (ToT)
Reasoning pattern: generate and evaluate multiple candidate thoughts at each step; prune weak branches. Cost O(kd). Use selectively for high-stakes design decisions where errors are expected to be random, not correlated.

Debugging Terms

Debug Protocol
A 6-step procedure activated after 2 failed fix attempts: Reproduce → Instrument → Hypothesize → Verify → Fix → Regress. After steps 1–4, if the hypothesis is wrong — go back to step 3 with new evidence. Do not guess.
See: DEBUG_PROTOCOL.md
Two-Failed-Attempt Rule
After 2 unsuccessful fixes on the same problem, mandatory switch to the debug protocol. No 3rd attempt without completing Steps 1–4. A hard rule — a fix that was not researched is a guess.
Local Falsifiable Hypothesis
Before any bug fix edit, state: "I think the bug is at [location] because [reasoning]" and "This check would disconfirm it: [check]." Forces honest verification before touching code.

Knowledge Graph Terms

Wiki Link
An Obsidian-style cross-reference: [[filename]] or [[filename|display text]]. Obsidian resolves by filename stem — no path prefix needed. Survives file moves; bare paths do not.
Frontmatter
YAML metadata block at the top of every Markdown file between --- delimiters. Mandatory fields: title and tags. Enforced by scripts/obsidian_lint.py.
Tag Taxonomy
Hierarchical tags with / separators. Categories: doc/ (type: research, spec, task, adr, checkpoint, wiki), status/ (active, done), phase/ (N), topic/ (slug), layer/ (slug).
Backlink
A link from document B to document A. In Obsidian, visible in the backlinks panel. Programmatically discoverable: grep -r "[[filename]]" docs/ tasks/ wiki/.
Orphan
A Markdown file with no incoming wiki links. Advisory finding (LK02) from scripts/obsidian_lint.py. Not necessarily wrong, but worth reviewing.
ADR (Architecture Decision Record)
A document capturing a significant design decision: context, options considered, decision, rationale, consequences. Numbered sequentially in docs/adr/. Never deleted — only superseded.
