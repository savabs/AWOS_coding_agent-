## The issue in one paragraph

`soup data review | inspect | validate | stats | dedup` crash with `AttributeError` (exit 1, no line number) when a `.jsonl` line is valid JSON but not an object (`"abc"`, `[1,2]`, `42`, `null`). A `.json` array holding a scalar crashes `inspect` the same way. The cause is that `_load_jsonl` appends whatever `json.loads` returns, and `_load_json` returns the list unchecked. `review_cmd` has its own `json.loads` loop. The issue asks for a warning that names the line, the row to be skipped (matching the existing invalid-JSON handling), and tests across all five commands.

## What AWOS changed and why

- `src/soup_cli/data/loader.py`: `_load_jsonl` now warns `line N is a JSON <kind>, not an object -- skipped` and skips the row, right after the existing `invalid JSON on line N` branch. `_load_json` does the same per item (`item N is a JSON number…`). A small `json_kind()` helper maps Python values to JSON type names, checking `bool` before `int`.
- `src/soup_cli/commands/data.py`: `review_cmd` enumerates lines and skips non-dict entries with the same warning.
- `tests/test_issue1860_non_object_rows.py` (named in the project's `test_issueNNNN_*` style): 20 parametrized CLI cases (5 commands × 4 bad values). Each asserts exit 0, no `AttributeError`, and `line 2 is a JSON … not an object` in the output.
- `tests/test_loader.py`: one unit test for `.jsonl` and one for `.json`.
- `changelog.d/0.76.0/1860.fixed.md`: one line.
