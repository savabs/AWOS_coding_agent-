## The issue in one paragraph

#1779 made `soup eval gate` refuse NaN/inf baseline scores with `ValueError`, which callers turn into exit code 3. An integer too large for a float (`10**400`) still raises `OverflowError` before that check, at three sites in `eval/gate.py` (`_coerce_score_map`, `stamp_baseline_scores`, `run_gate`). So `soup eval gate` / `soup ship --baseline` exit 1 with a raw `OverflowError`, and two callers that promise not to crash let it escape. The issue proposes a fix: one shared `_finite_score` helper that converts `OverflowError` to `ValueError`, refuses rather than clamps, and does not echo the raw value.

## What AWOS changed and why

- `src/soup_cli/eval/gate.py`: adds `_finite_score(value, *, name, context)`. It wraps `float(value)` in `try/except OverflowError` and raises `ValueError("… for 'control' must be finite (out of range)")` without echoing the value, then applies the existing `math.isfinite` check with the existing message. All three sites now go through the helper, so `run_gate` no longer calls `math.isfinite` on the raw value. The nan/inf message wording is unchanged: existing tests that match it still pass.
- `tests/test_eval_gate.py`: 9 new tests, written and run red before the fix. They cover `resolve_baseline` on a flat file and on a stamped file, `stamp_baseline_scores` + `write_baseline_file` (asserting no file is created), and `run_gate` (asserting the huge value is not in the message), each with `±10**400`, plus `soup eval gate --baseline` → exit code 3.
- `changelog.d/0.76.0/1865.fixed.md`: one line in the style of the neighbouring fragments.

Net: +91 / −16 across 3 files. No caller changes, as the issue asked.
