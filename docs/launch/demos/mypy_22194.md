## The issue in one paragraph

```python
TextInput: TypeAlias = str
ImageInput: TypeAlias = str | None
SingleInput: TypeAlias = TextInput | ImageInput
def f(si: SingleInput) -> None: ...
f(1)   # expected "str | str | None"   <- should be "str | None"
```

Union items are deduplicated before the aliases are expanded, so the formatter prints the same item twice.

## What AWOS changed and why

- `mypy/messages.py`, in `format_type_inner.format_union_items`: adds a local `flatten_union_items` that expands nested unions behind aliases (`get_proper_type`). It then deduplicates the formatted item strings in first-occurrence order (`dict.fromkeys`), keeping the existing "`None` goes last" rule. The fix is display-only; type checking is unchanged.
- `test-data/unit/check-type-aliases.test`: new case `testOverlappingUnionAliasNoDuplicateItems` with the issue's repro (written with `Optional`/`Union` and `typing_extensions.TypeAlias` to match the test stubs), expecting `"str | None"`.

## Review notes (strict maintainer)

1. **Reuse the existing helper.** `mypy.types.flatten_nested_unions` is already imported in `messages.py`. It does exactly this, including the `handle_recursive` guard for recursive aliases. The hand-rolled `flatten_union_items` duplicates it and lacks that guard. The fix should be `flat = flatten_nested_unions(types)`.
2. **Formatting.** Run `black` (the `dict.fromkeys(...)` call fits on one 99-column line).
3. Optional: also add the PEP 604 form of the repro (`str | None` with `[builtins fixtures/type.pyi]` or similar), since that is what the reporter wrote.
4. Design question for the maintainers: they may prefer fixing this where the union is built, not where it is printed. A formatter-level fix is defensible because the type itself is correct and only the message is wrong, but say so in the PR description.

After 1 and 2 the diff would get smaller and I would be comfortable sending it.
