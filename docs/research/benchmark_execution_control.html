Research: Benchmark Execution Control

Status: active · 2026-07-31

Observed failure chain

  1. Non-interactive plan review receives EOF and continues instead of failing closed.
  2. ReAct tasks exhaust turns without a deterministic completion path.
  3. Failed tasks trigger recursive decomposition, multiplying provider calls.
  4. Stagnation relies too heavily on repeated signatures and detects state-without-progress late.
  5. The holdout budget is not visibly propagated to the orchestrator; logs showed $20 while the trial cap was $0.50.
  6. Outer timeout can terminate before a candidate report is finalized.

Relevant modules

  • scripts/run_holdout_live.py: one-task holdout validation, timeout, report finalization.
  • scaffold/agent/evaluation_v1.py: trial lifecycle and truthful result semantics.
  • scaffold/agent/orchestrator.py: plan review, task execution, decomposition, budget and stagnation behavior.
  • scaffold/agent/react_worker.py: bounded model/tool loop and completion.
  • scaffold/agent/exploration_phase.py: grounded planning evidence.

Design direction

Introduce explicit benchmark-mode execution invariants: fail closed on unavailable approval, disable recursive decomposition by default, share the external budget, stop on verified progress, constrain tools, and always emit a terminal report.

Non-goals

  • No new provider or dependency.
  • No broad Markdown cleanup.
  • No claim of SWE-bench capability from infrastructure-only tests.
