Research: CI Workload Decoupling

Status: active · Phase: 1 · Topic: CI workload decoupling

CI repair remains an optional coding-agent workload, not the identity of the kernel or canonical interface.

Findings

  • The orchestrator is already documented as domain-agnostic.
  • CI discovery/planning/TUI modules can remain workload adapters.
  • Canonical GUI statistics/history routes still use ci-rescue naming.
  • Existing CI routes and mission flags need compatibility preservation.

Safe boundary

Make generic session routes canonical, keep CI aliases, retain CI benchmark code, and avoid changing the generic orchestrator in this slice.
