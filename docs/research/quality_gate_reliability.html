Research: Quality Gate Reliability

Observed failures

  • obsidian_lint.py scans generated .awos/worktrees and legacy Markdown, producing thousands of unrelated findings.
  • quality_gate.py runs the entire repository suite by default, which includes slow/flaky integration paths and can report pytest internal errors unrelated to the changed task.
  • Linting needs a narrow, explicit scope for incremental task completion while preserving a separate full-vault audit command.

Decision

Add safe generated-directory exclusions to the linter and add an explicit file-list mode. The quality gate will lint the task's adjacent canonical HTML/Markdown artifacts, not historical repository debt. The full-vault command remains available for deliberate cleanup work.

Safety

No test failures are hidden: test command failures remain failures. The gate only changes lint scope and makes the test command configurable; it does not reinterpret pytest exit codes.
