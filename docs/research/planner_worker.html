Research: Planner-Worker Architecture

Cost-optimized hierarchical agent orchestration for sub-$25/month token budgets

Problem Statement

Current token consumption is 20-100M/month. Traditional monolithic agent prompting wastes 60-80% of cost:

  • Expensive model (Sonnet) does both reasoning AND coding in one prompt
  • If coding fails, entire expensive context is re-run
  • No parallelization; model types linearly
  • Junior models unused (cheaper than Sonnet)

Core Insight: Separation of Concerns

Planning is expensive. Execution is cheap.

  • Planner (Sonnet): Understand goal, create atomic blueprint → ~$0.03-0.05 per feature
  • Worker (DeepSeek): Execute each micro-task → ~$0.001 per task
  • Verifier (Local): Compile/lint, catch errors → free

Why this works: Junior models excel at narrow, well-defined tasks. By giving DeepSeek only 50 lines of context + one instruction, its accuracy matches Sonnet on that specific task, at 1/18th the cost.

Architecture Phases

Phase 1: Observation (Context Gathering)

User provides goal. System loads STRUCT.xml (codebase map) and SOUL.xml (rules). No API calls yet.

Phase 2: Planning (Sonnet)

Send: Goal + context maps + constraints. Receive: Machine-readable JSON blueprint.

[
  {"task_id": 1, "file": "src/ingestion.cpp", "action": "Add struct...", "complexity": "low"},
  {"task_id": 2, "file": "src/radar.cpp", "action": "Update buffer...", "complexity": "medium"}
]

Cost: ~$0.03-0.05 per feature request

Phase 3: Execution (DeepSeek Worker Loop)

For each task in JSON: Extract task → Load 50-line context window → Send to DeepSeek → Receive SEARCH/REPLACE.

Cost: ~$0.001-0.002 per task

Phase 4: Verification (Local Compiler)

Apply SEARCH/REPLACE → Run g++ / pytest → If error, feed to worker for fix (retry cost ~$0.0001).

Cost: Free (local execution)

Why This Breaks Traditional Pricing

  • Isolation of failures: If task 5 fails, only task 5 reruns ($0.0001), not the whole $0.60 feature
  • Parallelization: Tasks 1, 2, 3 can execute simultaneously via async calls → faster feature delivery
  • Micro-context: Junior models don't see 10k lines of irrelevant code → accuracy increases, cost decreases
  • Reusable plans: Same plan can be executed 10x (cost = 1 plan + 10 executions, not 10 full runs)

Implementation Requirements

  • Planner module: Sonnet API calls, structured output (JSON)
  • Worker module: DeepSeek API calls, SEARCH/REPLACE parsing
  • Verifier module: Local compiler/linter integration, error parsing
  • Orchestrator module: Task loop, parallelization, cost tracking, retry logic
  • Integration: Unified agent entry point for mode detection (plan vs execute)

Known Risks

  • Sonnet planning output must be valid JSON (parser needed)
  • DeepSeek can hallucinate syntax; verifier must catch and retry
  • Context windows are small; large features need multiple tasks
  • API rate limits could delay parallelization

Success Metrics

  • Monthly cost <$25 for 100M token usage
  • Feature delivery time same or faster than Sonnet-alone
  • Syntax error rate <5% (caught by verifier)
  • Plan accuracy >95% (matches delivered feature)
