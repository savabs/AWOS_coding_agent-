Research: Agent Loop Control Comparison

Project: AWOS · Date: 2026-08-01 · Status: active

Question

Why did the successful Controlled9 SWE-bench run spend turns 6–12 searching for unavailable tests, and what control-loop behavior should AWOS learn from leading open-source coding agents?

AWOS baseline

  • scaffold/agent/react_worker.py runs a fixed _MAX_TURNS loop, default 12.
  • The worker records tool results and detects repeated failures, but successful repeated reads/searches are only treated as stagnant when the exact action repeats.
  • finish is a model action. Final success is decided later from changed files and an optional test result.
  • The SWE-bench evaluator owns the hidden acceptance command, but the worker is not currently given that command as a first-class completion contract.
  • Controlled9 passed independently, but the trajectory shows poor turn allocation after the edit.

Conclusion

The immediate bug is not only a 12-turn limit. It is that AWOS has no explicit transition from “edit completed” to “run the required proof now,” and no independent rule that repeated successful but uninformative exploration is not progress. Increasing the limit without fixing those controls would buy more wasted calls.

Risk: A stricter verification gate can stop a run that is actually correct when no public test exists. Mitigation: classify “no tests found” as inconclusive, retain the independent evaluator, and report the distinction truthfully.

Non-goals

  • Do not copy another agent’s architecture.
  • Do not add a new provider or dependency.
  • Do not run another paid SWE-bench trial as part of this research.
