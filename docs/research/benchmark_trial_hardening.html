Research: Benchmark Trial Hardening

Date: 2026-08-01

Observed failures

  • The third SQLFluff trial used the correct interpreter but pytest created .pytest_cache and Hypothesis created .hypothesis in the candidate workspace. The evaluator treats those paths as unsafe writes.
  • Benchmark planning produced two tasks even though the fixture allowed one implementation path, consuming the ReAct turn budget searching for tests.

Current insertion points

  • scaffold/agent/test_runner.py builds and executes pytest commands.
  • scaffold/agent/coding_tools.py builds requested-path test commands.
  • scaffold/agent/evaluation_v1.py passes benchmark configuration into the orchestrator.
  • scaffold/agent/orchestrator.py accepts planner output and begins execution.
  • tests/test_fixed_opencode_go_agent.py contains benchmark regressions.

Verified source

Hypothesis example database documentation: the default database is a directory under .hypothesis in the current working directory; database behavior is controlled by Hypothesis settings.

Decision

Benchmark test subprocesses will receive isolated temporary cache/home locations outside the candidate workspace and pytest will run with -p no:cacheprovider. Benchmark planning will enforce one executable task when the fixture exposes one allowed implementation path; general Build mode remains unchanged.

Risks and non-goals

  • Do not add cache directories to allowed paths; that would weaken the safety gate.
  • Do not globally constrain Build-mode decomposition.
  • Temporary directories must be cleaned by the operating system or explicit lifecycle code and never become candidate changes.
