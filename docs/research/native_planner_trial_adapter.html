Research: Native Planner Trial Adapter

Status: pre-implementation · Date: 2026-08-03

Problem: the live holdout adapter currently injects a one-file pre-planned task in benchmark mode, so the Planner never runs for the common one-allowed-path case.

Current Flow

  1. run_holdout_live.py calls make_orchestrator_agent(..., benchmark_mode=True).
  2. make_orchestrator_agent creates a synthetic task when the fixture has exactly one allowed path.
  3. It passes that task as pre_planned

    _tasks    .
    4. <li>Orchestrator.execute_feature> detects pre_planned_tasks and skips both advanced Planner and CheapPlanner.

Required Flow

  1. The live adapter requests native-planner mode explicitly.
  2. No synthetic task is injected in that mode.
  3. The orchestrator calls the advanced Qwen Planner.
  4. The Planner returns a native execution graph.
  5. The graph is executed by the orchestrator; DeepSeek Pro remains the atomic worker.
  6. Trajectory evidence records whether
    7. planning ran and which provider/model roles were used.

Safety Findings

    >Default benchmark behavior must remain unchanged because existing tests and deterministic evaluations intentionally use pre-planned tasks.
  • Native mode must be opt-in and used
    • only by the explicitly authorized live holdout command.
  • The adapter must never log credential values.
  • Evaluator-owned acceptance and safety checks remain
    • authoritative.
  • Missing route evidence should
    • be visible in the trajectory, not treated as proof that planning occurred.

Non-goals

    >No live provider call during implementation tests.
  • No change to Planner or worker model routing.
  • No change to the one-task holdout contract, budget, timeout, or digest validation.
  • No removal of the legacy pre-planned benchmark path.
