Research: Production Hardening Single Run

phase/1 · topic/production-hardening · active · 2026-08-09

Scope

This slice hardens the existing single coding-run path before sandboxing, release automation, or self-learning. The supported initial workload is a repository bug-fix task producing a verified patch or draft PR; automatic merge and deployment are out of scope.

Known evidence

  • scaffold/agent/exploration_phase.py already emits bounded, deterministic snapshots and reserves explicit paths.
  • scaffold/agent/orchestrator.py validates strict plan evidence against snapshot candidate, hit, and test files.
  • scaffold/agent/planner_graph_contract.py already validates graph version, node fields, paths, dependencies, cycles, metadata bounds, and legacy projection.
  • Existing tests cover nested outer .awos, explicit out-of-sample targets, graph hints, unknown fields, dependency errors, and native execution.
  • The latest targeted run exposed subprocess timeout in symbol retrieval tests; performance must be treated as a release concern, not hidden by a larger timeout.

Gap to investigate

Trace the live planner path and verify whether path grounding and graph normalization are enforced consistently across legacy-plan, native-graph, and real orchestrator paths. Add only the missing contract tests first.

Risks

Do not infer production readiness from unit tests or one benchmark task. Preserve the current worktree; unrelated modified/untracked artifacts are out of scope. Do not expose credentials in evidence.

Research sources

  • Existing AWOS planner-grounding research and tests.
  • OpenHands SDK: durable state, replay, sandbox portability, and typed tools — arXiv 2511.03690.
  • SWE-ReX: separation of agent logic from sandbox execution — GitHub.

Conclusion

The first implementation target is a provider-free canonical path contract and a graph compatibility regression slice. If those pass, proceed to durable run contracts. If they fail in more than two iterations, stop and follow the debug protocol.
