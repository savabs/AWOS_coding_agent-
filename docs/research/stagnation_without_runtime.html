Research: Stagnation Without Runtime Sessions

phase/1 · topic/recovery · active · 2026-07-31

Observed failure

In the live trial, repeated ReAct tool failures triggered _check_stagnation(). The branch unconditionally dereferenced self._runtime_session.pause_reason, although runtime sessions were disabled and the field was None.

Required behavior

Stagnation must stop the current execution safely in both runtime-enabled and runtime-disabled modes. Runtime metadata may be persisted only when a runtime session/store exists.

Non-goals

  • Do not disable stagnation detection.
  • Do not add retries or provider calls.
  • Do not hide the original worker failure.
