Native Contract

The advanced Planner response will contain execution_graph with graph_version and typed nodes. Nodes contain only executable intent and evidence requirements—not hidden chain-of-thought.

  "graph_version": "1",
  "nodes": [

Risks

  • Structured-output API support can vary by model/provider deployment; tests must mock the request and parser.
  • A valid JSON
    • graph can still be unsafe or semantically vague; deterministic validation remains authoritative.
  • Native graph nodes may not have a one-file legacy task projection, so
    • projection must be explicit and incomplete nodes must not be silently executed as edits.
  • Prompt/schema changes affect advanced-model token cost; the graph should
    • carry only necessary fields and use caching for stable instructions.
  • Planner graph output must not give cheap models authority to change project decomposition.

Non-goals

  • No automatic native-graph execution wiring in this
    • slice.
  • No change to CheapPlanner responsibility or model tier.
  • No new dependency; use the existing Anthropic SDK and stdlib validation.
  • No hidden reasoning storage.

Conclusion

Add a provider-free graph contract validator, request the contract from the advanced Planner using structured JSON output, and provide a deterministic legacy task projection. Native graph execution remains a separately gated follow-up.
