Research: Authenticated Electron Control Bridge

Status: ready for implementation · Date: 2026-07-28

Question

How can AWOS give the assistant reliable control of the user’s already-running Electron app while preserving the live observer’s truth, avoiding hidden test windows, and preventing arbitrary desktop or shell access?

Findings

  • Electron’s main process owns BrowserWindow and can show, hide, focus, reload, navigate, and close the real window.
  • Electron’s webContents can execute JavaScript in the current renderer and send input events. DOM-targeted actions are more reliable than screen coordinates for this app.
  • The existing Python observer server cannot directly access the Electron BrowserWindow; a small control listener in Electron’s main process is the correct insertion point.
  • The control listener must bind to 127.0.0.1, require an ephemeral token, enforce a command allowlist, bound request sizes/timeouts, and append audit records.
  • Structured control events must enter the existing observer ledger so the assistant can see both the requested action and its result. Control must never silently alter the observer’s state.
  • Playwright and OS-level mouse/keyboard automation are unnecessary for the first reliable milestone. They add dependency and coordinate fragility; they can be a later adapter using the same command contract.

Security and safety constraints

  • No public network binding, shell execution, arbitrary JavaScript from the caller, filesystem writes, or process termination through the control API.
  • Initial actions: status, show, hide, focus, reload, navigate to an allowlisted internal route, DOM click on an allowlisted selector, bounded text entry into an allowlisted input, and cancel/stop the active UI request if the app exposes it.
  • Every request receives an audit id and produces success/failure telemetry. Sensitive prompt contents are not copied into audit logs.
  • Control is opt-in and disabled when no token is present. A user-visible emergency disable mechanism is required.

Verified sources

  • Electron BrowserWindow API — lifecycle, visibility, focus, close, and navigation operations.
  • Electron webContents API — renderer control, executeJavaScript, sendInputEvent, and page lifecycle.

Conclusion

Implement an Electron-main-process control bridge first. Keep the Python observer API as the assistant-facing read path and use the same correlation ids for control telemetry. Do not add Playwright until this bridge is proven against the real running app.
