Research: Self-Verification Loop (Phase 7)

Date: 2026-05-19

Current State

AWOS already has a two-stage pipeline:

  1. Worker generates SEARCH/REPLACE and does a lightweight self-check (SEARCH exists in file).
  2. Verifier applies the change to disk, runs compile() and contract checks.

The problem: the Verifier writes to disk first, then validates. If syntax or contract fails, the file is rolled back. This wastes I/O and a full Verifier round-trip for errors that could be caught in-memory.

Research Findings

VERIFIED — V&V Loop Pattern (muthu.co, 2025)
Verification and Validation (V&V) loops follow: Generate → Verify → Correct. The agent acts as its own QA system. Hierarchical V&V runs checks in order of cost (syntax first, then type, then logic, then security). Fail fast on cheap checks.
VERIFIED — "Easier to verify than generate" (nikhil thorat, 2025)
LLMs are better critics than composers. A coding agent taught to self-verify via lint, typecheck, and runtime logs catches its own mistakes. Tool chains (ruff, mypy, eslint) are faster than LLM retries and free up tokens for harder problems.
VERIFIED — Code Validation Example (muthu.co)
Practical implementation: ast.parse() for syntax, subprocess sandbox for runtime, and LLM critique for semantic validation. This pattern reduces first-attempt failures by ~40% in controlled settings.
UNVERIFIED — Expected AWOS Impact
Estimates from reasoning: adding an in-memory self-verification step before the Verifier could reduce expensive disk-apply → rollback cycles by 30-50%. Exact figure depends on how often Worker currently produces syntactically invalid SEARCH/REPLACE.

Proposed Solution

Add a SelfVerificationEngine that runs fast, in-memory checks before the Verifier touches disk:

Worker.generate() → SelfVerificationEngine.verify() → Verifier.apply()
                           ↓ fail                    ↓ fail
                    retry with error_context    retry with error_context

Risks

  • R1: Self-verify could add latency. Mitigation: checks are pure Python (ast, regex), sub-millisecond.
  • R2: False positives in import resolution (dynamic imports, optional deps). Mitigation: only flag truly unresolvable imports; warn not error.
  • R3: Contract check duplication with Verifier. Mitigation: extract shared logic into a helper used by both.
