Diagnosis

One root cause explains 8/9 Category D failures: The orchestrator's execute_feature() interface was changed (to add extra_context) but the change was never propagated to callers. Multiple pathways (_execute_create_task, _parse_response, classify_task) were renamed or removed during a refactor, and the tests — which are the only integration-level verification — were left behind.

The 9th failure (test_orchestrator_replan_after_verify_fail) is the most serious: it tests that when verification fails, the orchestrator replans and retries. This is the core claim of the kernel ("verify → reward → learn"). If this doesn't work, the self-learning loop doesn't function.
