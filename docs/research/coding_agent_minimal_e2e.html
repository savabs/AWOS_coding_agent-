Research: Coding Agent Minimal E2E

phase/1 · topic/coding-agent-e2e · active · 2026-07-29

Purpose

Define the smallest deterministic proof that AWOS can plan a coding change, generate an edit, reject a bad attempt, retry with a corrected edit, run tests, and report success without a live model provider.

Current architecture

  • Orchestrator.execute_feature() coordinates planning, task execution, verification, testing, logging, and final status.
  • _execute_single_task() retries the worker up to three times, then sends the patch through Verifier.verify_and_apply().
  • TestRunner.run() executes a detected local test framework only when AWOS_SAFE_TO_RUN_TESTS=1.
  • tests/test_orchestrator_e2e.py already proves one real edit and debug evidence, but bypasses planning and does not prove recovery.

Observed data flow

  1. Use a temporary repository containing a small Python module, a pytest configuration, and a test.
  2. Return a fixed planner task so no planning API call occurs.
  3. Return a syntactically invalid patch on worker attempt one.
  4. Return a valid patch on the retry.
  5. Let the real verifier apply only the valid patch, then let the real test runner execute pytest.
  6. Assert the final result, file content, retry count, test pass, and debug completion evidence.

Key observations

  • Existing focused E2E passes: python3 -m pytest -q tests/test_orchestrator_e2e.py → 1 passed.
  • The verifier rejects syntax errors before writing the file, preserving the original content for retry.
  • After successful verification, the orchestrator runs TestRunner and stores the result on the task.
  • All normal orchestrator runs create a debug journal and emit session_done.
Scope decision: Add one new test only. Do not change production code unless this test demonstrates a product defect. Use mocks only at the planner/worker model boundary; keep orchestrator, verifier, file I/O, and test runner real.

Risks and mitigations

Risk: Initialization may touch persistent runtime state or require optional model packages.
Mitigation: Use a temporary working directory, disable optional ReAct/runtime features, provide a fake provider key, and patch auxiliary cheap calls.
Risk: Test execution can be skipped by the safety guard.
Mitigation: Set AWOS_SAFE_TO_RUN_TESTS=1 only inside the isolated test environment and assert a real passing test result.

External sources

No external source is required. This is an integration test of existing AWOS interfaces; findings are grounded in the files listed above.
