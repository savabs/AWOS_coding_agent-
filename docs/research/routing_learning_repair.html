Research: Routing Learning System Repair

doc/research phase/4 topic/routing topic/linucb active 2026-07-09

Root Cause: Learning System Stalled Since May 24

The AWOS routing system has three bugs that collectively prevent LinUCB from learning:

Bug 1: N_ACTIONS mismatch silently discards all weights

Bug 2: ReplayGate rejects 79.5% of episodes

The ReplayGate has threshold=0.4 and scores each episode on informativeness, novelty, and boundary. Since most coding tasks produce similar feature vectors (same keywords like "add", "fix", "implement"), the novelty component is always near zero for common tasks. For DeepSeek (61% of all episodes), the boundary component is also near zero because it's the majority action. Combined with a 0.4 threshold, most episodes get rejected.

Bug 3: No warm-start from RewardStore data

LinUCB starts at 0 updates every time. It needs min_samples=20 admitted episodes before activating. At 20.5% admit rate, that takes ~100 raw episodes. In shorter sessions, it never activates. There's no mechanism to batch-replay existing RewardStore episodes to prime the router.

ReplayGate Deep Dive

Gate Scoring Formula

score = (informativeness + novelty + boundary) / 3

informativeness = min(|reward| / 1.0, 1.0)
  → For rewards in [-0.35, 1.0]: inform = [0.0, 1.0], mean ≈ 0.41

novelty = min(min_euclidean_dist / 0.75, 1.0)
  → Features are in [0,1], 10-dim. Typical distance between vectors ≈ 0.1-0.5
  → So novelty = min(0.3/0.75, 1.0) ≈ 0.4 for "normal" tasks
  → After 50 episodes, novelty drops to ~0.15 (most seen)

boundary = 1.0 - own_action_count / max_action_count
  → For DeepSeek (owns 61%): boundary ≈ 0.0
  → For OpenRouter (owns 0.8%): boundary ≈ 0.99

Typical score for a DeepSeek episode (61% of data):
  score = (0.41 + 0.15 + 0.01) / 3 = 0.19  → REJECTED (threshold=0.40)

Typical score for an OpenRouter episode (0.8% of data):
  score = (0.60 + 0.15 + 0.98) / 3 = 0.58  → ADMITTED

Why This Is Wrong

  • Novelty punishes common task types — coding tasks ARE repetitive by nature. We want LinUCB to learn from common tasks, not ignore them.
  • Boundary punishes the default model — DeepSeek does 61% of work because it's the DEFAULT. It needs the MOST learning, not the least.
  • Missing data biases LinUCB — If only rare actions get admitted, LinUCB learns to recommend rare actions even when inappropriate.

Proposed Fix: Adaptive Threshold

threshold = max(0.15, 0.40 - 0.01 * sqrt(total_episodes))
  At     0 episodes: threshold = 0.40 (strict — prevents overfit)
  At   500 episodes: threshold = 0.18 (lenient — accepts most data)
  At  1600 episodes: threshold = 0.15 (floor — accepts almost everything)

This keeps strict filtering when data is scarce (cold-start safety), then relaxes as the volume grows and overfitting risk decreases.

Fix Design

Fix 1: Weight File Versioning

File: scaffold/agent/ml_router.py

Change: Add format_version to saved weights. On load, handle n_actions mismatch by padding or truncating matrices instead of discarding.

Padding Strategy (more actions than stored)

If stored n_actions=4 but current n_actions=10:
  - Keep actions 0-3 learned weights as-is
  - Actions 4-9 start with identity A matrix and zero b vector
  - Log: "Loaded v2 weights: 30 updates, padded 4→10 actions"

New actions start exploring freely (identity matrix = no prior). No learning is lost.

Truncation Strategy (fewer actions than stored)

If stored n_actions=10 but current n_actions=4:
  - Drop actions 4-9 (models that no longer exist)
  - Keep actions 0-3
  - Log: "Loaded v2 weights: truncated 10→4 actions"

Format Version Check

payload = {"format_version": 2, "n_actions": ..., ...}
if "format_version" not in payload or payload["format_version"] < 2:
    # Try to migrate old format
    if payload.get("n_actions") == self.n_actions:
        # Old format but matches — load as-is
        ...
    else:
        logger.warning("[linucb] dropping v1 weights — needs manual migration")

Fix 2: Adaptive ReplayGate Threshold

File: scaffold/agent/reward_store.py

def __init__(self, threshold: float = 0.40, ...):
    self._base_threshold = threshold
    ...

def _adaptive_threshold(self, total_episodes: int) -> float:
    """Tight at cold-start, relaxes as data grows."""
    return max(0.15, self._base_threshold - 0.01 * total_episodes**0.5)

Also: novelty weight is halved (contributes 1/6 instead of 1/3 to the score). This reduces the penalty for repetitive coding tasks.

score = (informativeness * 0.4) + (novelty * 0.2) + (boundary * 0.4)

Fix 3: Warm-Start from RewardStore

File: scaffold/agent/ml_router.py, scaffold/agent/orchestrator.py

Add method to LinUCBRouter:

def warm_start(self, reward_store, max_episodes: int = 100) -> int:
    """Batch-replay episodes from RewardStore to prime weights.
    Returns number of episodes replayed."""

Call from orchestrator AFTER RewardStore and LinUCBRouter are created:

# orchestrator.py __init__:
self.ml_router.warm_start(self.reward_store, max_episodes=100)

Warm-start skips ReplayGate (these are historical episodes, trust them). Uses get_prioritized() for maximum learning per episode.
