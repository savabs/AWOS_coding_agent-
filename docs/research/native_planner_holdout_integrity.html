Research: Native Planner Holdout Integrity

2026-08-03 · phase/1 · topic/evaluation

Observed failures

  1. The native live adapter emitted intended Qwen route metadata, but Orchestrator.execute_feature() selected CheapPlanner because ambient AWOS_CHEAP_ONLY

    was enabled.
  2. The private fixture used the oracle directory as a Python script argument. The loader replaced the token with the directory and accepted it because it validated only the first executable token.

Relevant modules

  • scaffold/agent/orchestrator.py: planner selection and CheapPlanner fallback.
  • scaffold/agent/evaluation_v1.py: live adapter environment management, trajectory evidence, and evaluator callback contract.
  • scripts/run_holdout_live.py: one-task live authorization and fixture loading.li>
  • scaffold/agent/evaluation_corpus.py: digest-bound holdout references.

Root-cause hypotheses2>
  • Native mode

is currently an observability hint, not an execution policy. It must temporarily neutralize cheap-only flags and prohibit fallback when the advanced Planner is required.
  • Oracle-token replacement is underspecified. The token denotes the oracle directory, so the fixture must reference a file below that directory
    • and the loader must reject a directory target.

    Safety constraints

    • Do not modify the preserved invalid trial artifacts.
    • Do not make another provider call.
    • Keep default benchmark and CheapPlanner behavior unchanged outside explicit native mode.
    • Keep acceptance commands
      • structured argv with shell=False.
    • Require actual route evidence, not intended constants
      • , for a future trial.

    Decision

    Implement a fail-closed native Planner execution policy and validate oracle references before any future live run. Add provider-free tests for ambient cheap-only flags, primary Planner failure, actual route evidence, and directory-valued oracle references.
