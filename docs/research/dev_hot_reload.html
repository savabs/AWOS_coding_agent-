Development Supervisor for Electron

Status: ready · Date: 2026-07-28

Problem

Electron main-process JavaScript is loaded once per process. Requiring the user to manually restart the app after every control/observer edit makes live development slow and causes avoidable context loss.

Findings

  • Node’s stable child_process.spawn() can run Electron as a child and exposes lifecycle events for controlled restarts.
  • Node’s fs.watch() can monitor the small set of development-critical files without adding a dependency.
  • File watchers can emit duplicate events and have platform caveats, so the supervisor needs debounce, an explicit watch list, and a clean shutdown path.
  • Automatic restarts belong only to an explicit development command. Production npm start must retain normal process ownership.

Verified sources

  • Node child_process.spawn
  • Node fs.watch

Decision

Add a dependency-free npm run dev supervisor. It watches Electron main/preload code and the Python observer/backend sources, restarts the child with inherited stdio, and never exposes shell interpolation or arbitrary commands.
