Research: Trial Cost Telemetry

Date: 2026-08-01

Question

Why did controlled8 display a nonzero provider cost while its evaluator report recorded cost_usd: 0.0?

Observed data flow

  1. TokenTracker.record() increments total_cost.
  2. Orchestrator.execute_feature() reads that tracker for console and renderer output.
  3. The evaluator adapter reads result["total_cost"] and returns it as agent_report["cost_usd"].
  4. EvaluationRunner copies agent_report["cost_usd"] into TrialResult.cost_usd, and aggregation serializes it as mean_cost_usd.

Root cause

The normal successful return dictionary at the end of execute_feature() does not contain total_cost. The adapter therefore applies its documented default of 0.0. Earlier error returns use zero intentionally because no successful execution result exists at those points.

Insertion points

scaffold/agent/orchestrator.pyFinal success return omits the already-computed tracker total.
scaffold/agent/evaluation_v1.pyAdapter and runner already propagate total_cost correctly when present; no change required.

Decision

Repair the producer contract rather than changing evaluator defaults or rewriting reports. Use the existing mocked-LLM path for a focused regression; it makes no paid provider call.

Risks and non-goals

  • Do not infer or reconstruct cost from console text.
  • Do not alter evaluator ownership of correctness, safety, or report generation.
  • Do not launch another paid trial until the focused regression passes.

Sources

Primary sources are the repository implementations named above and controlled8 checkpoint evidence. No new external API or dependency is introduced.
