Research: Small Holdout Evaluation v1

phase/1 · topic/evaluation · active · 2026-07-30

Decision

Start with one task and one trial. Use a tiny repository in a temporary root, run sequentially, keep evaluator-owned acceptance and safety authoritative, and do not run a provider call until provider, model, credentials, budget, and timeout are explicit.

Current architecture

  • scaffold/agent/evaluation_v1.py defines EvaluationFixture, EvaluationRunner, acceptance checks, changed-path safety checks, trajectories, and reports.
  • make_orchestrator_agent adapts Orchestrator.execute_feature; its success is evidence, not the correctness oracle.
  • scripts/run_evaluation_v1.py already supports one provider-free demo trial and an explicit live mode.
  • scripts/run_holdout_pipeline.py verifies digest-bound private reports but does not call an agent.

Observed evidence

  • The focused evaluation/holdout test set passed: 42 passed in 15.94s.
  • A one-task correct deterministic trial produced pass_at_1=1.0, safety passed, and a truthful report.
  • A one-task wrong deterministic trial produced pass_at_1=0.0 and a non-zero exit, proving the acceptance oracle catches failure.
  • The three-task smoke comparison reported no regression, but it is deterministic plumbing proof, not agent capability evidence.

Space and resource findings

  • Filesystem: approximately 37 GB free of 280 GB.
  • Existing .awos/ runtime state: approximately 28 GB.
  • Private holdout workspace: approximately 36 KB before real data.
  • Safe initial shape: one repository snapshot, one trial, sequential execution, temporary workspace under /tmp, no dependency installation, no parallel workers.
  • The current evaluator cleans its temporary workspace, but does not impose an agent-callback wall-clock or disk quota. A live run therefore needs an external timeout and a preflight size check until stronger sandbox resource enforcement exists.

Risks and mitigations

High: A live agent can consume more time or disk than intended. Mitigation: require explicit single-task/single-trial flags, reject oversized snapshots, use a temporary root, run sequentially, and invoke live execution only behind an operator wall-time limit. Stop on safety or false-success evidence.
Medium: Private data could leak into tracked files. Mitigation: keep task/repository/report artifacts outside Git, use digest-bound manifests, and never tune prompts or rewards on holdout results.

Non-goals

  • No full corpus run.
  • No Cursor/Hermes/SWE-bench parity claim.
  • No provider or prompt tuning from the first holdout result.
  • No CI default live calls.
  • No new dependency or container claim.

Verified sources

  • Python subprocess documentation — argv sequences, shell=False, timeout behavior, and process cleanup requirements.
  • Python tempfile documentation — secure temporary directories and automatic cleanup via TemporaryDirectory.
