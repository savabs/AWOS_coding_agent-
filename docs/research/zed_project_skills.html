Research: Zed Project Skills — AWOS

Date: 2026-07-30 · Status: active · Scope: project-local agent workflow

Question

How should AWOS use Zed Agent Skills to make future development sessions more consistent, safer, and easier to resume?

Verified Zed behavior

  • A skill is a directory containing a required SKILL.md with YAML frontmatter.
  • Zed loads global skills from ~/.agents/skills/ and project-local skills from <worktree>/.agents/skills/.
  • The layout is flat: skill directories must be direct children of the skills root.
  • The required frontmatter is name and description; names are lowercase alphanumeric with single hyphens.
  • Zed exposes only name/description until a skill is activated, so descriptions should contain concrete triggers and bodies should use progressive disclosure.
  • Project-local skills from untrusted worktrees are excluded until the worktree is trusted.
  • Skills can be invoked automatically, by slash command, or by @-mention. disable-model-invocation: true keeps a skill manual-only.
  • Zed does not fetch a remote registry at runtime; copying a reviewed skill into one of the two local roots is the installation mechanism.

Design choice

Use four project-local skills: awos-session-start, awos-change-gate, awos-evaluation, and awos-debug-safety. This is intentionally small: overlapping skills create catalog noise and contradictory instructions. A global skill is not appropriate because these instructions reference AWOS-specific files and commands.

Risks

Instruction injection: project-local skills are instructions loaded into the agent context. Mitigation: keep them version-controlled, short, reviewed, and free of external executable content.

Stale guidance: skill text can diverge from canonical protocols. Mitigation: skills link to canonical files and state that those files own policy.

Trust confusion: skills will not appear in Zed until the project is trusted. This is expected security behavior, not an installation failure.
