Research: Typed Execution Graph

Phase: 1 · Status: active · Date: 2026-08-02

Finding: the advanced Planner should propose typed operations, while a deterministic graph compiler validates the executable graph before cheap task solvers run it.

Current architecture

AWOS has ProjectPlanner for persistent goal/task state, DAGExecutor for dependency waves, RuntimeSession for pause/resume, and Verifier for evidence. The missing layer is a canonical graph representing edits, tests, barriers, and recovery operations.

Design observations

  • Tests must be first-class nodes and gates.
  • Independent nodes can run concurrently.
  • Same-file writes must be serialized.
  • Failed prerequisites must not unlock downstream nodes.
  • Recovery should be visible as graph nodes, not hidden retries.

Sources

  • Python graphlib TopologicalSorter — ready-node processing and dependency ordering.
  • ExoFlow, OSDI 2023 — execution/recovery separation and durable workflows.
  • Hatchet DAG documentation — persisted status, parallel independent tasks, joins, and retries.

Summary

Build a stdlib-only typed execution graph above ProjectPlanner and below the advanced Planner. The first slice validates nodes, dependencies, waves, test barriers, failure blocking, recovery insertion, and persistence without changing production orchestration.
