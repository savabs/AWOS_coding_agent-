Research: Holdout Metadata Consistency

Date: 2026-08-01

Plain-language problem

A holdout trial has a manifest (trial description), a baseline report (reference result), and a candidate report (new result). Controlled8 used different trial labels in the manifest and baseline report, so the comparison tool correctly refused to compare them.

Current flow

  1. scripts/run_holdout_live.py checks the manifest and runs the trial; it does not inspect the baseline report before a live call.
  2. scripts/verify_holdout_comparison.py later calls compare_holdout_report_bundles().
  3. scaffold/agent/evaluation_corpus.py already rejects corpus label, environment label, digest, and task coverage mismatches during comparison.

Root cause

The safety check exists, but it happens too late. A malformed baseline can survive dry-run and only block comparison after provider cost has been spent.

Decision

Reuse the existing report-bundle schema and add a baseline-only preflight in run_holdout_live.py. It will verify the baseline file digest, corpus ID, environment identity, and exact task coverage before dry-run succeeds or a provider call begins.

Risks and non-goals

  • Do not rewrite an existing baseline or candidate report.
  • Do not weaken the later digest-bound comparison verifier.
  • Do not require a candidate report before a fresh trial; it must remain absent.

Sources

Primary sources: scripts/run_holdout_live.py, scripts/verify_holdout_comparison.py, scaffold/agent/evaluation_corpus.py, and controlled8 evidence.
