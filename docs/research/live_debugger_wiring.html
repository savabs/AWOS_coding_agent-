Research: Live Debugger Wiring

Date: 2026-07-27

Question

How should normal AWOS orchestrator runs automatically populate the evidence-first debugger bundle?

Verified repository facts

  • Orchestrator.execute_feature() owns session setup, task execution, finalization, and the returned result.
  • Runtime session IDs and GUI event buses are optional, controlled by AWOS_RUNTIME_SESSION.
  • Existing debugger modules already provide DebugJournal, runtime adapters, deterministic proof rules, and inspection.
  • Verifier results are dictionaries; test results are TestResult dataclasses.

Decision

Create a debugger journal for every orchestrator run using the existing reasoning session ID, independent of GUI/runtime-session flags. Record lifecycle evidence, verifier/test evidence, and deterministic findings. Journal failures are logged and must not change the task result.

Scope

Modify only the orchestrator and add focused integration tests. Do not change truth semantics, model/provider behavior, or GUI schemas.

Risks

  • Some early returns must still leave a readable bundle.
  • Parallel tasks may append concurrently; JSONL append is retained as the existing persistence contract.
  • Missing optional result fields must remain non-fatal.
