Research: Planner Graph Contract Compatibility

Date: 2026-08-03 · Status: active · Topic: planner/runtime contract

Observed live failure: Qwen returned useful task-contract fields that the graph validator rejected. A fixed five-field allowlist is only a bridge; it would repeat the same failure whenever the Planner learns a new non-executable annotation.

Required separation

  • Execution core: strict, versioned, hand-validated fields controlling node types, dependencies, paths, retries, parallelism, tests, and safety.
  • Planner metadata: extensible, bounded JSON guidance preserved for workers but never permitted to override execution or safety rules.

Compatibility policy

The graph accepts a planner_metadata object with bounded recursive JSON values and preserves unknown metadata keys. The five previously emitted top-level contract fields remain accepted temporarily and are normalized into planner_metadata. Unsupported top-level execution fields continue to fail closed.

Safety bounds

  • Metadata is JSON-like only: null, booleans, finite numbers, strings, lists, and objects.
  • Bound depth, key count, list count, string length, and total serialized size.
  • Metadata is advisory context; it cannot create nodes, change dependencies, expand paths, alter retries, disable tests, or execute commands.
  • Ambiguous duplicate keys between compatibility fields and planner_metadata fail closed.

Insertion points

  • scaffold/agent/planner_graph_contract.py: schema, recursive metadata validation, legacy-field normalization.
  • scaffold/agent/planner.py: instruct Qwen to emit metadata rather than top-level ad hoc fields.
  • scaffold/agent/orchestrator.py: preserve metadata into native nodes and worker task dictionaries.
  • scaffold/agent/worker.py: consume the known contract hints from metadata without granting metadata execution authority.

Decision

Implement strict core plus extensible bounded metadata now. Do not solve future execution capabilities through metadata; any new executable behavior requires a versioned contract change, tests, and explicit promotion.
