Integration Boundary

The advanced Planner remains responsible for project-level decomposition. A deterministic compiler is responsible for converting its plan into executable typed nodes, adding conservative same-file ordering, validating dependencies, and rejecting malformed or ungrounded structure. Cheap workers receive one concrete node/task at a time. Tests and reviews are represented as nodes and become dependency barriers; their evidence, not worker claims, controls downstream readiness.

For the first integration slice

, existing planner tasks map as follows:

  • ordinary file-changing task →
    • edit node>read-only exploration task → explore node when explicitly marked
  • task with an
    • acceptance command → test node only when the planner explicitly supplies a separate typed task; do not infer arbitrary tests from prose
  • join/review
    • /final verification → explicit typed nodes in a future planner-output extension

This avoids pretending that the current Planner already emits a complete typed graph. The compiler can support the richer schema while preserving the current task format as a compatibility input.

Persistence and Resume

The runtime session is the correct owner for the concrete graph because it already owns pause/resume state. Persisting the graph as an optional JSON object preserves old session files and lets resume restore node statuses, evidence references, retry counts, and recovery branches. GoalGraph remains the cross-session intent record; the graph is the run-level execution record.

Safety and Failure Rules

  • Validate unknown dependencies and cycles
    • before any worker call.
  • Do not use the legacy DAG executor's
    • cycle-forcing fallback for typed graph execution.
  • Mark a node completed
    • only from verifier/test evidence; worker return values are observations, not authoritative proof.
  • Mark ordinary downstream
    • nodes blocked after failed prerequisites. Recovery is an explicit graph node.
  • Persist
    • status/evidence after node completion and before scheduling the next wave where feasible.
  • Do not run parallel writes
    • sharing touched files.
  • Keep the first integration provider-free in tests
    • ; no credentials or network calls.

Non-goals

  • No production rollout of arbitrary model-generated graph JSON in this slice.
  • No replacement of GoalGraph with ExecutionGraph.
  • No new model provider, dependency, sandbox backend, or UI.
  • No full rewrite of the existing orchestrator loop.

Conclusion

Integrate through a deterministic compiler and a graph-aware

orchestration seam. Persist the graph with RuntimeSession, keep ProjectPlanner focused on intent, and make typed graph validation the gate before cheap task execution.
