Research: AWOS Agent Execution Contract

phase/1 · topic/agent-reliability · status/active · 2026-07-31
Question: How can AWOS adopt the reliability boundaries used by leading coding agents without losing exploration, recovery, observability, budget awareness, or failure-driven learning?

Current AWOS architecture

The active coding path is orchestrator.py → exploration/planner → escalation/router → react_worker.py → coding_tools.py → evaluator. The ReAct worker currently builds one broad registry containing shell, structured edits, search, tests, web, GitHub, HuggingFace, Python execution, and finish. Benchmark mode blocks some external names after the model selects them, but does not construct a capability-limited registry.

Observed facts

  • react_worker.py manually parses JSON action text and dispatches action names through a registry.
  • coding_tools.py exposes shell before structured editing tools; shell can modify files without the structured change callback.
  • Progress currently mixes exploration, editing, testing, and repeated failure into a small number of counters.
  • Completion can depend on the model calling finish, with a later evidence fallback.
  • The worker currently overwrites the selected provider/model inside _call_model, risking provider identity drift.
  • The latest failed trial stopped after read_file → read_file → shell; the model had access to shell even though structured edits were intended.

Design principles

  1. Capability selection is separate from model reasoning.
  2. Policy is enforced at registry and execution boundaries.
  3. Exploration progress is distinct from edit and verification progress.
  4. Completion is based on verified evidence; finish is optional metadata.
  5. Recovery is bounded by repeated-call and repeated-failure guards, not by an overly small exploration threshold.
  6. Provider/model identity is immutable for a configured trial.
  7. Learning, reward, traces, and debugging observe the state machine but cannot silently alter its safety contract.

Non-goals

  • Do not copy OpenCode, Zed, Hermes, or Claude architecture.
  • Do not remove AWOS exploration, learning, reward, recovery, observability, or budget systems.
  • Do not add a provider or dependency.
  • Do not launch another paid trial before offline contract tests pass.
