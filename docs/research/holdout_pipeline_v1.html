Research: Offline Holdout Pipeline v1

Date: 2026-07-30 · Status: active · Topic: local operator workflow

Current architecture

  • scripts/init_private_holdout.py creates the ignored local workspace and metadata template.
  • scripts/verify_holdout_comparison.py verifies two explicit local report bundles and returns hard-gated exit status.
  • scaffold/agent/evaluation_corpus.py owns manifest and report-bundle validation.

Gap

The operator must currently compose paths manually. A thin pipeline can validate that inputs belong to the private workspace, select the standard comparison output path, and delegate without duplicating comparison semantics.

Design decisions

DecisionReason
Offline onlyPrivate data and live provider execution must remain explicit separate operations.
Delegate comparisonOne authoritative verifier prevents CLI/pipeline semantic drift.
Boundary validationInputs under public fixture roots must be rejected before comparison.
Default outputWrite to `/comparisons/comparison.json`, but allow an explicit output path inside the private root.

Risks

Semantic drift: a second implementation could disagree with the verifier. Mitigation: subprocess delegation only.

Path leakage: a user may pass public fixtures. Mitigation: reject paths outside the private root and known private report directories.

False completion: setup can be mistaken for a live evaluation. Mitigation: output clearly states that no agent/provider was run.
