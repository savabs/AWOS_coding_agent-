Research: Private Holdout Setup v1

Date: 2026-07-30 · Status: active · Topic: local evaluation workspace

Observed constraints

  • The existing `.awos/` directory contains tracked runtime state, so it is not itself a private boundary.
  • Private holdout task contents must not enter Git or public fixture paths.
  • The comparison CLI accepts explicit local paths and does not fetch external references.
  • A setup command should create structure only and fail closed rather than overwrite an existing corpus.

Design

PathPurpose
.awos/holdout_private/Local-only ignored root for this worktree.
tasks/Operator-supplied private task fixtures.
repositories/Operator-supplied repository snapshots.
reports/baseline/Immutable baseline bundles.
reports/candidate/Immutable candidate bundles.
comparisons/CLI comparison outputs.

Security decisions

  • The initializer creates directories with mode 0700 where supported.
  • The root Git ignore rule is explicit and narrow: `.awos/holdout_private/`.
  • No credentials, private task contents, or repository copies are generated.
  • Existing files are never overwritten; template files are written only when absent.
  • Operators should use a separately access-controlled machine/volume for high-sensitivity data; Git ignore is not encryption.

Risks

False privacy: Git ignore does not protect data from local users, backups, or accidental upload. Mitigation: use filesystem permissions and an access-controlled volume.

Path confusion: a user may point the CLI at public fixtures. Mitigation: the manifest and verifier reject public fixture references; operator paths still need review.

Overwrite: setup could destroy existing evidence. Mitigation: initializer is additive and refuses unsafe replacement.
