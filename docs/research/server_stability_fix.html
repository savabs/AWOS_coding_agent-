🔬 Research: Server Stability Fix

Phase: 4 · Date: 2026-07-21 · Priority: CRITICAL (#1)

Problem

AWOS server (gui/server.py) crashes after 2–3 chat queries. Users cannot sustain a session.

Root Cause: HTTP Client Connection Leaks

Every chat query creates multiple HTTP client objects that are never closed. After 2–3 queries, accumulated unclosed connections exhaust file descriptors, crashing the server.

Leak Vector 1: requests.Response(stream=True)

Filescaffold/agent/gui_chat.py, lines 1061–1085
Function_stream_opencode_go() — anthropic protocol streaming
ImpactCRITICAL — 1–3 TCP sockets leaked per query

Each anthropic-protocol model tier opens a streaming requests.Response. resp.close() is never called. The loop exhausts the urllib3 connection pool (default: 10) after ~3 queries × 3 anthropic tiers = 9 connections.

Leak Vector 2: openai.OpenAI() clients

Filescaffold/agent/gui_chat.py, lines 951 (_stream_deepseek) and 1034 (_stream_opencode_go)
ImpactCRITICAL — 2 httpx.Client pools leaked per query

The openai.OpenAI() constructor wraps an httpx.Client with a connection pool. Fresh clients created per-call, never closed. In a multi-threaded server, httpx.Client.__del__ timing is unpredictable and can raise RuntimeError.

Leak Vector 3: Anthropic() client

Filescaffold/agent/gui_chat.py, line 979 (_stream_anthropic)
ImpactHIGH — 1 httpx.Client pool leaked per query

Same httpx leak pattern as OpenAI clients. The stream context manager is correct but the client object itself is never closed.

Secondary: _send_sse() Exception Propagation

Filegui/server.py, lines 122–134
IssueWhen client disconnects, the consumption loop for _ in gen: pass re-enters the generator. Downstream errors (OSError, RuntimeError) propagate uncaught.

Tertiary: provider_health.py Client Leaks

4 check functions (check_deepseek, check_anthropic, check_openai, check_opencode_go) create OpenAI/Anthropic clients every 300s via daemon thread. Never closed. Compounds over time.

Fix Strategy (4 Atomic Steps)

  1. Close streaming requests.Response — wrap anthropic streaming path in try/finally with resp.close()
  2. Reuse or close OpenAI/Anthropic clients — use with context managers or store as instance attributes on GuiChatService
  3. Safeguard _send_sse() generator consumption — catch and suppress exceptions during client disconnect cleanup
  4. Close provider_health.py clients — add try/finally close to each health check function
