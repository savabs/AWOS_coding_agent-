Research: Read-only Observer Follow

Status: active · Date: 2026-07-28

Question

How can an assistant follow the user's current Electron chat and its backend run live without controlling the GUI or guessing among historical sessions?

Findings

  • The UI ledger is .awos/gui/ui/events.jsonl and carries chat and trace correlation.
  • Backend ledgers are per-runtime-session under .awos/gui/<session>/events.jsonl.
  • Runtime sessions can be ambiguous when stale records remain active, so newest-directory selection is unsafe.
  • The existing observer API already provides bounded replay, SSE, and snapshots for an explicit session.

Recommendation

Add a read-only resolver that joins a UI chat_id/trace_id to the backend ledger, then expose a follow command that emits the ordered assistant-safe timeline. The resolver must return an explicit ambiguous/not-found result rather than guessing.

Out of scope

  • Mouse/keyboard control.
  • Playwright or Electron automation.
  • Raw prompt text, hidden reasoning, secrets, or unbounded tool output.
