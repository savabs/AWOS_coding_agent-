Research: Held-out Report Verification v1

Date: 2026-07-30 · Status: active · Topic: evaluation integrity

Current architecture

ComponentFactGap
EvaluationReportRepresents one task’s trial aggregate and hard-gate metrics.Cannot represent a corpus bundle by itself.
compare_reportsCompares one baseline/candidate task and flags correctness/safety regression.No exact corpus coverage or artifact-integrity verification.
HoldoutCorpusManifestRecords task refs, environment identity, and digest-bound report references.No loader/verifier consumes the referenced report artifacts.

Verified guidance

  • SWE-bench evaluates patches in isolated environments and records per-instance results plus aggregate resolution metrics.
  • OpenHands evaluation harnesses preserve instance metadata, runtime configuration, histories, metrics, and errors; benchmark runs are reproducible and isolated.
  • OpenAI evaluation guidance recommends logging, task-specific held-out datasets, automated comparison, continuous evaluation, and human calibration rather than vibe-based scores.

Design observations

  • Digest verification must read the exact artifact bytes; parsing and reserializing cannot establish artifact identity.
  • Bundle identity must include corpus and environment values matching the manifest.
  • Exact task coverage prevents silently dropping hard cases or adding unregistered cases.
  • Per-task hard-gate comparisons are safer than only comparing aggregate averages.
  • Cost and latency are diagnostics; they cannot override correctness or safety regressions.

Risks

Tampering: a report can be edited after it is recorded. Mitigation: SHA-256 verification before parsing.

Coverage bias: a bundle can omit difficult tasks. Mitigation: exact set equality against manifest task IDs.

False aggregate: a mean score can hide one failed task. Mitigation: preserve per-task comparisons and mark any hard-gate regression.
