Token and Context Observability

Phase: Stage 1 coding agent. Date: 2026-08-20.

Verified Current State

  • scaffold/agent/usage_record.py normalizes provider input/output usage and updates the token tracker and budget ledger.
  • scaffold/agent/react_worker.py has the complete message history, provider/model, response, and model-call boundary.
  • scaffold/agent/planner.py and worker.py contain additional primary-path model calls.
  • .awos/cache_stats.jsonl already stores provider-specific cache telemetry, but no provider-neutral per-call record exists.
  • awos.py exposes aggregate budget totals but not individual model-call or context-category records.

Insertion Point

Add a best-effort append-only model-call record beside the existing usage normalization. Pass optional session, task, step, prompt, and message metadata only where already available. Telemetry failures must never affect model behavior.

Non-Goals

No routing, memory, repository indexing, prompt redesign, model changes, tool behavior changes, or verifier changes.

Risks

  • Provider usage schemas differ and may omit reasoning/cache fields.
  • Context category counts are estimates unless the provider supplies segmented counts.
  • Persistent writes must be best effort and bounded.
