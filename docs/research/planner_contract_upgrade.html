Planner Contract Upgrade — Research

Date: 2026-05-16

Problem

Cheap models (DeepSeek) fail ~25% on multi-file tasks because the Planner (Sonnet) emits only natural-language actions. The Worker must invent function signatures, error handling patterns, and interface contracts. This causes inconsistency, hallucinated dependencies, and broken SEARCH/REPLACE blocks.

Root Cause

  • Current task schema: {task_id, file, action, complexity} — too vague
  • Worker prompt gives only the action string; model must infer everything else
  • No machine-enforceable validation of whether output matches intent

Prior Art

The "Correct AI Development Hierarchy" (shared 2026-05-16) states: cheap models should be "deterministic code compilers from specs." The real secret is that cheap models fail when requirements are ambiguous. If the top model produces exact contracts, signatures, and constraints, weaker models perform surprisingly well.

Solution

Extend Planner output with machine-enforceable contract fields. Extend Worker prompt to consume them. Extend Verifier to validate contract compliance (not just syntax).

Risks

  • Sonnet output is already near token limit; adding contracts may require higher max_tokens
  • Backwards compatibility: old task format must still work
  • Contracts may be wrong — need fallback if contract contradicts codebase reality

Files Affected

  • scaffold/agent/planner.py — richer prompt + output schema
  • scaffold/agent/worker.py — consume contract fields in prompt
  • scaffold/agent/verifier.py — contract compliance check
  • scaffold/agent/orchestrator.py — pass contracts through pipeline
