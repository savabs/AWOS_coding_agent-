Research: Test Outcome Gate

phase/1 · topic/coding-agent-reliability · active · 2026-07-29

Problem

AWOS currently has two execution paths. Both can apply a syntactically valid edit and then run tests. The legacy Worker → Verifier path records the task as completed before test results are consumed. The ReAct path also records completion before its test result is handled. A failing test can therefore be visible in telemetry while the returned task status and execution log say success.

Current architecture

BoundaryObserved behavior
_execute_single_task()Verifier applies syntax-valid patch, then TestRunner runs. Completion bookkeeping currently happens before the test block.
_execute_task_via_react()ReAct worker computes a test-aware success, but orchestrator logs completed before consuming test_result.
TestRunnerReturns structured TestResult with passed, failed, errors, pass_rate, timed_out, and no_tests_found.
GitManagerBacks up existing files before execution and can restore individual changed files.

Observed failure modes

  • Syntax-valid but behaviorally wrong patch: test failure does not currently control the legacy task result.
  • Test errors or timeout can be treated as a successful verified task in the legacy path.
  • ReAct can return success=False for failed tests, but the earlier completed execution-log entry remains misleading.
  • Reward and performance metrics already use the test pass rate, creating inconsistent user-facing and learning outcomes.
Policy boundary: A discovered test failure, test error, or timeout is a hard task failure and must roll back changed files. If no tests are detected or test execution is explicitly skipped by the safety guard, preserve the existing syntax-only behavior and record that condition as evidence rather than claiming full test proof.

Options considered

  1. Change only the reward signal. Rejected: telemetry would improve, but users and orchestration would still receive false success.
  2. Add a shared outcome gate after TestRunner. Chosen: one policy controls both Worker/Verifier and ReAct paths; completion, rollback, reward, live events, debug evidence, and return status can agree.
  3. Require tests to exist for every task. Deferred: useful as a future strict mode, but it would break syntax-only workflows and repositories without discoverable tests.

Risks

High: Rolling back only one primary file could leave secondary ReAct edits behind.
Mitigation: Roll back every path reported in files_changed; legacy path rolls back the task file.
Medium: Repositories with no tests would become failures if policy is too strict.
Mitigation: Keep no_tests_found syntax-only behavior explicit and observable.
Medium: Moving completion bookkeeping can affect GUI/debug/reward timing.
Mitigation: Add assertions for execution log, returned success, rollback, task-complete debug evidence, and reward success.

Summary

The next implementation should make the final task outcome depend on the strongest available evidence: verification must pass, and any executed test suite must pass completely. The change belongs in orchestrator outcome bookkeeping, with focused legacy and ReAct regression tests and a human-readable proof command.
