Research: Shell Safety Classification

Status: active · 2026-07-28

Current architecture

scaffold/agent/tools/shell.py uses _SAFE_PATTERNS.match() to classify shell commands. The pattern is anchored at the start but not the end, so a safe prefix can hide a later command. Workspace-scoped shell execution is exposed through WorkspaceShellTool; dedicated filesystem tools already provide write_file.

Observed failure

The agent's harmless file-creation command using touch was blocked. Adding touch to a prefix-only regex would weaken safety. The root fix is complete-command classification, not a broad exception.

Decision

  • Preserve the conservative shell gate.
  • Classify the full command, rejecting command chaining and redirection unless explicitly enabled.
  • Use write_file for normal file creation.

Risks

Shell syntax is broad; this task will not attempt a full shell parser. Tests will cover the current allowlist and common chaining separators.
