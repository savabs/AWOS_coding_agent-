Research: AWOS Coding-Agent Capability Audit

Status: Active · Date: 2026-07-27 · Phase: 1

Vision guardrail: AWOS is a learnable operating system for autonomous work. The coding agent is App #1. This audit strengthens the existing AWOS agent toward capability parity with strong agents such as Hermes, Cursor, and Zed agents without copying their codebases or narrowing AWOS into a generic coding tool.

Research question

Can the existing AWOS codebase provide the foundation for a high-quality coding agent, and what verified gaps prevent the current DeepSeek Pro through OpenCode Go baseline from completing real coding work reliably?

Verified observations from code inspection

  1. The main orchestrator initializes CheapPlanner, Worker, and Verifier, then attaches debugging, reward, routing, recovery, and observability components.
  2. The current worker can construct an OpenCode Go client from OPENCODE_GO_API_KEY; it also contains legacy direct DeepSeek, Anthropic, and OpenAI clients.
  3. The legacy Planner requires ANTHROPIC_API_KEY, but the cheap-only orchestrator path uses CheapPlanner. The active runtime path must be tested rather than inferred.
  4. The escalation ladder contains OpenCode Go DeepSeek Flash and DeepSeek Pro entries, but availability and exact runtime selection require proof.
  5. The repository already contains substantial AWOS-specific infrastructure; a parallel generic agent would duplicate functionality and risk losing the project's differentiators.

Parity target

Use Hermes/Cursor/Zed agents as capability references only: repository understanding, planning, safe edits, tool use, test execution, iterative repair, context management, transparency, and usable interaction. AWOS must add evidence-first proof, controlled reruns, failure-driven learning, resource optimization, and future non-coding autonomous-work support.

Risks

  • High: Fixing the wrong execution path because legacy provider code is mistaken for active behavior. Mitigation: trace and test the exact orchestrator path.
  • High: Rebuilding a generic coding agent and discarding AWOS additions. Mitigation: reuse-first file map and AWOS capability acceptance tests.
  • Medium: Premature dynamic routing adds instability while only OpenCode Go is available. Mitigation: preserve DeepSeek Pro through OpenCode Go as the baseline; defer routing.
