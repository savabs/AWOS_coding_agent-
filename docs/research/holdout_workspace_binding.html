Research: Holdout Workspace and Report Binding

phase/1 · topic/evaluation · active · 2026-07-31

Observed contract failures

  • The SWE-bench fixture embeds an absolute acceptance-test path under the historical swebench_2419_clean workspace.
  • run_holdout_live.py rewrites the repository path but does not bind acceptance argv to the selected private root.
  • The fresh manifest contains a candidate report digest before the new candidate report exists.
  • The live runner writes a new candidate report without finalizing the manifest’s candidate digest.
  • The comparison verifier correctly rejects the resulting stale digest.

Required invariant

Every acceptance oracle must be bound to the selected private holdout root, while remaining outside the agent’s temporary repository workspace. A candidate report digest must be unset before execution and finalized only after the report is atomically written.

Design direction

  1. Use a private-root oracle token in fixture acceptance argv and resolve it to a root-contained hidden oracle directory during fixture loading.
  2. Require the oracle directory to exist and remain inside the selected root.
  3. Reject pre-existing candidate reports and stale nonzero candidate digests before execution.
  4. Write the candidate bundle, compute its digest, then atomically finalize the manifest candidate reference.
Security risk: hidden oracle files must not be copied into the agent workspace or included in repository digests. Acceptance should run with the temporary workspace as its working directory and the private oracle path only as the test-file argv.
