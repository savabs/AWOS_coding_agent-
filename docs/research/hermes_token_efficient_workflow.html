Hermes Token-Efficient Coding Workflow

AWOS needs a compact, evidence-preserving way for Hermes to work on the repository. The repository already has canonical identity, project structure, checkpoints, task files, repo-map/context tooling, token tracking, and Hermes compression. The gap is orchestration: selecting only task-relevant context, enforcing bounded output, and measuring cost per verified task.

Constraints

  • Do not weaken verification or safety.
  • Do not inject all active tasks, checkpoints, or research into every session.
  • Do not modify global Hermes configuration from the project.
  • Use deterministic local context generation before any model call.

Chosen approach

  1. Build a task-context packet from canonical files and explicitly requested paths/symbols.
  2. Use a compact session response contract.
  3. Measure packet size and verified-task outcomes.
  4. Add project-local Hermes guidance through the existing AGENTS.md.

Rejected

Directly wiring the existing Aider/Anthropic output optimizer into Hermes is rejected because its request format and pricing assumptions are provider-specific.
