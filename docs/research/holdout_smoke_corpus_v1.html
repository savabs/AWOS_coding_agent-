Research: Three-task Holdout Smoke Corpus v1

Date: 2026-07-30 · Status: active · Topic: end-to-end evaluator proof

Purpose

Prove the complete local data flow on three tiny synthetic tasks before handling real private tasks. This is a harness smoke test, not a measurement of AWOS model capability.

Existing components reused

ComponentRole
EvaluationRunnerFresh workspace, acceptance tests, changed-path safety, trial result.
HoldoutReportBundlePer-task baseline/candidate report serialization.
HoldoutCorpusManifestTask, repository, environment, and report digest identity.
run_holdout_pipeline.pyPrivate-root boundary and hard-gated comparison.

Smoke tasks

  • smoke_add: arithmetic function with a failing test.
  • smoke_greet: greeting function with a failing test.
  • smoke_total: list aggregation function with a failing test.

Flow

  1. Write synthetic task/repository snapshots under ignored private root.
  2. Run a deterministic baseline callback that leaves bugs unchanged.
  3. Run a deterministic candidate callback that applies known fixes.
  4. Write report bundles and compute exact SHA-256 digests.
  5. Write manifest and invoke the real pipeline.
  6. Expect three task improvements and exit code zero.

Risks

Capability confusion: deterministic known fixes can look like agent success. Mitigation: label every output smoke-only and keep it out of capability metrics.

Private overwrite: rerunning could overwrite evidence. Mitigation: refuse when manifest or task outputs already exist.
