Research: Holdout Trial Reliability

phase/1 · topic/evaluation · 2026-07-31 · active

Decision under research

Before another live holdout call, make acceptance failures, agent exceptions, and provider errors produce truthful evaluator evidence without retrying or hiding the failure.

Observed architecture

  • scripts/run_holdout_live.py validates one digest-bound task and writes a candidate report after EvaluationRunner.run_trial().
  • scaffold/agent/evaluation_v1.py owns workspace snapshots, safety checks, structured acceptance argv, trajectories, and report aggregation.
  • scaffold/agent/cheap_planner.py already constructs create_fixed_client() and uses FIXED_MODEL; its error messages still say Gemini.
  • The private fixture acceptance command referenced a missing /tmp/awos-swebench-sqlfluff-venv-2419/bin/python. _run_acceptance() catches timeout but not OSError, so the runner exited before writing a report.

Required changes

  1. Convert acceptance launch errors into a failed acceptance event with a bounded, secret-safe error.
  2. Keep agent exceptions as evaluator-visible error trials and ensure the live adapter emits a report.
  3. Correct provider labels to OpenCode Go / fixed model without changing provider selection.
  4. Add tests for missing acceptance executable, agent exception, and fixed-provider error labels.

Risks

High: A missing executable could be mistaken for a successful or absent evaluation. Mitigation: record passed=false, an explicit failure reason, and a non-passing report.
Medium: Error output can expose credentials or large provider responses. Mitigation: record exception type and bounded output only; never log environment values.

Non-goals

  • No live retry.
  • No prompt/reward tuning against the hidden task.
  • No dynamic provider routing or fallback.
  • No dependency installation inside the live trial.

Verified sources

  • Python subprocess documentation — structured argv, shell=False, timeout and launch failures.
  • small_holdout_evaluation_v1 — existing AWOS holdout constraints.
