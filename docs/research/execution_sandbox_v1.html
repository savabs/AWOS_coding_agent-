Execution Sandbox v1

phase/1 · topic/execution-safety · active · 2026-07-29

Research question

How can AWOS let a coding agent inspect, edit, install, and test code without allowing a bad command or model-generated patch to damage the user’s host workspace or leak sensitive data?

Safety principle: isolation is layered. A worktree protects source state; it does not by itself contain processes, network access, secrets, filesystem traversal, resource exhaustion, or malicious repository instructions.

Current AWOS boundaries

BoundaryExisting capabilityGap to prove
RuntimeSession.SessionSandboxPersists enabled flag, feature ID, worktree path, and branch.Need lifecycle invariants, path containment, cleanup, and failure recovery.
GitManagerCreates branches, backs up files, rolls back files/all changes.Branch/file rollback is not process isolation and must not be treated as a sandbox.
HITLConsentDefault-deny interactive approval and decision logging.Approval needs structured action risk, exact command/paths, session binding, and fail-closed behavior.
Shell/tool safetyExisting command classification and safety flags.Need policy enforcement at the execution boundary, not only classification or prompt instructions.

Security model

  1. Workspace isolation: execute against a disposable worktree or container path; mount only the task workspace.
  2. Process isolation: use a dedicated process group, timeout, cancellation, and cleanup.
  3. Privilege reduction: non-root execution, no privileged capabilities, read-only mounts by default, explicit writable workspace.
  4. Network policy: deny by default; allow only declared package/provider access with auditable policy.
  5. Secret boundary: never mount host credential directories; pass only explicitly approved ephemeral credentials.
  6. Command policy: classify shell actions, reject traversal/out-of-root paths and dangerous flags before process creation.
  7. Human approval: pause before shell, install, network, destructive, or host-visible actions; bind approval to exact action digest and session.
  8. Evidence: record policy decision, approval, command, environment identity, exit status, output digest, and cleanup result.

Threats to test

ThreatExpected control
../../ path or symlink escapeReject before read/write/command.
rm -rf, fork bomb, long-running processReject or terminate by policy/timeout; host remains unchanged.
Repository prompt injectionTreat repository text as untrusted data; it cannot change policy or approval.
Test writes outside workspaceSandbox prevents host mutation; cleanup removes workspace.
Network exfiltrationDenied by default or explicitly recorded/approved.
Container escape/privileged requestNo privileged mode; least-privilege runtime; fail closed if guarantees unavailable.
Crash during executionProcess group and workspace cleanup are idempotent; session records failed cleanup if not proven.

Decision

Do not claim “sandboxed” from worktree support alone. v1 must expose the isolation level honestly: worktree-only, process-isolated, or container-isolated. If a requested guarantee is unavailable, execution must fail closed or require explicit override.
