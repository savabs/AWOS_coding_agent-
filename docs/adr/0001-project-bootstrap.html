Context

This project uses the Agentic OS workflow system. This ADR records the decision to adopt it and documents any customisations made for this specific project.

The problem being solved: AI-assisted development on complex, multi-session projects fails in three specific ways:

  1. Memory loss between sessions — the agent re-derives decisions, contradicts prior work, re-reads the entire codebase every session start.
  2. Unplanned implementation — code is written before architecture is clear; bugs require re-reading what was just written.
  3. Fact drift — the same number or decision exists in multiple files and they silently diverge.

Decision

Adopt the Agentic OS workflow system as the backbone for this project.

Options Considered

Option A: Agentic OS ✓ Chosen

Full workflow system: research → spec → task triad, single-owner facts, session checkpoints, Obsidian knowledge graph, automation scripts, HTML-first artifacts.

ProsCons
  • Prevents all 3 primary failure modes
  • Scales to multi-month, multi-session projects
  • Machine-readable progress tracking
  • Cold-start in ~5 minutes
  • HTML artifacts are readable and shareable
  • Initial setup overhead (~15 minutes)
  • Requires discipline to maintain templates and checkpoints

Option B: Ad Hoc Documentation ✗ Rejected

Write docs as needed, no enforced structure.

ProsCons
  • Zero setup overhead
  • Does not survive context loss between sessions
  • Agent re-derives decisions already made
  • No canonical file for any fact — all facts drift

Option C: External Project Management Tool ✗ Rejected

Use a dedicated tool (Jira, Linear, Notion) for task tracking.

ProsCons
  • Rich UI, integrations
  • Not co-located with codebase — agent cannot read/write directly
  • Breaks Single-Owner Rule — creates fact copies outside codebase
  • No git history for decisions

Rationale

Option A was chosen because this project spans multiple sessions and the cost of memory loss (re-deriving decisions, contradicting prior work, re-reading the codebase) is higher than the overhead of maintaining the Agentic OS artifacts.

The HTML-first artifact policy (§5.7) was adopted because: (1) HTML documents with navigation, tables, and syntax highlighting are 4× more likely to be actually read; (2) they are shareable without attachments; (3) they support interactive elements like "Copy as Prompt" buttons that provide direct agent utility.

Consequences

TypeConsequence
PositiveCold-start from any session in ~5 minutes using AGENT_INDEX.md → project_structure.md → checkpoint → active task.
PositiveAll decisions are traceable, durable, and readable without replaying the conversation.
PositiveAgent and human share the same source of truth. Conflicts resolve by consulting canonical files.
NegativeEvery non-trivial change requires a research doc and spec before code is touched.
NegativeCheckpoints must be written at every natural session breakpoint — this is a discipline requirement, not optional.

Validation

  • Cold-start test: a new agent session should be fully oriented within 5 minutes of reading the 5 cold-start files.
  • Memory loss test: no decision from a prior session should need to be re-derived in a subsequent session.
  • Fact drift test: scripts/fact_lint.py should report zero duplicated constants after each milestone.
