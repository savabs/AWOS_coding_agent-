Spec: Agent Loop Control

Date: 2026-08-01 · Status: active

Goal

Make the coding worker stop on verified evidence, recover from failed verification in bounded cycles, and stop wasting turns on repeated no-progress exploration without weakening safety.

Governing research: agent_loop_control_comparison.html
Task: agent_loop_control.html

Allowed files

  • scaffold/agent/react_worker.py
  • tests/test_react_worker.py
  • scaffold/agent/evaluation_v1.py only if the completion contract needs a typed evaluator field
  • tests/test_evaluation_v1.py only for that contract

Atomic implementation steps

Step 1 — Define a completion contract.

Represent required acceptance commands, allowed paths, and whether verification is required as explicit worker input. Prove the contract is carried into the worker prompt and does not expose hidden evaluator details incorrectly.

Exit: focused unit test proves contract serialization and prompt inclusion.

Step 2 — Add evidence-backed completion state.

Change finish from immediate success to candidate completion. Promote it to verified completion only when the required evidence passes; preserve an explicit inconclusive state for no-test results.

Exit: tests cover finish-before-test, passing test, failing test, and no-test cases.

Step 3 — Add a focused verification continuation.

After a file edit, prioritize the supplied focused acceptance command before broad test discovery. Feed structured failure output back to the model for a bounded repair cycle.

Exit: test proves one failed verification produces one repair continuation and a passing rerun ends the task.

Step 4 — Extend progress detection to successful no-ops.

Track normalized tool/action signatures, normalized result signatures, changed paths, and test-result signatures. Detect exact repeats and short ping-pong loops without blocking legitimate polling.

Exit: tests prove repeated successful identical reads pause/fail honestly while distinct exploration remains allowed.

Step 5 — Replace one global budget with bounded categories.

Keep an absolute safety cap, but allocate initial exploration, implementation, verification, and recovery budgets separately. Preserve the existing cost guard and make every model call consume the same ledger.

Exit: tests prove verification recovery cannot bypass the total turn/cost cap.

Step 6 — Run focused regression validation.

Run the ReAct and evaluation tests, then the relevant holdout harness tests without making a paid provider call.

Exit: focused suites pass and no evaluator report is rewritten.

Edge cases

  • Acceptance command is absent: retain existing local verification behavior and report that no focused command was available.
  • Acceptance command returns no tests: do not claim pass; classify as inconclusive.
  • Tool changes an untracked primary file: retain existing diff-based detection.
  • Repeated command is a legitimate poll: require a bounded poll budget or changed observation before allowing continuation.
  • Model claims completion with no edit: fail honestly for tasks requiring an edit.

Non-goals

  • No provider/model change.
  • No architecture copy from Hermes, OpenCode, Claude, or OpenHands.
  • No hidden-test access in the worker.
  • No paid trial during implementation.
