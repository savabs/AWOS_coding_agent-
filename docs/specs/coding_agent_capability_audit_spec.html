Spec: AWOS Coding-Agent Capability Audit and Baseline Hardening

Status: Active | Date: 2026-07-27

Governing principle: Make the existing AWOS coding agent reliable and capable. Do not create a parallel generic agent. Preserve the current DeepSeek Pro through OpenCode Go baseline. Use competitor agents as capability benchmarks, not implementation sources.

Goal

Prove the active AWOS coding-agent path can complete representative coding tasks with safe edits, verification, evidence-backed diagnosis, and bounded recovery, then fix only confirmed gaps.

Files initially in scope

  • scaffold/agent/orchestrator.py
  • scaffold/agent/cheap_planner.py
  • scaffold/agent/worker.py
  • scaffold/agent/react_worker.py
  • scaffold/agent/verifier.py
  • scaffold/agent/test_runner.py
  • scaffold/agent/core/debug_*.py
  • Focused tests under tests/

No file is modified unless a task step identifies a reproduced gap.

Atomic implementation steps

<ol>
  • Trace the active runtime path. Identify the exact planner, worker, verifier, model, and evidence components used by Orchestrator.execute_feature. Exit: a test or trace names each active component and confirms whether DeepSeek Pro through OpenCode Go is selected.
  • Prove the OpenCode-only baseline. Run an isolated representative coding task with mocked transport and only OpenCode Go configured. Exit: the task reaches planning, edit, verification, and final evidence without other provider credentials.
  • Record the first verified blocker. Use debugger evidence to classify the earliest failure. Exit: the blocker is PROVEN, or the baseline is explicitly marked passing.
  • Fix only the reproduced provider blocker. Modify the smallest existing component owning the confirmed OpenCode failure. Exit: the focused OpenCode regression passes.
  • Fix defensive ReAct initialization. Make ReActWorker.execute_task() safely handle controlled construction where optional state is absent, without changing normal runtime behavior. Exit: the mocked ReAct test and normal E2E pass.
  • Prove bounded recovery. Inject a bounded edit or test failure and verify the existing recovery and debugger path. Exit: recovery produces evidence and either a verified success or honest terminal failure.
  • Establish capability baseline. Run representative tasks covering repository inspection, multi-file change, test repair, and failure recovery. Exit: results include success, latency, cost, retries, and evidence status.

    • Acceptance criteria

    • DeepSeek Pro through OpenCode Go remains usable.
    • No missing provider credential causes an unapproved API call.
    • Existing AWOS debugging and verification are present in results.
    • No unsupported issue is reported as proven.
    • New code is limited to verified gaps.
    • Results improve strong coding-agent capabilities without narrowing AWOS beyond App #1.
