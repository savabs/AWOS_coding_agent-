Spec: Holdout Executable Validation

Goal: make holdout dry-run reject acceptance commands that cannot launch from the evaluator boundary.

Research: holdout_executable_validation.html · Task: holdout_executable_validation.html

Allowed files

  • scripts/run_holdout_live.py
  • tests/test_holdout_live.py

Atomic steps

  1. Validate acceptance executable metadata. Require each command's first token to be absolute, existing, and executable during private fixture loading. Exit: malformed fixtures raise LiveHoldoutError before dry-run returns.
  2. Cover relative executable rejection. Add a test with a relative first token and assert dry-run fails. Exit: no provider authorization is reached.
  3. Cover missing executable rejection. Add a test with a nonexistent absolute first token and assert dry-run fails. Exit: no provider authorization is reached.
  4. Preserve valid dry-run behavior. Use the current interpreter as an absolute executable in the valid fixture and assert dry-run succeeds. Exit: focused holdout tests pass.

Edge Cases

  • An absolute existing non-executable file is rejected.
  • Arguments after the executable remain structured strings and are not independently launched.
  • Oracle token binding remains unchanged.
