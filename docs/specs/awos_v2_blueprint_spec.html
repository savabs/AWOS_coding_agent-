AWOS v2 Blueprint

Implementation Specification

Atomic Steps: Sprint 1–3 | 23 Total Steps

Implementation Plan Overview

  • Sprint 1 (Foundation): 8 steps — CLI scaffolding, Tree-Sitter setup, basic Cartographer
  • Sprint 2 (Intelligence): 8 steps — Complexity scoring, model routing, HITL consent gate
  • Sprint 3 (Persistence): 7 steps — Hydration, prompt caching, SOUL.xml, dreaming cycle

Total estimated effort: 12–16 weeks for one engineer. Parallelizable: Sprint 2 Layer 2 can begin after Sprint 1 completes Layer 1 Cartographer.

Sprint 1: Foundation Layer Phase 0 Extension

Goal: Establish CLI skeleton, initialize Tree-Sitter integration, build basic STRUCT.xml output.
Duration: ~4 weeks | Steps: 1.1–1.8 | Exit: awos map generates STRUCT.xml for any language
1.1
Create .awos/ project memory directory
Initialize the project soul storage. All persistent data (rules, patterns, decisions, cost history) lives here.
Changes: Create .awos/soul.xml (template), .awos/cost_log.xml (template), .awos/session_dreaming.py (placeholder)
Test: Verify directory exists; XML templates are valid; git check-ignore .awos confirms directory is untracked (add to .gitignore if needed)
Exit condition: .awos/ is initialized and checked into repo as example structure. User can customize.
1.2
Add tree-sitter + language parsers to requirements
Pin Tree-Sitter Python bindings and language parser modules for initial scope (Python, C, C++, Rust).
Changes: Add to requirements.txt: tree-sitter==0.21.0, tree-sitter-python==0.21.x, tree-sitter-cpp==0.21.x, tree-sitter-rust==0.21.x
Test: pip install -r requirements.txt succeeds; python -c "import tree_sitter; print(tree_sitter.__version__)" confirms install
Exit condition: Tree-Sitter + parsers installed; Python REPL can import language parsers without error
1.3
Implement TreeSitterCartographer class
Core parser class. Takes a file path, language, and returns AST + symbol list.
Files: New scaffold/agent/cartographer.py
Class: TreeSitterCartographer(language: str, parsers: Dict[str, Language])
Methods:
  • parse(file_path: str) → AST
  • extract_symbols(ast) → List[Symbol] (returns id, type, name, signature, line)
  • get_content_hash(file_path: str) → str (XXH3)
Test: Unit test with fixture files:
  • Python: def my_func(): pass → extract Symbol(id='f1', type='function', name='my_func')
  • C++: void render() {} → extract symbol
  • Verify XXH3 hash matches same file, differs when modified
Exit condition: pytest tests/test_cartographer.py passes; all fixtures extracted correctly
1.4
Build STRUCT.xml generator
Traverse repository tree, parse each file, produce hierarchical STRUCT.xml output.
File: New scaffold/agent/struct_builder.py
Class: StructBuilder(cartographer: TreeSitterCartographer, repo_path: str)
Methods:
  • build() → str (returns XML string)
  • to_file(output_path: str)
Test: Create minimal test project (5 files), generate STRUCT.xml, validate:
  • XML is well-formed (can parse with ElementTree)
  • All files appear in tree
  • All symbols are correctly typed and named
  • Hashes are present and stable
Exit condition: pytest tests/test_struct_builder.py passes; STRUCT.xml output is human-readable and valid
1.5
Add file-watcher integration (Watchdog)
Detect file changes in real-time. Trigger incremental STRUCT.xml re-parse on modified files only.
File: Update scaffold/agent/struct_builder.py with FileWatcher class
Deps: Add watchdog==3.0.0 to requirements.txt
Feature: watch_repo(callback: Callable) — starts file monitor, calls callback on change
Test: Integration test:
  • Modify a test file (add/remove function)
  • Verify STRUCT.xml updated within 1 second
  • Verify other files untouched (no redundant re-parse)
Exit condition: File watcher correctly detects modifications and updates STRUCT.xml incrementally (verified by timestamp + hash diff)
1.6
Implement awos map CLI command
New entry point: awos map [--watch] [--output STRUCT.xml]. Generates initial STRUCT.xml from repo.
File: Update scaffold/agent/cli.py
Command: @app.command("map") with Typer options
Test: CLI integration:
  • awos map --help shows usage
  • awos map generates STRUCT.xml in current directory
  • awos map --output /tmp/test.xml writes to custom path
  • awos map --watch starts file watcher (manual Ctrl+C to stop)
Exit condition: awos map works for Python + C/C++ projects; STRUCT.xml is stable and parseable
1.7
Add language detection logic
Detect project primary language(s) by file count heuristic. Auto-select appropriate Tree-Sitter parsers.
File: New scaffold/agent/language_detector.py
Function: detect_languages(repo_path: str) → Dict[str, float] (returns language → proportion)
Test: Test projects with known language distributions:
  • Python repo: detect Python > 80%
  • Mixed C++/Python: detect both, correct proportions
Exit condition: detect_languages() accurately identifies primary languages; awos map auto-loads correct parsers
1.8
End-to-end test: Generate STRUCT.xml for AWOS_coding_agent repo
Dogfooding: Run awos map on this project. Verify it correctly indexes itself.
Test: Manual + CI: scripts/test_cartographer_e2e.py
Checks:
  • STRUCT.xml generated without error
  • All Python files in scaffold/ are indexed
  • Symbols extracted correctly (e.g., TreeSitterCartographer class, parse() method)
  • File hashes are stable across runs
Exit condition: STRUCT.xml generated for AWOS_coding_agent; at least 20 symbols correctly extracted; Sprint 1 complete

Sprint 2: Intelligence Layer Phase 1 Extension

Goal: Implement complexity scoring, model routing, HITL consent gate, pre-flight manifest.
Duration: ~4 weeks | Steps: 2.1–2.8 | Exit: awos run shows pre-flight manifest and routes tasks to correct model tier
2.1
Implement complexity scorer
Tier 4 model (fast + cheap) scores task description → 1–10. Routing uses this score.
File: New scaffold/agent/dispatcher.py
Class: ComplexityScorer(model_client)
Methods: score(task_description: str) → int (1–10 score)
Test: Unit tests with hardcoded task examples (no API calls):
  • Simple: "Add type hints to function" → score 1–3
  • Medium: "Refactor memory allocator" → score 5–7
  • Hard: "Redesign async architecture" → score 8–10
  • Verify score is deterministic
Exit condition: Scorer gives consistent scores for known tasks; scores match expected tier (1–3 → Tier 3, etc.)
2.2
Implement multi-provider model router
Maps complexity score → model tier → API provider. Returns (provider, model, estimated_cost).
File: Update scaffold/agent/dispatcher.py with ModelRouter class
Methods: route(complexity_score: int) → (provider, model, cost_estimate)
Test: Routing table test:
  • Score 1 → (DeepSeek, deepseek-chat, $0.001)
  • Score 5 → (Anthropic, claude-sonnet-4-5, $0.10)
  • Score 9 → (Anthropic, claude-opus-4-5, $0.50)
Exit condition: Routing table matches published model costs; all tiers testable without API
2.3
Build pre-flight manifest generator

File: New scaffold/agent/manifest.py
Class: PreFlightManifest(task, model_tier, cost_estimate, runtime_estimate)

Test: Manifest rendering:

Exit condition: Manifest renders correctly; matches spec example format

Test: Interactive mode disabled in tests (mock user input):

Test: Log entries and verify:

If Tier 2/3 fails (build error, returned None), propose Tier 1 escalation with context.

Sprint 3: Persistence & Optimization Phase 2-3 Extension

Goal: Implement hydration protocol, prompt caching, SOUL.xml persistence, and session dreaming.
Duration: ~4 weeks | Steps: 3.1–3.7 | Exit: Multi-task session with caching shows 80%+ cost reduction; SOUL.xml learns patterns
3.1
Implement symbol hydration engine
Given STRUCT.xml + symbol ID, fetch source code for that symbol from disk.
File: New scaffold/agent/hydrator.py
Class: SymbolHydrator(struct_xml_path, repo_path)
Methods: hydrate(symbol_id: str) → str (returns source code in <active_code> tags)
Test: Hydrate specific symbols from STRUCT.xml:
  • Parse STRUCT.xml for AWOS_coding_agent
  • Hydrate a function symbol
  • Verify returned code matches file contents
  • Verify <active_code> wrapper applied
Exit condition: Hydrator correctly extracts symbol source code from files; wrapper tags present
3.2
Integrate prompt caching wrapper (LiteLLM level)
Wrap API calls with Claude prompt caching support. Mark STRUCT.xml + system prompt as cacheable.
File: New scaffold/agent/caching.py
Class: CacheStrategy(model: str)
Methods: prepare_cache_control_blocks(struct_xml, system_prompt) → List[CacheBlock]
Test: Mock Claude API calls with cache headers:
  • First call: cache_creation_input_tokens > 0
  • Second call (same prefix): cache_read_input_tokens > 0
  • Verify cost calculation accounts for 10% read cost
Exit condition: Mock tests show cache hits; cost reduction correctly calculated (90% reduction on repeated prefixes)
3.3
Implement the Hydration Protocol (Observe → Select → Hydrate)
Agent reads STRUCT.xml (observe), identifies needed symbols (select), fetches code (hydrate), wraps in active_code.
File: New scaffold/agent/protocol_hydration.py
Class: HydrationProtocol(struct_xml_path, repo_path, hydrator)
Methods: execute(symbol_ids: List[str], context_tokens: int) → str (returns prompt with hydrated code)
Test: Protocol execution:
  • Parse STRUCT.xml (observe)
  • Select 3 symbols for a task
  • Hydrate all 3; verify total token count ≤ context_tokens
  • Verify active_code tags wrap hydrated source
Exit condition: Hydration protocol respects token budget; wraps code correctly
3.4
Create SOUL.xml schema and persistence layer
Define SOUL.xml structure (invariants, patterns, decisions, cost_history). Load/save to .awos/soul.xml.
File: New scaffold/agent/soul.py
Class: ProjectSoul(path: str = '.awos/soul.xml')
Methods:
  • load() → ProjectSoul
  • add_invariant(rule: str) → None
  • add_pattern(issue: str, fix: str) → None
  • add_decision(choice: str, reason: str) → None
  • record_cost(model, cost) → None
  • save() → None
Test: SOUL lifecycle:
  • Create empty ProjectSoul
  • Add invariant, pattern, decision
  • Save to file
  • Load from file
  • Verify all data persisted correctly
Exit condition: SOUL.xml reads/writes correctly; XML is valid; data round-trips without loss
3.5
Implement session dreaming cycle
On session end, extract session logs → call Tier 4 model → parse rules/patterns → merge into SOUL.xml.
File: New scaffold/agent/dream.py
Class: SessionDreamer(soul: ProjectSoul, llm_client, session_log: str)
Methods: dream() → None (updates SOUL.xml)
Test: Mock dreaming cycle:
  • Create session log with sample errors + fixes
  • Mock Tier 4 model response (returns pattern)
  • Verify pattern merged into SOUL.xml
Exit condition: Dreaming correctly extracts and merges patterns; SOUL.xml learns from sessions
3.6
Add session checkpoint + dreaming to CLI
awos end-session → write checkpoint → call dreaming → update SOUL.xml.
File: Update scaffold/agent/cli.py
Command: @app.command("end-session")
Test: CLI command:
  • awos end-session completes without error
  • Checkpoint written to docs/memory/
  • SOUL.xml updated with session summary
Exit condition: End-session command works; checkpoints + SOUL.xml updated correctly
3.7
End-to-end multi-task session with caching + SOUL learning
Run synthetic 5-task session: score → route → manifest → execute (mocked) → hydrate → cache → log cost. End session, dream, verify SOUL.xml updated.
Test: scripts/test_full_e2e.py (integration test)
Checks:
  • 5 tasks routed correctly (mix of Tier 1–3)
  • Cache hit rate ≥ 80% after task 2
  • COST_LOG shows cumulative spend + cache savings
  • SOUL.xml contains ≥ 1 new pattern from session
  • Checkpoint written with session summary
Exit condition: Full flow works; demonstrates caching benefit + SOUL learning. Sprint 3 complete; AWOS v2 Blueprint MVP ready for production
