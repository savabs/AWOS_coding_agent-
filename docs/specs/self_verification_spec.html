Interface Contract

SelfVerificationEngine

class SelfVerificationEngine:
    """In-memory pre-flight verifier. Never writes to disk."""

    def verify(
        self,
        original_content: str,
        search_replace: dict,
        file_path: str,
        task_spec: dict | None = None,
    ) -> VerificationResult:
        """
        Simulate the SEARCH/REPLACE and run fast checks.

        Returns:
            VerificationResult(
                passed: bool,
                stage: str,          # e.g. "syntax", "import", "contract"
                errors: list[str],
                error_context: str,  # formatted for worker retry prompt
            )
        """

VerificationResult dataclass

@dataclass
class VerificationResult:
    passed: bool
    stage: str              # which check failed (or "all" if passed)
    errors: list[str]
    error_context: str      # human-readable prompt injection text

Check Stages (run in order — fail fast)

  1. Search string exists — SEARCH must appear literally in original_content.
  2. Replace produces unique match — SEARCH must appear exactly once (or warn on ambiguity).
  3. AST parse of modified content — ast.parse() the post-replacement text.
  4. Import resolution — top-level import / from ... import names must be resolvable (stdlib + local modules; warn only on third-party).
  5. Contract compliance — function_signature, constraints, must_not from task_spec.

Implementation Steps

  1. Extract contract helper — move _check_contract_compliance from Verifier to module-level check_contract_compliance(). Update Verifier to call it.
  2. Create scaffold/agent/self_verification.py — implement SelfVerificationEngine with 5 check stages. Each stage returns early on failure (fail fast).
  3. Wire into Worker — after parse_search_replace, call SelfVerificationEngine.verify(). If fail, retry with error_context.
  4. Write tests — tests/test_self_verification.py with 15+ tests covering each stage and integration.
  5. Run full suite — zero regressions required.

Edge Cases

  • Empty SEARCH — caught by stage 1, returns passed=False.
  • Multiple SEARCH matches — stage 2 warns; Verifier handles ambiguous replace on disk.
  • Dynamic/optional imports — stage 4 only flags unresolvable stdlib + local imports; third-party imports are warnings, not errors.
  • No task_spec — stage 5 is skipped gracefully.
  • Non-Python files — AST check is skipped for .py only; other stages run regardless.
