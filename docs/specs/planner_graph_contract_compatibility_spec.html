Goal

Make the native graph contract future-resistant: strict for executable behavior, extensible for bounded Planner guidance, and backward-compatible with the current five top-level contract fields.

Allowed files

  • scaffold/agent/planner_graph_contract.py
  • scaffold/agent/planner.py

  • scaffold/agent/worker.py

  • memories/repo/project_structure.md

Atomic steps

1. Define bounded metadata validation.

Validate recursive JSON-like metadata with limits for depth, keys, list items, strings, and total size. Verify unsupported values fail closed.

2. Add extensible metadata to the graph schema.

Allow planner_metadata while retaining strict runtime fields and arbitrary top-level rejection.

3. Migrate legacy top-level hints.

Normalize the five current fields into metadata and reject ambiguous duplicates.

4. Preserve metadata through execution.

Carry metadata into native nodes and atomic worker tasks; only known worker guidance is rendered into the prompt.

5. Update Planner instructions.

Tell Qwen to place guidance in metadata and distinguish advisory metadata from executable fields.

6. Run offline regression validation.

Test unseen metadata fields, legacy graphs, malformed metadata, safety invariants, worker propagation, and all relevant existing suites.

Invariants

  • Metadata cannot create or modify graph nodes.
  • Metadata cannot change dependencies, paths, retry limits, parallel safety, acceptance checks, or permissions.
  • Unknown metadata keys are preserved but not interpreted as execution policy.
  • Unknown top-level fields remain rejected unless they are the temporary five-field compatibility fields.
  • Historical holdout artifacts remain untouched; no live provider call is part of this task.
