Spec: Held-out Evaluation Corpus v1

Goal: Validate a private held-out corpus manifest that is split-safe, hash-bound, environment-bound, and baseline/candidate reproducible without storing private tasks in this repository.

Research: evaluation_holdout_corpus_v1.html
Task: evaluation_holdout_corpus_v1.html

Files affected

  • scaffold/agent/evaluation_corpus.py — new manifest dataclasses and fail-closed validator.
  • tests/test_evaluation_corpus.py — schema, leakage, hash, and reference tests.
  • docs/evaluation_holdout_v1.md — operator contract.
  • tests/fixtures/evaluation_v1/holdout_manifest.example.json — metadata-only example with no private task content.

Atomic steps

1. Define HoldoutTaskRef. Require task ID, family, external fixture reference, fixture SHA-256, and repository SHA-256.
Verify: valid reference round-trips deterministically.
2. Define HoldoutCorpusManifest. Require schema version, split=holdout, corpus ID, environment identity, and non-empty task references.
Verify: missing fields and wrong split raise the schema error.
3. Reject public fixture overlap. Reject external references containing the public fixture root or unsafe traversal.
Verify: public path and traversal tests fail closed.
4. Bind baseline and candidate reports. Require report references with SHA-256 and forbid mutable empty references.
Verify: report reference validation passes only with a digest.
5. Add metadata-only example. Store no private repository or task contents in the example.
Verify: example loads and contains no public fixture path.
6. Run focused validation. Run corpus tests and existing evaluator tests.
Verify: both suites pass.

Non-goals

  • No private task data committed to Git.
  • No live provider execution.
  • No statistical pass@k redesign in this task.
  • No automatic training or reward updates from holdout results.
