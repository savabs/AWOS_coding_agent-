Spec: Recenter Self-Improving Coding Agent

doc/spec phase/4 topic/self-improving-coding-agent active 2026-07-26

Goal

Make the repository’s current-facing identity consistently describe AWOS as a learnable OS built through the pathway proper coding agent → self-learning coding agent → AI-operated OS, where self-learning means the agent improves by analyzing and solving its own prior failures rather than by product/GTM framing or generic customer-memory claims.

Implementation Steps

Each step is atomic: changes one thing, tests one thing, proves one thing.

Step 1
Correct canonical identity documents

Update VISION.md, README.md, AWOS.md, AGENT_INDEX.md, and memories/repo/project_structure.md so they consistently present AWOS as a learnable OS that must first build a proper coding agent, then add failure-driven self-learning, then expand into an AI-operated OS.

Exit condition: Canonical docs explicitly encode the pathway and no longer define the project through CI, customer GTM, or repo-learning-only language.
Step 2
Correct active planning and strategy documents

Update active tasks/specs/research/product docs that currently state the repo is organized around customer pilots, pricing, agency GTM, compounding-sales framing, or CI-wedge identity. Preserve CI repair only as one benchmark workload where appropriate.

Exit condition: Active docs no longer claim the current project focus is customer/pilot/GTM-first or CI-wedge-first.
Step 3
Correct UI, packaging, and agent-facing copy

Update visible UI labels, descriptions, and backend naming so the app is clearly the interface to the coding agent. Remove top-level CI-wedge, pricing, or customer-sales identity from user-facing copy unless a string is clearly tied to a benchmark or narrow feature endpoint.

Exit condition: Main user-facing surfaces describe AWOS as a coding-agent system and interface, not a CI wedge or GTM product shell.
Step 4
Validate the correction pass

Run targeted grep checks and project diagnostics to confirm the updated wording is in place and no accidental syntax issues were introduced in edited code or JSON files.

Exit condition: Grep results and diagnostics match the intended scope; historical files remain untouched.

Edge Cases

  • Historical references to the CI Rescue pivot can remain in immutable checkpoint files and clearly historical notes.
  • Capability-specific mentions of fixing CI may remain when they describe a benchmark or narrow workflow rather than the top-level identity.
  • Generated files under .awos/ should not be edited as part of this consistency pass.
  • “Compounding” may remain where it describes an effect, but not where it replaces the clearer failure-driven self-learning definition.
