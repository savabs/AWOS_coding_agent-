Spec: Held-out Report Verification v1

Goal: Verify two digest-bound report bundles against a holdout manifest and produce a deterministic per-task regression result.

Research: holdout_report_verification_v1.html
Task: holdout_report_verification_v1.html

Files affected

  • scaffold/agent/evaluation_corpus.py — report bundle and verification functions.
  • tests/test_evaluation_corpus.py — bundle, integrity, coverage, and comparison tests.
  • docs/evaluation_holdout_v1.md — operator workflow update.

Atomic steps

1. Define HoldoutReportBundle. Store schema version, corpus ID, environment identity, and one EvaluationReport per task.
Verify: deterministic JSON round trip.
2. Verify artifact digest. Hash exact report bytes before parsing and compare with the manifest reference.
Verify: modified artifact is rejected.
3. Verify identity. Require bundle corpus/environment to equal the manifest.
Verify: each mismatch is rejected.
4. Verify coverage. Require report task IDs to equal manifest task IDs exactly.
Verify: missing, extra, and duplicate IDs are rejected.
5. Compare tasks. Call existing hard-gate compare_reports for every task and mark aggregate regression if any correctness or safety regression exists.
Verify: candidate failure cannot be hidden by another task’s success.
6. Serialize comparison. Emit deterministic JSON with per-task and aggregate results.
Verify: output round-trips exactly.
7. Validate. Run focused corpus/evaluator tests and scoped lint.
Verify: all commands pass.

Non-goals

  • No provider execution.
  • No private task contents.
  • No reward updates or prompt tuning from holdout outputs.
  • No statistical pass@k redesign.
