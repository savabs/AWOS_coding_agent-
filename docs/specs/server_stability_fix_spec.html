📋 Spec: Server Stability Fix

Phase: 4 · Date: 2026-07-21 · Priority: CRITICAL (#1)

Goal

Fix resource leaks causing the server to crash after 2–3 chat queries, enabling stable multi-query sessions.

Files Affected

scaffold/agent/gui_chat.py3 leak vectors: requests.Response, openai.OpenAI, Anthropic clients
gui/server.py_send_sse() generator consumption exception hole
scaffold/agent/provider_health.py4 client leak vectors in health check functions

Implementation Steps

Step 1: Close streaming requests.Response in _stream_opencode_go()

File: scaffold/agent/gui_chat.py

What: Wrap the anthropic-protocol streaming path in a try/finally block that calls resp.close(). This is the single largest leak (1–3 TCP sockets per query).

Verification: Run 20 sequential chat queries via stress test. Server stays alive. No OSError: Too many open files.

Edge cases: What if resp.close() itself raises? Wrap in nested try/finally with exception suppression.

Step 2: Close openai.OpenAI and Anthropic clients in gui_chat.py

File: scaffold/agent/gui_chat.py

What: Store OpenAI/Anthropic clients as instance attributes on GuiChatService (created once in __init__, reused across calls). Add a close() method for explicit cleanup.

Affected: _stream_deepseek() (OpenAI client), _stream_anthropic() (Anthropic client), _stream_opencode_go() (OpenAI client_chat)

Verification: After 20 queries, only 3 httpx.Client objects exist (one per cached client). No growth per query.

Edge cases: Client creation can fail (missing API key). Lazy initialization — create only on first use. Handle None gracefully.

Step 3: Safeguard _send_sse() generator consumption

File: gui/server.py

What: Wrap the generator consumption loop (for _ in gen: pass) in a try/except to catch and suppress downstream exceptions when the client has already disconnected.

Verification: Force a client disconnect mid-stream. No unhandled exceptions in server logs. Server thread stays alive.

Edge cases: Only catch in the consumption path, not in the primary streaming path where errors should propagate.

Step 4: Close clients in provider_health.py

File: scaffold/agent/provider_health.py

What: Add try/finally: client.close() to check_deepseek(), check_anthropic(), check_openai(), and check_opencode_go().

Verification: Health check daemon runs for 10 cycles (50 minutes simulated). No client leak growth.

Edge cases: What if client is None (missing API key)? Guard with conditional close.
