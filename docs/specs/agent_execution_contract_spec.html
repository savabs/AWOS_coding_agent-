phase/1 · topic/agent-reliability · status/active · 2026-07-31

Goal

Make AWOS use an explicit, executable agent capability contract so general autonomous coding remains capable while audited benchmark runs are narrow, deterministic, state-aware, budget-bound, and evidence-complete.

Atomic implementation steps

1. Define capability profiles.

Add explicit Explore, Build, and Benchmark profile names and allowed tool sets without removing existing tools from the default Build path.

Exit: profile unit tests show Benchmark omits shell/web/GitHub/HF/run_python and Build retains existing autonomous tools.
2. Enforce profile dispatch.

Make the worker construct the selected profile registry and return a structured blocked-action result for unavailable actions.

Exit: a fake Benchmark model requesting shell cannot execute or modify the workspace.
3. Separate progress dimensions.

Track exploration, edit, verification, and repeated-call progress independently.

Exit: read/grep exploration does not trigger benchmark stagnation before the configured exploration bound.
4. Make completion evidence-based.

Permit successful completion after target edit and passing verification even when the model omits finish.

Exit: read → edit → read → run_tests succeeds without finish; unchanged target fails.
5. Preserve provider identity.

Use the explicit model specification for every worker request and reject a trial-local provider mismatch.

Exit: fake request inspection proves OpenCode Go / deepseek-v4-pro for planner and worker calls.
6. Preserve autonomous Build behavior.

Run general ReAct/orchestrator regression cases with the Build profile and verify structured editing, tests, recovery, and callbacks remain available.

Exit: existing autonomous E2E and ReAct tests pass without enabling benchmark restrictions.
7. Add trial-local budget guard.

Check accumulated provider usage before each request and return a terminal truthful result when the trial cap would be exceeded.

Exit: a fake multi-call worker stops before cumulative cost exceeds the configured cap.
8. Run focused validation and update task state.

Run targeted tests, then the complete focused suite, and record results in the task file before any live call.

Exit: focused suite is green and the task records the exact command and result.

Edge cases

  • Unknown profile fails closed rather than defaulting silently.
  • Blocked shell request cannot change files through a fake or real registry.
  • Read-only exploration may use several distinct calls without being treated as a loop.
  • Repeated identical failing calls stop with a truthful error.
  • Model returns finish before an edit: task fails if an edit is required.
  • Tests are unavailable: result is inconclusive/failed according to evaluator policy, never falsely successful.
  • Provider returns empty content: no fallback to an unauthorized provider.
