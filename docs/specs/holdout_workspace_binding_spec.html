Spec: Holdout Workspace and Report Binding

phase/1 · topic/evaluation · active · 2026-07-31

Goal

Make one private holdout run use its selected hidden oracle and produce a candidate report that the comparison verifier can authenticate.

Research: holdout_workspace_binding.html
Task: holdout_workspace_binding.html

Allowed files

  • scripts/run_holdout_live.py
  • tests/test_holdout_live.py
  • scaffold/agent/evaluation_corpus.py only if the manifest lifecycle requires a typed helper
  • private ignored holdout fixture/oracle/manifest artifacts

Atomic steps

Step 1 — Bind the oracle token.

Resolve a fixture acceptance token to a hidden oracle directory inside the selected private root and reject missing/outside paths.

Exit: a fixture cannot retain the historical _clean path; a temporary-root test resolves the token correctly.

Step 2 — Reject stale candidate state.

Require the candidate report path to be absent and the manifest candidate digest to be an unset zero digest before a live run.

Exit: stale report or nonzero candidate digest fails closed before provider execution.

Step 3 — Finalize candidate binding.

Write the candidate bundle, compute its digest, and atomically update the manifest candidate reference after execution.

Exit: the comparison verifier accepts a generated candidate bundle with the finalized manifest.

Step 4 — Run offline gates.

Run holdout tests, comparison tests, and dry-run validation without provider calls.

Exit: all relevant offline tests pass.

Edge cases

  • Oracle token missing.
  • Oracle path escapes the selected root.
  • Candidate report already exists.
  • Candidate digest is stale/nonzero before execution.
  • Manifest finalization is interrupted.
