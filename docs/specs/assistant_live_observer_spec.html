Spec: Assistant Live Observer

Status: active · Phase: 1 · Date: 2026-07-27

Goal

Provide a reliable local observer contract through which an assistant can follow AWOS user actions and backend execution live, recover from disconnects, and distinguish current events from historical sessions.

Governing research: assistant_live_observer.html
Task file: assistant_live_observer.html

Design constraints

  • Use existing GuiEventBus, JSONL event logs, SSE, session manifests, and renderer projection where possible.
  • Keep the event contract reusable beyond coding-agent UI.
  • Use structured events as truth; screenshots are out of scope.
  • Never expose hidden chain-of-thought, API keys, or unbounded raw sensitive payloads.
  • Bind local observer endpoints to localhost by default.
  • Do not make a model/provider or MCP a kernel dependency.

The Electron application loads gui/static/agent.html at /agent; it must be instrumented alongside the browser chat and developer renderer.

Implementation steps

Step 1 — Define the event envelope.

Add schema version, event ID, sequence, timestamp, source, type, correlation fields, payload, and visibility.

Exit: Envelope fixtures validate and malformed envelopes are rejected without crashing the stream.

Step 2 — Assign stable event IDs.

Assign a unique ID and monotonic sequence at event creation, then persist both in JSONL.

Exit: One session's event log has strictly increasing sequences and unique IDs.

Step 3 — Add correlation identifiers.

Propagate session, chat, trace, and optional task identifiers across UI and agent events.

Exit: A submitted UI action can be joined to its agent session and terminal evidence.

Step 4 — Classify assistant-safe payloads.

Define allowlisted event types and bounded fields for the assistant observer.

Exit: Hidden reasoning, secrets, and oversized payloads are excluded or redacted.

Step 5 — Emit meaningful UI actions.

Emit app lifecycle, view, prompt submission, session selection, approval, and task-control events without logging every keystroke.

Exit: A user task produces a correlated UI-to-backend timeline.

Step 6 — Add replay by cursor.

Expose a bounded event-range endpoint accepting session and cursor parameters.

Exit: Replaying after an event ID returns only later events in order.

Step 7 — Add resumable observer SSE.

Expose filtered SSE with SSE event IDs, keepalive comments, retry guidance, and Last-Event-ID support.

Exit: Disconnect/reconnect does not lose or duplicate events in the tested range.

Step 8 — Add current observer snapshot.

Project the latest safe events and manifests into a compact snapshot with cursor and freshness metadata.

Exit: A fresh observer can reconstruct current state with one read.

Step 9 — Add assistant read-only adapter.

Add awos observe snapshot and awos observe events or an equivalent local tool contract.

Exit: An assistant/tool call can retrieve current state and cursor ranges without mutating AWOS.

Step 10 — Migrate renderer to observer contract.

Keep the renderer's existing projection while switching its live/replay source to the shared observer API.

Exit: Existing renderer tests and live browser smoke continue to pass.

Step 10a — Instrument the Electron entrypoint.

Emit semantic observer events from gui/static/agent.html, the page loaded by Electron at /agent, without logging raw keystrokes or prompt text.

Exit: Opening Electron and submitting a request produces UI events carrying the same chat/trace correlation as the backend run.

Step 11 — Run live listener proof.

Open Electron, perform UI actions, run a bounded task, disconnect/reconnect the observer, and compare assistant observations with the UI/backend.

Exit: The observer identifies the current chat/session and narrates the ordered backend path without historical-session confusion.

Edge cases

  • No active session returns an explicit idle snapshot, not an invented current run.
  • Concurrent sessions require an explicit filter or are represented as separate streams.
  • Reconnect from an unknown cursor returns a gap marker and a snapshot request path.
  • Malformed JSONL is reported as a bounded observer error and does not stop later events.
  • Large tool output is summarized with a reference to persisted evidence.
  • Secret-like payloads are redacted before SSE, snapshot, or CLI output.
  • User prompt content is governed by an explicit local privacy setting.
