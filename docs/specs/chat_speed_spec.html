📋 Spec: Chat Speed Optimization

Phase:4 · Priority: #1 (after stability fix)

Goal

Reduce chat response time from 7-16s to 3-5s for typical queries. Target: codebase queries under 8s, simple queries under 3s.

Files Affected

scaffold/agent/gui_chat.pyAll 5 fixes

Step 1: Remove max_tokens hardcoded override + dynamic sizing

What: Delete line 1045 max_tokens = 2048. Add logic to choose max_tokens based on query type: 256 for simple questions, 2048 for codebase/architecture questions.

Heuristic: If query contains project-specific keywords (AWOS, orchestrator, kernel, scaffold, agent, routing, verify, CI, rescue) → 2048. Otherwise → 512.

Verify: Simple "What is Python?" uses 512 tokens and completes under 5s. Codebase query uses 2048.

Step 2: Short-circuit context for non-codebase queries

What: In _read_project_context(), skip SymbolIndex loading for generic questions. Check if query has project-specific keywords; only load SymbolIndex if it does.

Verify: "What is Python?" — no SymbolIndex loaded, context under 4K chars. "How does orchestrator work?" — SymbolIndex loaded.

Step 3: Eliminate duplicate context loading

What: In _stream_qa(), load context once, pass to both _build_qa_prompt() and _qa_context_blob(). Modify _build_qa_prompt to accept optional pre-loaded context.

Verify: _read_project_context() called exactly once per query.

Step 4: Reduce artificial time.sleep delays

What: Cache path: time.sleep(0.008) → time.sleep(0.002). Plan path: remove entirely (use real streaming speed).

Verify: Cache hit response under 100ms (was ~250ms). Plan display at natural speed.

Step 5: Reduce fallback timeout

What: Per-model timeout: 6s → 4s. Total timeout: 20s → 12s. The primary model (MiniMax M3) responds in ~1.6s. 6s is generous for a timeout.

Verify: Fallback chain completes within 12s when primary model fails.
