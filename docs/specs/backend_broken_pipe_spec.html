Spec: Attribute and Recover From Backend Broken Pipe

Status: active · Governing research: docs/research/backend_broken_pipe.html

Goal

Identify the exact backend boundary producing Broken pipe, preserve actionable evidence, and prevent a real UI submission from failing without a correlated runtime outcome.

Allowed implementation files

  • awos-app/main.js
  • awos-app/dev-runner.js
  • scaffold/agent/gui_chat.py only if further attribution proves it is needed.
  • The specific provider/worker module proven to be the failing boundary.
  • A focused regression test under tests/ or awos-app/.

Atomic steps

  1. ☑ Reproduce the failure through a direct bounded backend call and record the exact failing boundary.
  2. ☑ Add structured attribution around the proven external boundary without changing success behavior.
  3. ☐ Add a regression test that simulates a closed pipe and asserts an actionable error result.
  4. ☑ Apply the minimal lifecycle fix at the proven boundary.
  5. ☐ Run focused tests and a live Electron task; verify a runtime session is created or the failure is correlated to the correct chat/trace.

Non-goals

  • No broad provider rewrite.
  • No observer replay changes during diagnosis.
  • No swallowing or relabeling the error as success.
  • No model/provider replacement as a workaround.

Exit criteria

The smallest live task either creates a resolvable runtime session and completes, or emits a correlated backend failure with boundary, provider, and trace evidence.
