Spec: Planning & Exploration v1

phase/1 · topic/planning-exploration · active · 2026-07-29

Goal

Provide the planner with one bounded, structured, replayable repository snapshot and reject plans whose files or atomic acceptance contracts are not grounded in that snapshot, while preserving final test correctness as the hard quality gate.

Atomic implementation steps

Step 1 — Define the exploration snapshot schema.

Add a typed/deterministic schema containing run ID, goal terms, explicit paths/symbols, candidate files, search hits, structural anchors, dependency facts, test/config files, negative evidence, bounds, and tool-cost counters.

Exit: a fixture snapshot serializes deterministically and includes all required fields without scanning excluded directories.

Step 2 — Normalize goal references.

Extract quoted/backticked paths, file extensions, symbols, and search concepts while preserving exact references separately from fuzzy keywords.

Exit: tests distinguish explicit target paths from inferred keywords and preserve case-sensitive symbols.

Step 3 — Bound and unify repository discovery.

Make pre-plan exploration and ReAct repo mapping consume one bounded discovery path with configurable file, hit, byte, and latency limits.

Exit: a fixture run reports identical candidate/hit evidence across both consumers and never exceeds configured bounds.

Step 4 — Connect the snapshot to planning.

Pass the structured snapshot and compact summary into the planner context and persist a run-linked exploration evidence record.

Exit: a mocked planner receives the snapshot ID, grounded files, and evidence references; no live model call is needed.

Step 5 — Validate the plan contract.

Require each accepted task to contain one primary file, a concrete action, an acceptance check, and an exploration evidence reference; reject unresolved paths.

Exit: invalid-path and multi-file/non-atomic plans are rejected before Worker/ReAct execution.

Step 6 — Add deterministic planning-quality fixtures.

Create reviewed fixtures for single-file, cross-module, test-repair, ambiguity, non-Python, and no-match tasks with expected target files and dependencies.

Exit: fixture metadata contains explicit ground truth and can be loaded without network access.

Step 7 — Add offline evaluation assertions.

Score target-file recall, invalid-path rate, dependency recall, atomicity, exploration cost, and evidence completeness; final repository tests remain a hard gate.

Exit: the evaluator reports per-fixture results plus aggregate metrics and fails when correctness or evidence is missing.

Step 8 — Run regression and baseline comparison.

Run the new deterministic suite plus existing E2E/outcome-gate tests and compare the upgraded path against the current baseline.

Exit: all existing tests pass, the new evaluator produces a versioned report, and no quality regression is hidden by averages.

Outcome contract

  • Exploration is bounded, deterministic, and replayable.
  • Every accepted plan task is grounded in a resolvable file and evidence reference.
  • Planner quality is measured against reviewed fixture truth, not prose or model confidence.
  • Final tests and repository state are authoritative; cost and speed can only optimize after the quality floor is met.
  • All eval runs record configuration, model/provider identity, trial number, tool actions, observations, costs, latency, and final result.

Edge cases

  • Explicit file path does not exist: plan validation fails with a structured finding.
  • Goal has no useful keywords: preserve negative evidence and require deliberate tool exploration.
  • Non-Python repository: do not claim Python-only recall; report unsupported language coverage explicitly.
  • Large repository: enforce file/hit/byte/time budgets and report truncation.
  • Ambiguous goal: planner may ask for clarification or produce a marked low-confidence plan; it may not silently guess.
  • Fixture has no discoverable tests: evaluator reports unverified correctness rather than awarding success.
