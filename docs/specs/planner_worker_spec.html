Specification: Planner-Worker Orchestrator

Atomic implementation steps for cost-optimized hierarchical agent system

Overview

Build a 4-module system: Planner (reasoning) → Worker (execution) → Verifier (validation) → Orchestrator (coordination). Each step is atomic: one thing changed, one test, one proof.

Phase 1: Planner Module

1
Create scaffold/agent/planner.py

What: Build Sonnet interface that converts user goals into JSON blueprints.

Interface:

class Planner:
    def plan(self, goal: str, codebase_context: dict) -> dict:
        """
        Returns:
        {
          "plan": [
            {"task_id": 1, "file": "...", "action": "...", "complexity": "low/medium/high"},
            ...
          ],
          "reasoning": "..."
        }
        """

Implementation details:

  • Accept goal + codebase context (STRUCT.xml loaded as dict)
  • Call Sonnet via Anthropic API with structured output constraint
  • Parse JSON response, validate schema
  • Return dict with plan array + reasoning field
Exit Criteria: Call planner.plan("add user auth") on sample codebase, receive valid JSON with ≥3 tasks, each with file/action/complexity.
2
Add cost tracking to Planner

What: Record Sonnet API calls and token usage.

Implementation:

  • Before calling Sonnet, note timestamp + input tokens
  • After response, record output tokens + cost
  • Log to token_tracker (already exists)
  • Add plan() method param: tracker: TokenTracker = None
Exit Criteria: Planner logs one call to token_tracker. Verify cost is ~$0.03-0.05 for typical feature request.

Phase 2: Worker Module

3
Create scaffold/agent/worker.py

What: Build DeepSeek interface that executes one micro-task (SEARCH/REPLACE).

Interface:

class Worker:
    def execute_task(self, task: dict, file_content: str, codebase_context: dict) -> dict:
        """
        Args:
          task: {"task_id": 1, "file": "...", "action": "...", "complexity": "..."}
          file_content: Full text of the file to modify
          codebase_context: Dict of relevant codebase info
        
        Returns:
        {
          "search": "exact text to find",
          "replace": "exact text to replace with",
          "reasoning": "why this change"
        }
        """

Implementation details:

  • Accept task + file content + context (max 50 lines of actual code + surrounding)
  • Call DeepSeek Coder via API
  • Parse SEARCH/REPLACE response (strict format validation)
  • Return dict with search, replace, reasoning
Exit Criteria: Execute one task on real file (e.g., add struct field), receive valid SEARCH/REPLACE that when applied doesn't break file structure.
4
Add cost tracking and retry logic to Worker

What: Track DeepSeek calls, implement automatic fallback to Haiku if API rate-limited.

Implementation:

  • Record call to token_tracker (input + output + cost)
  • On API error, set fallback_model="Haiku" and retry once
  • If second attempt also fails, propagate error with full context
Exit Criteria: Trigger one successful execution logged to token_tracker (~$0.001 cost). Verify fallback path works (manually trigger API timeout simulation).

Phase 3: Verifier Module

5
Create scaffold/agent/verifier.py

What: Apply SEARCH/REPLACE, run compiler/lint, detect errors.

Interface:

class Verifier:
    def verify_and_apply(self, search_replace: dict, file_path: str, check_type: str = "syntax") -> dict:
        """
        Args:
          search_replace: {"search": "...", "replace": "..."}
          file_path: Path to file to modify
          check_type: "syntax", "lint", or "all"
        
        Returns:
        {
          "success": bool,
          "applied": bool,
          "errors": [],
          "file_content": "modified content (if applied)"
        }
        """

Implementation details:

  • Read file, apply SEARCH/REPLACE (using exact string match)
  • If search string not found, return success=False
  • If applied, run local compiler (g++, python -m py_compile, etc based on extension)
  • Parse compiler errors, return errors array (empty if no errors)
Exit Criteria: Apply valid SEARCH/REPLACE to real file, verify compiles. Deliberately introduce syntax error, confirm error is caught and returned.
6
Add error feedback loop to Verifier

What: If verification fails, return structured error for worker retry.

Implementation:

  • Parse compiler error, extract line number + error message
  • Return dict with needs_retry: bool and error_context: str
  • Include relevant lines from file where error occurred
Exit Criteria: Apply broken SEARCH/REPLACE, detect error, return structured feedback that worker can use to fix (no new API call yet).

Phase 4: Orchestrator Integration

7
Create scaffold/agent/orchestrator.py

What: Coordinate planner → worker → verifier loop.

Interface:

class Orchestrator:
    def execute_feature(self, goal: str, codebase_context: dict) -> dict:
        """
        1. Plan: Call planner.plan()
        2. Loop through tasks:
           a. Load file content
           b. Call worker.execute_task()
           c. Call verifier.verify_and_apply()
           d. If error: retry with error context (max 2 retries)
           e. If success: move to next task
        3. Return final report
        """

Implementation details:

  • Sequential task execution (start with serial, parallelize in Phase 2)
  • Maintain state: tasks_completed, tasks_failed, total_cost
  • On worker error + retry: pass error_context to next worker call
  • Track timing for each phase
Exit Criteria: Execute end-to-end: plan a simple 2-3 task feature, execute all tasks, verify all apply successfully, report total cost breakdown.
8
Integrate orchestrator into unified_agent.py

What: Add "planner-worker mode" to existing unified agent.

Implementation:

  • Add menu option: "Execute with Planner-Worker" (separate from existing REASONING mode)
  • Detect request type in RequestRouter: if goal-setting language → route to PW mode
  • Call orchestrator.execute_feature() and stream progress
  • Display final cost + token usage
Exit Criteria: Run unified_agent, select PW mode, execute a feature request, see full progress output and final cost report.

Feature example: "Add a progress bar to the unified agent menu output"

Validation:
