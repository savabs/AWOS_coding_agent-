Spec: Authenticated Electron Control Bridge

Status: active · Date: 2026-07-28

Goal

Allow the assistant to operate the user’s actual running Electron window through a bounded, auditable local API while preserving the observer as the source of truth.

Non-goals

  • No arbitrary shell commands.
  • No arbitrary JavaScript supplied by callers.
  • No OS-wide mouse or keyboard automation.
  • No Playwright dependency in this milestone.
  • No automatic stopping or restarting of a user’s active agent run.

Contract

Electron main process listens only on 127.0.0.1 at a dedicated control port. Requests require X-AWOS-CONTROL-TOKEN. JSON body limit is bounded. Responses include status, request_id, action, and a safe result/error summary.

{"action":"show|hide|focus|status|reload|navigate|click|fill|cancel","target":"...","value":"...","chat_id":"optional","trace_id":"optional"}

Allowed action semantics

  1. status: return window visibility/focus/loading/current internal route.
  2. show/focus/hide: operate the real main window.
  3. reload: reload the current renderer and emit lifecycle events.
  4. navigate: only allow known local AWOS routes such as /agent and /renderer.
  5. click: click only registered semantic controls by action id, not arbitrary selectors.
  6. fill: fill only registered safe text inputs, with a maximum length and no password fields.
  7. cancel: request cancellation through the app’s existing UI/backend cancellation path; never kill a process.

Atomic implementation steps

  1. Add token loading and request authentication in the Electron main process; prove unauthorized requests fail.
  2. Add a single status action; prove it reports the real running window.
  3. Add show, hide, focus, and reload actions; prove each changes the real window and emits audit telemetry.
  4. Add allowlisted internal navigation; prove external URLs are rejected.
  5. Add semantic renderer action dispatch for click and bounded fill; prove unknown targets and oversized values are rejected.
  6. Add cancellation dispatch without process termination; prove a cancellation request is observable.
  7. Add CLI commands and focused integration tests against a live Electron instance.
  8. Run the quality gate and complete a live user-approved control proof.

Exit criteria

  • Assistant can query and operate the actual Electron window, not a second test window.
  • Every action is authenticated, bounded, observable, and auditable.
  • Denied actions leave no ambiguous partial state.
  • Control can be disabled without deleting observer data or touching the active agent run.
