Spec: Holdout Trial Reliability

phase/1 · topic/evaluation · active · 2026-07-31

Goal

Ensure a failed holdout execution always yields truthful evaluator evidence and that fixed-provider errors identify the actual provider without exposing secrets.

Atomic steps

Step 1 — Record acceptance launch errors.

Catch OSError in _run_acceptance() and return a failed structured outcome with no secret or full traceback.

Exit: a missing executable produces passed=false and a completed TrialResult.

Step 2 — Preserve agent exceptions.

Run an adapter trial whose agent raises and prove the evaluator returns an error-status result with an ordered trajectory.

Exit: test_orchestrator_adapter_exception_is_reported passes.

Step 3 — Correct fixed-provider error labels.

Replace stale Gemini labels in CheapPlanner with the fixed provider/model identity.

Exit: malformed planner output raises an error naming OpenCode Go and deepseek-v4-pro, not Gemini.

Step 4 — Run focused offline gates.

Run evaluation and fixed-provider tests without credentials or provider calls.

Exit: all focused tests pass.

Edge cases

  • Acceptance executable is missing.
  • Acceptance command times out.
  • Agent raises an exception before editing.
  • Provider returns malformed JSON.
  • Error output contains a long or sensitive response.
