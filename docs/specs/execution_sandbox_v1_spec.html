Spec: Execution Sandbox v1

phase/1 · topic/execution-safety · active · 2026-07-29

Goal

Execute coding-agent commands and edits in an explicitly declared isolation level with fail-closed path/policy checks, approval for risky actions, bounded processes, idempotent cleanup, and evidence proving what happened.

Atomic implementation steps

Step 1 — Define the sandbox policy schema.

Add isolation level, network mode, writable roots, command limits, approval mode, and policy version.

Exit: policy serializes deterministically and unknown/unsafe modes fail closed.

Step 2 — Enforce workspace path containment.

Reject traversal, symlink escape, and out-of-root file/tool paths before execution.

Exit: hostile path tests prove no host file changes.

Step 3 — Bind approval to action identity.

Require approval for risky actions and bind it to session, policy version, command, arguments, and path digest.

Exit: changing an approved command or session invalidates approval.

Step 4 — Bound process execution.

Run commands in a dedicated process group with timeout, cancellation, output limits, and deterministic termination.

Exit: timeout/fork/resource tests terminate descendants and return structured failure.

Step 5 — Harden worktree lifecycle.

Create, identify, finalize, and remove disposable workspaces idempotently.

Exit: success, failure, crash, and repeated cleanup leave no untracked sandbox residue.

Step 6 — Record security evidence.

Persist policy decision, approval, action digest, environment identity, exit status, and cleanup result.

Exit: every attempted risky action has an auditable evidence record.

Step 7 — Run hostile-path proof.

Run the sandbox test suite plus planning/outcome/E2E tests without network or live model calls.

Exit: host remains unchanged for denied/failed actions and all permitted changes are scoped to the workspace.

Hard security contract

  • No approval means no risky side effect.
  • No path may escape the declared workspace.
  • No process may outlive its session without explicit evidence.
  • No secret or host credential directory is mounted implicitly.
  • No “sandboxed” status is reported unless the declared isolation guarantee is actually active.
  • Cleanup failure is a task failure requiring explicit user visibility.
