Goal

Create a deterministic, replayable evaluation harness that grades coding-agent runs with a hard correctness/safety gate and reports reliability, trajectory, cost, latency, and reward separately.

Atomic implementation steps

Step 1 — Define the fixture and report schemas.

Create typed, versioned schemas for task metadata, acceptance checks, forbidden paths, trial outcomes, trajectories, and aggregate reports.

Exit: valid fixtures serialize deterministically and invalid fixtures fail closed in a unit test.

Step 2 — Implement isolated fixture execution.

Copy a fixture repository into a temporary workspace and execute a supplied deterministic agent callback with bounded time and no network dependency.

Exit: a trial gets a fresh workspace and leaves the source fixture unchanged.

Step 3 — Implement executable acceptance grading.

Run required acceptance commands and forbidden-path checks, then derive hard success from those results.

Exit: a deliberately wrong patch fails even when it is cheap and syntactically valid.

Step 4 — Capture replayable trajectories.

Record ordered agent/tool/test/rollback events and environment identity in the trial report.

Exit: a saved report can be loaded and inspected without invoking a model.

Step 5 — Aggregate multi-trial metrics.

Calculate pass@1, all-trial reliability, latency, cost, retry, safety, and hard-gate failure metrics.

Exit: deterministic repeated trials produce the same aggregate report.

Step 6 — Separate reward from correctness.

Compute a diagnostic reward with correctness as a hard multiplier and retain raw metrics.

Exit: no failed trial receives a successful outcome or positive success label.

Step 7 — Add regression comparison and CLI.

Compare a candidate report against a baseline and expose list/run/replay commands.

Exit: the offline CLI runs the fixture suite and reports regressions without API keys.

Edge cases

  • Acceptance command timeout → failure and bounded cleanup.
  • Malformed agent result → failure with an evidence entry.
  • Forbidden file write → safety failure even if tests pass.
  • No acceptance checks → invalid fixture, never an automatic success.
  • Missing report or mismatched schema version → replay failure.
  • Zero-cost or zero-duration trial → stable division handling.
