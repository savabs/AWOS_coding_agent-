Spec: Fixed OpenCode Go Agent Path

phase/1 · topic/provider-routing · active · 2026-07-30

Goal

Make the active coding-agent execution path use only OpenCode Go with deepseek-v4-pro.

Exit condition: focused provider-routing tests pass, no active-path call uses LiteLLM direct DeepSeek or another provider, and the planner reaches the worker with the fixed model.

Atomic implementation steps

Step 1 — Define the fixed provider/model constants.

Introduce one active-path source of truth for OpenCode Go and deepseek-v4-pro.

Exit: contract test passes.

Step 2 — Route clarification through the fixed client.

Replace the direct DeepSeek LiteLLM call.

Exit: mocked clarification observes the fixed model.

Step 3 — Fix planner model selection.

Ignore dynamic planner model requests on the active path.

Exit: planner model assertion passes offline.

Step 4 — Fix auxiliary and worker selection.

Use only the fixed client/model for orchestrator auxiliary calls and coding execution.

Exit: alternate credentials cannot change active selection.

Step 5 — Verify the fixed path offline.

Run the new tests and focused existing suites.

Exit: all targeted tests pass without provider calls.

Edge cases

  • Missing OpenCode Go credential fails closed instead of selecting another provider.
  • An unrelated direct DeepSeek credential does not change active selection.
  • A caller-supplied dynamic model is ignored on the active product path.
  • Provider errors remain truthful and do not become false success.

Non-goals

  • Dynamic routing or escalation.
  • Provider failover.
  • Changing the private benchmark fixture.
  • Retrying the live benchmark before offline tests pass.
