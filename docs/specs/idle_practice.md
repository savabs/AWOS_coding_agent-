# Idle-time practice (T9): LLM-free practice tasks and a per-repo capability map

Status: generator, capability map and tests are implemented (2026-10-09). The overnight scheduler and the router hook are **not** wired in yet (see §6).
VISION stage: Stage 1 (one excellent worker): routing evidence and verification. Training on practice data is **DEFERRED** (`VISION.md`, Explicitly Deferred).
Source: `docs/research/trick_book_2026-10.md` §1 #10, §2.6, §3 combination 1, experiment E8.

## 1. Purpose

The always-on box is idle overnight. During that time it can inject known bugs into the owner's repos and let the local model try to fix them. A hidden oracle scores every attempt: the original test files, which passed before the bug was injected. That gives two things:

1. A **per-repo capability map**: a Beta posterior of the local model's verified solve rate for each (repo, bug type). The router can then escalate only where P(θ_local ≥ t) is low (trick book §2.5, E8).
2. **Strong evidence for skill promotion**: the hidden oracle uses held-out tests, which is the admission standard in §2.6 (combination 1: practice → verified compile → replay → Beta promotion).

No model is trained on this data.

## 2. Research (brief)

- **SWE-smith** (Yang et al., arXiv 2504.21798) synthesizes task instances from any Python repo with a test suite. It uses four bug-generation strategies:
  - **LM Generate/Rewrite**: an LM edits a function, or rewrites it from its signature and docstring.
  - **Procedural modification**: LLM-free AST transforms, for example changing an operator, swapping operands, inverting an if/else, removing a conditional, loop or assignment, shuffling lines, changing a constant, or removing a class method or base.
  - **Combine**: merge several validated bugs in one file or module.
  - **PR Mirror**: an LM reverts a real PR's diff into the current code.

  The **validation rule** keeps a candidate only if the suite still runs and **≥1 previously passing test now fails** (fail-to-pass). Candidates that break collection or time out are discarded. The paper reports roughly 23 min and $2.47 of compute per repo for environment construction plus generation.

  Issue text is generated by an LM from the patch and the failing tests. That step is not needed for an oracle-scored practice task: a templated report built from failing test names and assertion messages is enough. An LM rewrite can be added later as an optional step.
- **Mutation testing** (classical operators: relational/arithmetic/logical operator replacement, constant ±1, statement deletion, negated condition, return-value replacement) is the LLM-free core. Two of its standard problems carry over. *Equivalent mutants* are neutralized by the fail-to-pass rule. The *coupling effect* (simple mutants couple to real faults) is the main argument that they are useful practice at all.
- **BugPilot** (arXiv 2510.19898) reports that bugs which arise *naturally* (introduced while an agent adds a feature) train better than intentionally injected ones. This is the main realism risk (§7).
- **ACH** (Meta, arXiv 2501.12862) uses mutation-guided test generation. Its lesson: plausible, domain-relevant mutants matter more than mutant count.
- **Sleep-time compute** (arXiv 2504.13171) does precomputation during idle time. When queries are predictable it cuts test-time compute by about 5×. A repo's capability map and repo card are that kind of precomputation.

## 3. Generator: `scripts/practice/make_tasks.py`

```
python scripts/practice/make_tasks.py <repo_dir> --out <series_root> --n 10 \
    [--name NAME] [--budget-s 1800] [--per-file 2] [--seed 0] \
    [--max-fail-frac 0.5] [--max-tries 400] [--dead-file-after 12]
```

The generator works in these steps:

1. **Safety.** It copies `<repo_dir>` to a temp dir and never writes the original. `--out` must not be inside the repo. Every pytest run uses `PYTHONDONTWRITEBYTECODE=1`, which avoids stale `.pyc` files after a same-size edit.
2. **Baseline.** It runs `python -m pytest tests` with a junit XML report and requires a green run. If the baseline is red, it aborts.
3. **Candidates.** It enumerates every candidate in the source modules: never `tests/`, `docs/`, `conftest.py`, `setup.py` or `_version.py`. Annotations, `if TYPE_CHECKING:` blocks and `if __name__ == "__main__":` blocks are skipped. Candidates are ordered round-robin across operators so that the most common operator (off_by_one) does not dominate the output.
4. **Operators** (`scripts/practice/mutators.py`, 10 in all, all LLM-free):

   | op | edit |
   |----|------|
   | flip_compare | `<`↔`>=`, `>`↔`<=`, `==`↔`!=`, `is`↔`is not`, `in`↔`not in` |
   | flip_binop | `+`↔`-`, `*`→`//`, `/`→`*`, `//`→`/`, `%`→`//`, `&`↔`\|`, `<<`↔`>>` (not on string concatenation or `%` formatting) |
   | flip_boolop | `and`↔`or` |
   | off_by_one | int literal n → n±1 |
   | negate_if | `if c:` → `if not c:` (and `if not c:` → `if c:`) |
   | remove_conditional | delete an `if` block that has no `else` |
   | swap_args | `f(a, b, …)` → `f(b, a, …)` |
   | change_return | `return expr` → `return None` |
   | remove_call | delete a bare call statement |
   | swap_ifexp | `a if c else b` → `b if c else a` |

   Edits are **minimal splices**: the generator replaces only the operator token or the swapped operand spans, so formatting is kept and the diff is one small hunk. Each splice is verified two ways: it must compile, and it must parse to *exactly* the intended AST (`ast.dump` equality). If the plain splice fails that check, a parenthesized splice is tried; if that also fails, the candidate is dropped.
5. **Validation.** The generator applies one mutant at a time, runs the suite, and then restores the file. It keeps the mutant only when all of these hold:
   - pytest exits with code 1, so the suite still collects.
   - The suite has the same number of test cases as the baseline.
   - At least one baseline-passing test now fails or errors.
   - The flipped tests are at most `--max-fail-frac` of the suite.
   - The flipped tests live under `tests/`.
   - At least one visible test file remains.

   Rejections are counted by reason: timeout, collection or internal error, no test flipped, too many failures, duplicate, and so on.
6. **Dedupe and caps.** Mutants are deduped by normalized AST (`mutant_key`) and by the (file, set of failing tests) signature. At most `--per-file` mutants are kept per source file. A file is skipped after `--dead-file-after` tries in a row flip no test: the tests never reach it. On humanize this rule cut the tries from 400 to 21 for the same yield.
7. **Time bound.** The run stops when it has `--n` kept mutants, after `--max-tries`, or after `--budget-s` of wall clock. The per-run pytest timeout is max(20 s, 5 × baseline + 10 s).
8. **Output.** Each kept mutant becomes **one series**. A series is cumulative (job N starts from base + references 1..N-1), so independent mutants cannot share one. The format matches `~/.awos-harness/real_series/real_*`:
   ```
   prac_<repo>_<NNN>/
     base/                         repo + mutant, failing tests' files removed from tests/
     jobs/01_regression/
       task.json                   {"id","goal","max_turns":150,"max_cost_usd":1.0,"timeout_min":30}
       hidden_tests/test_hidden_<name>.py   original failing test files (the oracle)
       reference/<src path>        the original source file
     SOURCE.md                     provenance, mutation type, diff
     practice.json                 {repo, op, file, line, failing_tests, hidden_files, diff, ...}
   <series_root>/_practice_runs/<repo>_<ts>.json   run stats (tried/kept/rejected/per_op/seconds)
   ```
   The **goal** is a templated regression report. It lists the failing test names (at most 8), their test-file names and the first line of each assertion message. It says that those test files are absent and asks for a fix in library code. It never names the mutated file, line or operator. After writing the series, the generator re-runs the visible remainder on `base/` and requires it to pass.

Both runs used `--n 10 --per-file 2`. Humanize stopped at 8 because only 4 of its source files are covered by tests, and each file is capped at 2.

`scripts/job_series.py validate --series prac_<repo>_<NNN> --series-root /Users/becmachlean/.claude/jobs/e65f3328/tmp/practice_series` returned **ok for all 18 series**: hidden tests fail on the start state, pass with the reference, and the visible tests pass in both states.

Kept operators:
- humanize: flip_boolop ×2, remove_conditional, off_by_one, swap_ifexp, swap_args ×2, change_return.
- tinydb: swap_args, flip_boolop, off_by_one ×3, change_return ×2, flip_binop, negate_if, flip_compare.

Hidden-failure counts range from 1 to 128. That spread is a natural difficulty signal: a single failing test is usually a narrow bug, and 100+ failures point to a hot path.

Cost: 0 tokens. About 20 s of CPU per repo for 8–10 tasks on these small suites. The cost scales with suite time × tries, and SWE-smith's ~23 min per repo is the upper reference.

## 5. Capability map: `scripts/practice/capability_map.py`

```
python scripts/practice/capability_map.py --results <job_series results.json>... \
    --series-root <practice root> [--arm off] [--threshold 0.5] [--prior 1,1] [--out map.json]
```

- **Inputs:** one or more job_series results documents (`{"series", "results":[{"arm","solved","invalid"}]}`) and each series' `practice.json` (repo, op). Rows marked `invalid` (infrastructure failures) are dropped, because they are not evidence about the model. A series without `practice.json` falls back to `prac_<repo>_<NNN>` naming with op `unknown`.
- **Model:** θ_{repo,op} | s, f ~ Beta(a0+s, b0+f), with a uniform prior by default. The tool reports the map per (repo, op) and pooled per repo (`"*"`). Each entry holds the mean, a 90% equal-tailed credible interval and **P(θ ≥ threshold)**. The math is pure Python: the regularized incomplete beta is computed by Lentz's continued fraction and quantiles by bisection, so scipy is not needed.
- **Router use (planned hook, not wired yet):** for a task in repo R, `p = map[R]["*"].p_ge_threshold`. If p < 0.2, start at the cloud rung; otherwise try local first. Use the op-level entry only when a task is classified to a bug type, which today it is not. Experiment E8 sets the keep rule: escalations fall ≥25% while solves stay ≥ A−1.
- **Promotion use:** a skill or Routine is promoted only when the Beta lower bound on held-out practice tasks is ≥ 0.9 (combination 1).
- **Later (not built):** partial pooling across repos (an empirical-Bayes prior from the pooled rate) and decay or windowing so the map tracks model upgrades. Key the map by model id, because models are replaceable.

## 6. Integration hooks (described, not implemented; existing modules untouched)

1. **Overnight driver.** A scheduler entry (launchd/cron on the always-on box) runs the following each night, and only while the box is idle and on AC power:
   - for each owner repo: `make_tasks.py --budget-s 1800 --n 10`
   - then `job_series.py run --series prac_* --arms off` with `AWOS_PROVIDER=local`
   - then `capability_map.py --out .awos/capability_map.json`

   `job_series.py` currently runs one series per invocation. A loop in the driver is enough, so no change to job_series is needed.
2. **Router read.** `kernel/routing` (today `scaffold/agent/` model routing) reads `.awos/capability_map.json` keyed by the project's repo name, with the gate described in §5.
3. **Skill promotion.** The skill store counts a skill's practice solves as strong evidence only when the hidden oracle passed.
4. **Repo cards.** The repo card records which files the tests never cover: these are the "dead files" found by the generator. That is useful sleep-time knowledge for localization.

## 7. Risks

- **Realism.** Single-site operator mutants are easier and more local than real bugs (BugPilot), and a large share are "obvious" (`return None`, swapped args). So the capability map is likely **optimistic** for real work, and it should be calibrated against real series (`real_*`) before routing on it (E8). Mitigations for later: Combine (two or three mutants per task) and an optional LM rewrite of the goal.
- **Oracle leakage.** The goal shows assertion messages that sometimes almost state the fix (`assert '-Inf' == '+Inf'`). That mirrors real bug reports, but it lowers difficulty.
- **Removed test files.** Hiding whole failing test files also removes their passing tests from the visible suite, so the agent has less regression protection. When a mutant breaks a hot path (for example 88 failures across 5 of 7 files), most of the visible suite disappears. `--max-fail-frac` limits this.
- **Coverage-bound.** Only code that the tests reach can yield tasks. A repo with weak tests yields few tasks, and those tasks are biased toward well-tested code.
- **Requirements.** The generator needs a green `tests/` suite that runs under the AWOS venv. A `test/` directory, non-pytest runners and repos that need services are not supported.
- **Overfitting signal.** If the same mutants are replayed repeatedly, the map measures memorization. Regenerate with a new seed each night and keep a held-out seed set for promotion decisions.
