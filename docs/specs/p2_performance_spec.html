1. P2.1 — Persistent Prompt Cache

1.1 Current Problem

Every execute_feature() call creates a new Planner instance → new Anthropic client → new connection. The system prompt (stable ~800 token instructions block) is sent as uncached tokens every time. At $3/MTok input (Sonnet), each plan costs ~$0.0024 just for the system prompt — which could be cached at $0.0003.

At 10 eval runs × 4 tasks each = 40 planner calls:

ScenarioCost per callTotal 40 calls
Current (no cache)~$0.005~$0.20
With ephemeral cache (5 min)~$0.0015 after first~$0.06
With persistent singleton~$0.001 (cache hit)~$0.04
💰 Expected savings: ~75% on planning costs. Low effort, high ROI.

1.2 Solution: Module-Level Planner Singleton

# In planner.py — replace per-instance client with module-level singleton import threading _planner_lock = threading.Lock() _planner_instance: "Planner | None" = None def get_planner(api_key: str | None = None) -> "Planner": """Return the module-level Planner singleton (thread-safe).""" global _planner_instance if _planner_instance is None: with _planner_lock: if _planner_instance is None: _planner_instance = Planner(api_key=api_key) return _planner_instance class Planner: def __init__(self, api_key: str | None = None): self.api_key = api_key or os.getenv("ANTHROPIC_API_KEY") if not self.api_key: raise ValueError("ANTHROPIC_API_KEY not set") self.client = Anthropic(api_key=self.api_key) self.model = "claude-sonnet-4-6" # Build cached system block ONCE at init # Anthropic caches this after the first API call self._system_instructions = self._get_system_instructions() self._system_block = { "type": "text", "text": self._system_instructions, "cache_control": {"type": "ephemeral"}, }

1.3 Cache Stability Rules

For the cache to hit, the system block must be byte-identical between calls:

  • ✅ System instructions: static string, never changes → cacheable
  • ✅ System block structure: always same JSON keys → cacheable
  • ❌ User prompt: changes every call (different goal) → NOT cached (correct)
  • ❌ codebase_context: changes per project → NOT in system block

1.4 Extended Cache with Haiku for Simple Planning

Route simple single-file tasks to Haiku for planning (12x cheaper, 80% quality):

def plan(self, goal: str, codebase_context: dict, ...) -> dict: # Route simple goals to Haiku is_simple = self._classify_goal_complexity(goal, codebase_context) model = "claude-haiku-4-5" if is_simple else self.model response = self.client.messages.create( model=model, max_tokens=1536, system=[self._system_block], # Always cached after first call messages=[{"role": "user", "content": user_prompt}], ) ... def _classify_goal_complexity(self, goal: str, ctx: dict) -> bool: """True if goal is simple enough for Haiku planning.""" goal_lower = goal.lower() simple_keywords = ["add method", "fix bug", "rename", "update", "add test", "add docstring"] complex_keywords = ["refactor", "architecture", "multi-file", "system", "integrate"] if any(k in goal_lower for k in complex_keywords): return False if any(k in goal_lower for k in simple_keywords): return True # Default: use Haiku if goal is short and no multi-file indicators return len(goal.split()) < 15 and len(ctx.get("files", [])) < 3

1.5 Worker Prompt Cache Architecture (The Real Cost Killer)

Critical insight: P2.1 only caches the Planner system prompt (~800 tokens). The Worker makes far more API calls and sends far larger prompts — the codebase context block alone can be 3,000–10,000 tokens. If that block is identical between Task 1 and Task 2 of the same feature, it should be cached too. This is where 90% of the real savings live.

Anthropic caches any prefix of the messages array that stays byte-identical between consecutive calls. The worker prompt must be structured so stable content comes first:

## Three-Block Worker Prompt Structure: messages = [ { "role": "user", "content": [ # BLOCK A — Stable (changes at most once per session) # Cached after first call. Contains: worker instructions, # output format spec, skill templates. { "type": "text", "text": WORKER_SYSTEM_INSTRUCTIONS, "cache_control": {"type": "ephemeral"}, }, # BLOCK B — Semi-stable (changes per target file, not per retry) # Cached within all retries for the same task. # Contains: file content + CodebaseIndex RAG results. { "type": "text", "text": file_and_rag_context, # built once per task "cache_control": {"type": "ephemeral"}, }, # BLOCK C — Dynamic (changes every call — no cache) # Contains: specific task action, past_critiques, session context. # This is the ONLY part that varies per retry. { "type": "text", "text": dynamic_task_context, # rebuilt per attempt }, ], } ]

Why this matters for retries: On attempt 2 of a failed task, Blocks A + B are identical to attempt 1. Only Block C changes (new critique added). Cache hits on A + B = 90% savings on those tokens across all retries.

BlockContentTokens (typical)Changes whenCache?
A — InstructionsWorker system prompt + JSON format spec + skills~600Never (session)✅ Always
B — File + RAGTarget file content + top-3 CodebaseIndex chunks1,000–4,000New task or file✅ Per-task
C — Task contextAction + past critiques + session state200–800Every retry❌ Never
💰 Full impact: 5 retries on a failed task → A+B cached 4/5 times. At 3,000 token B block on Sonnet: 4 × 3,000 × ($3 - $0.30) / 1,000,000 = $0.032 saved per complex task.

1.6 Context Token Budget (MAX_CONTEXT_TOKENS)

Hard ceiling on tokens sent in Block B. Prevents CodebaseIndex returning 15k tokens of "relevant" context that floods the cache and the model:

# In worker.py MAX_FILE_TOKENS = 2000 # Max tokens from target file content MAX_RAG_TOKENS = 1500 # Max tokens from CodebaseIndex RAG results MAX_CONTEXT_TOKENS = 4000 # Hard ceiling: Block B total def _build_file_and_rag_context( self, file_content: str, task: dict, codebase_index, ) -> str: """ Build Block B: file content + RAG results. Enforces token budget. Returns stable, cacheable string. """ # 1. File content (truncated if large) file_tokens = self._estimate_tokens(file_content) if file_tokens > MAX_FILE_TOKENS: file_section = self._get_file_context(file_content, task["action"]) else: file_section = file_content # 2. RAG results from CodebaseIndex rag_results = "" if codebase_index: rag_raw = codebase_index.query_code(task["action"], n_results=5) rag_tokens = self._estimate_tokens(rag_raw) if rag_tokens > MAX_RAG_TOKENS: # Take only top chunks that fit rag_results = self._truncate_to_tokens(rag_raw, MAX_RAG_TOKENS) else: rag_results = rag_raw # 3. Combine and enforce hard ceiling combined = f"## File: {task['file']}\n{file_section}\n\n## Related Code:\n{rag_results}" if self._estimate_tokens(combined) > MAX_CONTEXT_TOKENS: combined = self._truncate_to_tokens(combined, MAX_CONTEXT_TOKENS) return combined def _estimate_tokens(self, text: str) -> int: """Fast token estimate: words × 1.3 (good enough for budgeting).""" return int(len(text.split()) * 1.3) def _truncate_to_tokens(self, text: str, max_tokens: int) -> str: """Truncate text to fit within token budget. Truncate from the end.""" words = text.split() target_words = int(max_tokens / 1.3) if len(words) <= target_words: return text truncated = ' '.join(words[:target_words]) return truncated + "\n... [truncated to fit token budget]"

2. P2.2 — Parallel Sampling for L3+

2.1 The Agentless Insight

Key finding from Agentless research: For complex tasks, generating N independent patch candidates and selecting the best by test execution outperforms a single carefully-reasoned attempt. Diversity of approaches + objective selection = better outcome. This is how humans do code review too.

2.2 When to Use Parallel Sampling

ConditionParallel Sampling?N candidates
L1/L2 simple tasks❌ No1
L3 multi-file, first attempt✅ Yes2
L3 multi-file, retry after failure✅ Yes3
L4 architecture-level✅ Yes2
Task complexity="high"✅ Yes2

2.3 Parallel Sampling Flow

# Complexity check: is this worth sampling? ┌────────────────────────────────────┐ │ Task: complexity = "high" or L3+ │ └─────────────────┬──────────────────┘ │ Yes ▼ ┌────────────────────────────────────┐ │ Generate N candidates in parallel │ │ (ThreadPoolExecutor or asyncio) │ │ Each gets: same task + context │ │ But: temperature varied (0.3/0.7) │ └─────────────────┬──────────────────┘ │ ▼ ┌────────────────────────────────────┐ │ Validate each candidate │ │ - Apply edits (P0 JSON format) │ │ - Run syntax check │ │ - Run pytest (P1 test execution) │ └─────────────────┬──────────────────┘ │ ▼ ┌────────────────────────────────────┐ │ Score candidates: │ │ tests_passed × 0.7 + │ │ syntax_ok × 0.2 + │ │ edit_applied × 0.1 │ └─────────────────┬──────────────────┘ │ ▼ ┌────────────────────────────────────┐ │ Select best candidate │ │ Apply to file │ └────────────────────────────────────┘

2.4 Implementation

from concurrent.futures import ThreadPoolExecutor, as_completed @dataclass class PatchCandidate: edits: list[dict] new_content: str reasoning: str temperature: float test_result: TestResult | None syntax_ok: bool score: float = 0.0 def _sample_candidates( self, task: dict, file_content: str, n: int = 2, **kwargs ) -> list[PatchCandidate]: """Generate N independent patch candidates in parallel.""" def generate_one(temperature: float) -> PatchCandidate | None: try: edits, reasoning = self._execute_direct( task=task, file_content=file_content, temperature=temperature, **kwargs ) new_content, error = self._apply_edits_to_content(file_content, edits) if error: return None return PatchCandidate( edits=edits, new_content=new_content, reasoning=reasoning, temperature=temperature, test_result=None, syntax_ok=self._check_syntax(new_content), ) except Exception: return None temperatures = [0.2, 0.7] if n == 2 else [0.2, 0.5, 0.8] candidates = [] with ThreadPoolExecutor(max_workers=n) as executor: futures = {executor.submit(generate_one, t): t for t in temperatures[:n]} for future in as_completed(futures): result = future.result() if result is not None: candidates.append(result) return candidates def _score_candidate( self, candidate: PatchCandidate, task: dict, project_root: str, ) -> float: """Score a candidate patch. Higher is better.""" score = 0.0 # Syntax check (20% weight) if candidate.syntax_ok: score += 0.2 # Edit was applied (10% weight) if candidate.new_content != "": score += 0.1 # Test execution (70% weight — the most important signal) if candidate.test_result: score += 0.7 * candidate.test_result.score candidate.score = score return score

2.5 Majority-Vote Reranking (Agentless Upgrade)

Research insight (Agentless, ICLR 2025): After test-filtering candidates, use AST-normalized majority voting — not just "highest score" — to pick the final patch. Two independently-generated patches that produce the same AST diff are stronger evidence of correctness than one high-scoring outlier. This is how Agentless achieves robustness.
import ast import difflib def _normalize_patch(self, old_content: str, new_content: str) -> str: """ Normalize patch for majority voting. Strips docstrings, normalizes whitespace, computes canonical diff. Based on Agentless patch normalization. """ def canonicalize(source: str) -> str: try: tree = ast.parse(source) # Remove docstrings (they're surface-level differences) for node in ast.walk(tree): if isinstance(node, (ast.FunctionDef, ast.AsyncFunctionDef, ast.ClassDef, ast.Module)): if (node.body and isinstance(node.body[0], ast.Expr) and isinstance(node.body[0].value, ast.Constant)): node.body.pop(0) return ast.unparse(tree) # canonical source format except SyntaxError: return source.strip() old_canon = canonicalize(old_content) new_canon = canonicalize(new_content) diff = list(difflib.unified_diff( old_canon.splitlines(), new_canon.splitlines(), lineterm="" )) return '\n'.join(diff) def _select_by_majority_vote( self, candidates: list["PatchCandidate"], original_content: str, ) -> "PatchCandidate": """ Select the best candidate using Agentless-style majority voting. 1. Normalize each patch (AST canonical form → diff) 2. Count normalized patch occurrences 3. Select the patch with highest occurrence count 4. Tiebreak: highest test score """ # First: filter to only test-passing candidates passing = [c for c in candidates if c.test_result and c.test_result.score >= 1.0] pool = passing if passing else candidates # fallback to all if none pass if not pool: return candidates[0] if candidates else None # Normalize each candidate norm_map: dict[str, list["PatchCandidate"]] = {} for c in pool: key = self._normalize_patch(original_content, c.new_content) if key not in norm_map: norm_map[key] = [] norm_map[key].append(c) # Majority vote: largest group wins best_group = max(norm_map.values(), key=lambda g: (len(g), max(c.score for c in g))) # Tiebreak within group: highest test score return max(best_group, key=lambda c: c.score)

2.6 Updated execute_with_sampling() using Majority Vote

def execute_with_sampling( self, task: dict, file_content: str, n_samples: int = 3 ) -> dict: """ Agentless-style: sample N → test filter → majority vote. Gate: AWOS_PARALLEL_SAMPLING=true and task.complexity >= 5 """ # 1. Sample N candidates in parallel candidates = self._sample_candidates(task, file_content, n_samples) if not candidates: return self.execute_task(task, file_content) # fallback # 2. Filter by test results (already done inside _sample_candidates scoring) # 3. Majority vote reranking best = self._select_by_majority_vote(candidates, file_content) return { "edits": best.edits, "new_content": best.new_content, "score": best.score, "test_result": best.test_result, "n_candidates": len(candidates), "method": "parallel_sampling_majority_vote", }

3. P2.3 — Git Worktree Isolation

3.1 Why Worktrees

Git worktrees allow multiple working directories from the same repository. Each directory is fully independent but shares git history. This enables:

  • Safe parallel execution: Two parallel sampling attempts don't conflict
  • Easy rollback: Failed feature? Just remove the worktree
  • Clean diffs: git diff between worktree and main branch shows exactly what changed
  • No dirty main: Main working directory stays clean during agent runs

3.2 Worktree Lifecycle

class WorktreeManager: def __init__(self, repo_root: str): self.repo_root = repo_root self.worktrees: dict[str, str] = {} # feature_id → worktree_path def create_worktree(self, feature_id: str) -> str: """Create a git worktree for a feature execution.""" # Sanitize feature_id for use as branch name branch_name = f"awos/feature/{feature_id[:20].replace(' ', '-')}" worktree_path = Path(self.repo_root) / ".awos" / "worktrees" / feature_id # Create new branch + worktree subprocess.run([ "git", "worktree", "add", "-b", branch_name, str(worktree_path), "HEAD", ], cwd=self.repo_root, check=True) self.worktrees[feature_id] = str(worktree_path) return str(worktree_path) def get_diff(self, feature_id: str) -> str: """Get the diff of all changes made in this worktree.""" worktree_path = self.worktrees[feature_id] result = subprocess.run( ["git", "diff", "HEAD"], capture_output=True, text=True, cwd=worktree_path, ) return result.stdout def commit_worktree(self, feature_id: str, message: str) -> str: """Commit changes in worktree. Returns commit hash.""" worktree_path = self.worktrees[feature_id] subprocess.run(["git", "add", "-A"], cwd=worktree_path, check=True) subprocess.run(["git", "commit", "-m", message], cwd=worktree_path, check=True) result = subprocess.run( ["git", "rev-parse", "HEAD"], capture_output=True, text=True, cwd=worktree_path, ) return result.stdout.strip() def merge_to_main(self, feature_id: str) -> bool: """Merge worktree branch to current branch.""" branch = f"awos/feature/{feature_id[:20].replace(' ', '-')}" result = subprocess.run( ["git", "merge", branch, "--no-ff", "-m", f"Merge AWOS feature: {feature_id}"], capture_output=True, text=True, cwd=self.repo_root, ) return result.returncode == 0 def cleanup_worktree(self, feature_id: str) -> None: """Remove worktree and its branch.""" if feature_id not in self.worktrees: return worktree_path = self.worktrees[feature_id] branch = f"awos/feature/{feature_id[:20].replace(' ', '-')}" subprocess.run( ["git", "worktree", "remove", "--force", worktree_path], cwd=self.repo_root ) subprocess.run( ["git", "branch", "-D", branch], cwd=self.repo_root ) del self.worktrees[feature_id]

3.3 Integration into Orchestrator

def execute_feature(self, goal: str, codebase_context: dict, ...) -> dict: use_worktree = os.getenv("AWOS_USE_WORKTREE", "false").lower() == "true" if use_worktree: feature_id = hashlib.md5(goal.encode()).hexdigest()[:8] wm = WorktreeManager(self.project_root) worktree_path = wm.create_worktree(feature_id) try: # Run all tasks in worktree result = self._execute_feature_in_path( goal=goal, working_dir=worktree_path, codebase_context=codebase_context, ) if result["success"]: diff = wm.get_diff(feature_id) result["diff"] = diff wm.commit_worktree(feature_id, f"AWOS: {goal[:80]}") # Optionally merge: wm.merge_to_main(feature_id) finally: wm.cleanup_worktree(feature_id) return result else: return self._execute_feature_in_path(goal, self.project_root, codebase_context)

3.4 Worktree + Parallel Sampling Together

For parallel sampling (P2.2), each candidate gets its own worktree:

# Each candidate runs in its own worktree worktrees = [] for i, temperature in enumerate(temperatures): wt_path = wm.create_worktree(f"{feature_id}_candidate_{i}") worktrees.append(wt_path) # Run candidates in parallel, each in own worktree with ThreadPoolExecutor(max_workers=len(temperatures)) as executor: futures = [ executor.submit(generate_and_test, task, worktree_path) for worktree_path in worktrees ] candidates = [f.result() for f in futures] # Select best, apply to main worktree best = max(candidates, key=lambda c: c.score) # Cleanup losers for i, wt in enumerate(worktrees): if candidates[i] != best: wm.cleanup_worktree(f"{feature_id}_candidate_{i}")

4. P2.4 — Condensed History (ACI-style)

4.1 The SWE-Agent Insight

SWE-Agent keeps only the last 5 steps condensed in context. This forces the model to work from current state, not from accumulating history. For AWOS: keep only last N task summaries, not full task bodies.

4.2 Current vs New Context Structure

ItemCurrent AWOSNew (ACI-style)
Task 1 resultFull 500-word description2-line summary: "Added snapshot() to ToolPerformanceTracker in tool_performance.py"
Task 2 resultFull description + code snippet2-line summary + key symbols only
Task 3+ resultCumulative full contextCompressed to bullet points after N=3
Token cost~600 tokens/task (grows unbounded)~50 tokens/task (capped)

4.3 Implementation

MAX_TASK_HISTORY = 3 # Show full summaries for last 3 tasks SUMMARY_TOKENS_CAP = 600 # Maximum tokens for all task history def _build_task_history_context( self, completed_tasks: list[TaskSummary], current_task_index: int, ) -> str: """Build compact task history for injection into worker prompt.""" if not completed_tasks: return "" # Last MAX_TASK_HISTORY tasks: show full summary recent = completed_tasks[-MAX_TASK_HISTORY:] # Older tasks: compress to one line each older = completed_tasks[:-MAX_TASK_HISTORY] lines = ["## Previous Task Results (session context):"] # Older tasks — very compressed if older: lines.append(f"Earlier: {len(older)} tasks completed in: {', '.join(set(t.file for t in older))}") # Recent tasks — more detail for task in recent: icon = "✅" if task.status == "completed" else "❌" lines.append(f"{icon} [{task.task_id}] {task.key_change}") if task.new_symbols: lines.append(f" → New: {', '.join(task.new_symbols)}") return '\n'.join(lines)
