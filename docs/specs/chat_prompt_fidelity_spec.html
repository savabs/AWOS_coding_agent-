Spec: Chat Prompt Fidelity

Status: active · Phase: 1 · Date: 2026-07-27

Goal

Make each Electron chat turn faithfully traceable from the exact user input through the provider request to the rendered response, while restoring intended conversation history for the OpenCode Go path.

Governing research: chat_prompt_fidelity.html
Task file: chat_prompt_fidelity.html

Implementation steps

Step 1 — Define structured prompt-trace metadata.

Add a bounded, secret-safe metadata shape for raw input, mode, provider/model, prior-turn count, and prompt/context estimates. Do not include hidden chain-of-thought or credentials.

Exit: Unit test accepts the trace schema and rejects secret-like values.

Step 2 — Preserve the exact raw user message.

Ensure the stored and rendered user message uses the submitted text without semantic normalization. Keep Markdown escaping limited to display formatting.

Exit: A test using the moat prompt finds the exact string in the saved user message and rendered source contract.

Step 3 — Restore OpenCode conversation history.

Use the existing session-message builder for the OpenCode Go request so prior user/assistant turns are included before the current provider prompt.

Exit: A mocked OpenCode request contains the system message, prior turns, and current user prompt in order.

Step 4 — Emit prompt-trace metadata.

Attach the structured trace to the completed chat response and persisted assistant metadata. Redact secret-like values and cap text sizes.

Exit: The response metadata contains provider, mode, history count, and bounded context information without API keys or hidden reasoning.

Step 5 — Render a collapsed developer trace.

Add a low-noise “What AWOS sent” disclosure to assistant messages. Keep the exact user message visually distinct from provider trace and model response.

Exit: UI source/DOM contract exposes separate raw-input and prompt-trace regions; default view remains programmer-oriented.

Step 6 — Add ambiguity handling contract.

When the system detects an uncertain reinterpretation, label it as an assumption or ask for clarification; never present an altered request as the user's original text.

Exit: Regression test verifies the moat prompt is not rewritten in the raw-input or trace fields.

Step 7 — Run live Electron proof.

Use the Electron app to submit the moat prompt and inspect the raw message, trace, provider, and rendered answer.

Exit: The live record and UI show matching raw input and an inspectable provider trace.

Edge cases

  • Empty input is rejected before a provider request.
  • First turn has zero prior messages and remains valid.
  • Multiple turns preserve order and cap context safely.
  • Provider failure still preserves the raw user message and failure metadata.
  • Secret-like prompt/context values are redacted from the developer trace.
  • Markdown characters in user input cannot create HTML injection.
