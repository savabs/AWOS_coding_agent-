Spec: Typed Execution Graph

Phase: 1 · Status: active · Date: 2026-08-02

Goal: create a deterministic, provider-free graph contract where typed nodes represent edits, tests, barriers, and recovery operations and safe ready nodes can be grouped into parallel waves.

Research: execution_graph.html · Task: execution_graph_task.html

Files affected

  • scaffold/agent/execution_graph.py — new graph contract.
  • tests/test_execution_graph.py — provider-free tests.

Production orchestrator wiring is explicitly out of scope for this first contract slice.

Atomic steps

1. Define typed nodes.

Support explore, edit, test, barrier, review, recovery, and final_verify nodes with dependencies, files, acceptance, status, retries, and evidence.

2. Validate graph structure.

Reject duplicate IDs, unknown dependencies, invalid types, and cycles.

3. Calculate ready waves.

Release only pending nodes whose dependencies completed; serialize same-file writes and preserve deterministic order.

4. Add recovery nodes.

Insert bounded, acyclic recovery nodes after failures.

5. Test and prove.

Run python3 -m pytest tests/test_execution_graph.py -q without credentials or network access.

Edge cases

  • Empty graph
  • Duplicate ID
  • Unknown dependency
  • Cycle
  • Failed prerequisite
  • Same-file conflict
  • Required test barrier
  • Malformed JSON
