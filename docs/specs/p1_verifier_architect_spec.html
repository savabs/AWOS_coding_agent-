1. P1.1 — Test Execution Verifier

1.1 Why This Matters

The ground truth problem: AWOS currently verifies code correctness with LLM self-evaluation — asking the model "does this look correct?". Every SOTA agent that scores above 50% on SWE-bench uses test execution as the objective verifier. LLM self-eval is wrong ~30% of the time. Tests are wrong ~2% of the time.

Research basis:

  • Agentless: generates N patches, selects by test pass rate — achieves competitive scores with no ReAct loop
  • SWE-Agent: runs python -m pytest after every edit, uses output as next-turn context
  • Claude Code: bash tool executes tests freely; agent loops until tests pass

1.2 Design: Two-Stage Verification

Stage 1 — Syntax + Static (current, keep)
  • ast.parse() — catches syntax errors instantly, free
  • _check_imports() — verifies imports exist
  • If Stage 1 fails → immediate retry with error, no test execution
Stage 2 — Test Execution (NEW)
  • Run pytest <test_file> -x -q --tb=short --timeout=30
  • Capture stdout/stderr
  • Parse: passed count, failed count, error messages
  • Return structured TestResult

1.3 Test File Discovery

Given a task's target file, find the most relevant test file:

def _discover_test_file(self, target_file: str, project_root: str) -> str | None: """ Find the test file for a given source file. Discovery order: 1. tests/test_{basename}.py (e.g., tests/test_worker.py for scaffold/agent/worker.py) 2. tests/{basename}_test.py 3. test_{basename}.py (same directory) 4. Grep for 'import {module_name}' in tests/ directory 5. None if not found """ basename = Path(target_file).stem # 'worker' from 'scaffold/agent/worker.py' module_name = basename candidates = [ Path(project_root) / "tests" / f"test_{basename}.py", Path(project_root) / "tests" / f"{basename}_test.py", Path(target_file).parent / f"test_{basename}.py", Path(project_root) / "scaffold" / "tests" / f"test_{basename}.py", ] for candidate in candidates: if candidate.exists(): return str(candidate) # Grep fallback return self._grep_for_test_file(project_root, module_name)

1.4 TestResult Dataclass

@dataclass class TestResult: ran: bool # Whether test execution was attempted passed: int # Number of tests passed failed: int # Number of tests failed errors: int # Number of test errors (not failures) test_file: str | None # Which test file was run output: str # Full pytest output (truncated to 2000 chars) duration_seconds: float timed_out: bool = False error_message: str = "" # If execution itself failed (not test failure) @property def all_passed(self) -> bool: return self.ran and self.failed == 0 and self.errors == 0 @property def score(self) -> float: """0.0 to 1.0 — fraction of tests passing.""" total = self.passed + self.failed + self.errors return self.passed / total if total > 0 else 0.0

1.5 Run Tests Method

def run_tests(self, target_file: str, project_root: str) -> TestResult: """Run pytest for the given target file. Returns TestResult.""" test_file = self._discover_test_file(target_file, project_root) if test_file is None: return TestResult( ran=False, passed=0, failed=0, errors=0, test_file=None, output="No test file found", duration_seconds=0.0 ) start = time.time() try: result = subprocess.run( ["python", "-m", "pytest", test_file, "-x", "-q", "--tb=short", "--timeout=30", "--no-header", "-rN"], capture_output=True, text=True, timeout=60, # Hard timeout for whole test run cwd=project_root, ) duration = time.time() - start output = result.stdout + result.stderr # Parse pytest output passed, failed, errors = self._parse_pytest_output(output) return TestResult( ran=True, passed=passed, failed=failed, errors=errors, test_file=test_file, output=output[-2000:], # Truncate, keep tail (failures are at end) duration_seconds=duration, ) except subprocess.TimeoutExpired: return TestResult( ran=True, passed=0, failed=0, errors=0, test_file=test_file, output="Test execution timed out (60s)", duration_seconds=60.0, timed_out=True, )

1.6 Integration into Orchestrator Retry Loop

After each worker attempt, the orchestrator gets a TestResult and decides:

# In _execute_single_task(): # After verifier passes syntax check: test_result = verifier.run_tests(task["file"], project_root) if test_result.ran and not test_result.all_passed: # Tests failed — inject test output as feedback for retry task["past_critiques"] = task.get("past_critiques", []) + [ f"[TEST FAILURE on attempt {attempt}]\n" f"Tests run: {test_result.passed + test_result.failed}\n" f"Failed: {test_result.failed}\n" f"Output:\n{test_result.output}" ] # Continue to retry loop elif test_result.all_passed: # Tests pass — mark as definitively successful result["test_verified"] = True result["test_score"] = test_result.score

1.7 Scoring Integration

Tests provide a more objective score than the current LLM-based scoring:

ConditionScore Contribution
Tests found + all pass+30 points (high confidence)
Tests found + some pass+10 to +25 points (proportional)
Tests found + all fail-20 points
Tests not found0 (no change to existing scoring)
Test execution error0 (don't penalize for infra issues)

2. P1.2 — Architect+Editor Split

2.1 Why Two Calls Are Better Than One

Current: Single LLM call

One model must simultaneously:

  • Understand the task deeply
  • Navigate the codebase
  • Plan the implementation
  • Write exact JSON/SEARCH blocks
  • Get whitespace exactly right

Conflicting demands → reasoning and editing quality both suffer.

New: Architect + Editor

Architect (Sonnet/DeepSeek-R1):

  • Understands task + context
  • Plans implementation in plain English
  • Specifies exactly WHAT to change

Editor (Haiku/DeepSeek-chat):

  • Receives architect's plain text plan
  • Only produces the JSON edit
  • No reasoning needed — just transcription
Cost analysis: Architect (Sonnet ~3k tokens) + Editor (Haiku ~1k tokens) = ~$0.010 + ~$0.001 = $0.011 vs current single Sonnet call ($0.015). Cheaper AND better quality.

2.2 Architect Prompt

ARCHITECT PROMPT: ================ You are a senior software architect. Analyze this coding task and produce a detailed implementation plan in plain English. TASK: {task["action"]} FILE: {task["file"]} COMPLEXITY: {task["complexity"]} FILE CONTEXT: {display_context} {cross_file_context} INSTRUCTIONS: 1. Identify exactly WHERE in the file the change should be made (line reference, function name, class name) 2. Describe WHAT new code should be added or modified 3. Specify the exact string that CURRENTLY exists that needs to change (quote it) 4. Specify what it should become 5. If multiple locations need changes, list each one Be specific. The editor needs exact quotes from the file to make the edit. Do NOT write code. Write instructions. OUTPUT FORMAT: ### Analysis [Your understanding of what needs to change] ### Changes Required Change 1: - Location: [class/method/line description] - Currently: `[exact quote from file]` - Change to: [description of new code] - Reason: [why this change] Change 2: [if needed] ...

2.3 Editor Prompt

EDITOR PROMPT: ============== You are a precise code editor. Convert the architect's instructions into exact JSON edits. ARCHITECT INSTRUCTIONS: {architect_output} FILE CONTENT: {full_file_content} OUTPUT RULES: - Respond ONLY with valid JSON, no other text - Each old_string MUST be an exact substring of the file content above - Include 2-3 lines of context around each change to ensure uniqueness { "edits": [ { "old_string": "exact text from file", "new_string": "replacement text" } ] }

2.4 Implementation in worker.py

def execute_task(self, task, file_content, ..., use_architect_split=True): if use_architect_split and task.get("complexity", "medium") in ("medium", "high"): return self._execute_with_architect_split(task, file_content, ...) else: return self._execute_direct(task, file_content, ...) def _execute_with_architect_split(self, task, file_content, ...): # Step 1: Architect call architect_prompt = self._build_architect_prompt(task, file_content, ...) architect_response = self._call_llm( prompt=architect_prompt, model=self.architect_model, # Sonnet or DeepSeek-R1 max_tokens=2048, ) # Step 2: Editor call (cheaper model) editor_prompt = self._build_editor_prompt( architect_output=architect_response, full_content=file_content, ) editor_response = self._call_llm( prompt=editor_prompt, model=self.editor_model, # Haiku or DeepSeek-chat max_tokens=1024, ) # Step 3: Parse JSON from editor response edits = self._parse_json_edits(editor_response) return {"edits": edits, "architect_reasoning": architect_response}

3. P1.3 — Auto Context Compaction

3.1 Problem

For features requiring 5+ tasks (L3/L4), the orchestrator passes increasingly large _applied_context dictionaries. By task 4, the context includes the full description of tasks 1, 2, and 3 — most of which is no longer relevant. This wastes tokens and can confuse the model.

Claude Code solves this with AutoCompact: a full LLM summarization when context approaches the limit. AWOS needs a lighter version: structured session state that grows predictably.

3.2 Session State Structure

@dataclass class TaskSummary: task_id: int action: str # Original action description file: str # Modified file status: str # "completed" | "failed" | "skipped" new_symbols: list[str] # New functions/classes added (e.g. ["snapshot", "ToolPerformanceTracker.snapshot"]) key_change: str # One-line description of what changed test_result: str | None # "passed" | "failed" | None @dataclass class SessionState: feature_goal: str # Original user goal completed_tasks: list[TaskSummary] modified_files: list[str] # All files changed so far current_task_index: int total_tasks: int compact_summary: str = "" # LLM-generated if too many tasks def to_context_block(self) -> str: """Generate the context block injected into each task's prompt.""" ...

3.3 Context Block Generation

def to_context_block(self) -> str: """Generate compact context for injection into task prompts.""" if len(self.completed_tasks) == 0: return "" lines = [ f"## Session Context (Feature: {self.feature_goal})", f"Progress: Task {self.current_task_index}/{self.total_tasks}", "", "### Completed Tasks:", ] for t in self.completed_tasks: status_icon = "✅" if t.status == "completed" else "❌" lines.append(f"{status_icon} Task {t.task_id}: {t.action}") lines.append(f" File: {t.file} | Change: {t.key_change}") if t.new_symbols: lines.append(f" New symbols: {', '.join(t.new_symbols)}") lines.append("") lines.append(f"### Modified Files: {', '.join(self.modified_files)}") return '\n'.join(lines)

3.4 Compaction Trigger

When the context block exceeds 800 tokens (approximately 8+ tasks), trigger an LLM-based compression:

MAX_CONTEXT_TOKENS = 800 def maybe_compact(self, cheap_llm_caller) -> None: """Compress context if too large.""" context = self.to_context_block() estimated_tokens = len(context.split()) * 1.3 # Rough estimate if estimated_tokens > MAX_CONTEXT_TOKENS: compact_prompt = f""" Summarize these completed coding tasks in 3-5 bullet points. Focus on: what was added, which files were modified, key new symbols created. Be very concise — this will be shown to an LLM for context. Tasks completed: {context} Summary (3-5 bullet points, max 200 words):""" self.compact_summary = cheap_llm_caller(compact_prompt, max_tokens=250) # Clear detailed tasks, keep only compact summary self.completed_tasks = []

3.5 Integration into Orchestrator

# In Orchestrator._execute_feature(): session_state = SessionState( feature_goal=goal, completed_tasks=[], modified_files=[], current_task_index=0, total_tasks=len(tasks), ) for i, task in enumerate(tasks): session_state.current_task_index = i + 1 # Inject session context into task task["session_context"] = session_state.to_context_block() # Execute task result = self._execute_single_task(task, ...) # Update session state if result["success"]: summary = TaskSummary( task_id=task["task_id"], action=task["action"], file=task["file"], status="completed", new_symbols=self._extract_new_symbols(result["patch"]), key_change=result.get("summary", task["action"][:80]), test_result=result.get("test_result"), ) session_state.completed_tasks.append(summary) if task["file"] not in session_state.modified_files: session_state.modified_files.append(task["file"]) # Maybe compact if too many tasks session_state.maybe_compact(self._cheap_call)

3.6 New Symbol Extraction

Parse the diff/edit result to find new function/class names added:

def _extract_new_symbols(self, new_content: str, old_content: str) -> list[str]: """Find new function/class definitions added in new_content vs old_content.""" import ast def get_symbols(code: str) -> set[str]: try: tree = ast.parse(code) symbols = set() for node in ast.walk(tree): if isinstance(node, (ast.FunctionDef, ast.AsyncFunctionDef, ast.ClassDef)): symbols.add(node.name) return symbols except SyntaxError: return set() old_symbols = get_symbols(old_content) new_symbols = get_symbols(new_content) return list(new_symbols - old_symbols)

5. Risks & Mitigations

RiskLikelihoodMitigation
Test execution adds latency per taskHighCap test timeout at 30s; make test discovery optional via flag; only run if test file found
Architect output is too verbose for editorMediumLimit architect to 2048 tokens; if editor fails to parse, fall back to direct edit
Cheap editor model produces wrong old_stringMediumFull JSON validation + nearest-match feedback from P0; retry with architect model if editor fails
Session compaction loses important contextLowOnly compact when >800 tokens; keep symbol list and modified files even after compaction
