Atomic implementation steps

1. Create session skill.
It must direct the agent to run python3 scripts/session_warmup.py, manually resolve stale warmup ordering, read canonical state, and declare session state.
Verify: frontmatter parser and content checks find all required references.
2. Create change-gate skill.
It must enforce research → spec → task before non-trivial implementation and identify the governing task/spec before edits.
Verify: content check contains the three artifact classes and implementation prohibition.
3. Create evaluation skill.
It must use evaluator-owned acceptance/safety/truthfulness gates, keep live runs opt-in, and report failed tests honestly.
Verify: content check names evaluation_v1, hard success formula, and offline default.
4. Create debug/safety skill.
It must apply the two-failed-attempt rule, use explicit hypotheses, and require sandbox/security checks for execution changes.
Verify: content check names debug protocol, hypothesis/disconfirmation, and security protocol.
5. Add inventory.
Document scope, invocation triggers, trust requirement, and canonical owners.
Verify: README lists exactly four skills.
6. Validate.
Run filesystem/frontmatter/line-limit checks, focused evaluator tests, and Obsidian lint.
Verify: every command result is recorded in the task/checkpoint.

Non-goals

  • No global skill installation.
  • No Zed settings modification or runtime agent code changes.
  • No remote skill registry or unreviewed downloaded skill.
  • No claim that skills make the coding agent fully Cursor/Hermes-equivalent.
