Spec: ReflexionMemory — Phase 5B

phase-5b error-pattern-store critique-injection Ready to Implement 2026-05-19

Goal

Upgrade AWOS from static rule-based retry hints to adaptive verbal critique memory. After every failure, generate a task-specific verbal critique using a cheap LLM, persist it cross-session, and inject relevant past critiques into retry prompts — preventing the same mistake from repeating.

Research basis: Reflexion (NeurIPS 2023) — verbal critique memory improves HumanEval pass@1 from 80% to 91% without weight updates. Self-Refine (NeurIPS 2023) — localised + actionable feedback achieves 5-20% code task improvement. Full research: reflexion_memory.html

Interface Contract

ErrorPattern dataclass

@dataclass
class ErrorPattern:
    task_id:    str   # task["task_id"]
    file_path:  str   # relative path, e.g. "api/users.py"
    error_type: str   # ErrorClass.name, e.g. "SYNTAX_ERROR"
    error_msg:  str   # raw error string, truncated to 300 chars
    critique:   str   # LLM-generated verbal critique, 1-3 sentences
    timestamp:  str   # ISO 8601, e.g. "2026-05-19T08:31:00Z"

ErrorPatternStore public API

class ErrorPatternStore:
    def __init__(self, store_path: str = ".awos/error_patterns.jsonl"): ...

    def save(self, pattern: ErrorPattern) -> None:
        """Append pattern to JSONL store. Thread-safe (file lock)."""

    def retrieve(
        self,
        file_path: str,
        error_type: str,
        top_n: int = 3
    ) -> list[ErrorPattern]:
        """Return top_n most recent patterns matching file_path + error_type."""

    def summary(self) -> dict:
        """Return {total: int, by_type: dict, by_file: dict}."""

Edge Cases

CaseBehaviour
No past critiques for this file/error_typetask["past_critiques"] = []. Worker prompt unchanged.
LLM critique call fails / times outLog warning. critique = "". No save() call. Static hint still injected.
Store file does not existsave() creates it. retrieve() returns [].
Critique is very long (model ignores max_tokens)Truncate to 400 chars before injection.
Multiple failures on same file (hundreds of critiques)retrieve() returns only top_n=3 most recent. No performance issue.
Concurrent Orchestrator instancesFile lock on append. No corruption.

Design Decisions

Decision 1: JSONL over SQLite. Consistent with RewardStore (JSONL). Zero dependencies. Human-readable. append-only = no corruption on crash.
Decision 2: Exact match retrieval (file_path + error_type) over vector search. Sufficient for Phase 5B. Vector search deferred to Phase 6 when we have 500+ critiques to justify ChromaDB overhead.
Decision 3: Critique generated after failure, stored, then retrieved on the next attempt (not the same attempt). This avoids adding latency to the current retry and matches Reflexion paper's architecture.
Cost guard: generate_critique() is only called after worker failure (attempt > 1 threshold configurable). At 500 failures/month @ /usr/bin/bash.0001 each = /usr/bin/bash.05/month. Negligible.
