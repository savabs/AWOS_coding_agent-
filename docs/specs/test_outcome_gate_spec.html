Spec: Test Outcome Gate

phase/1 · topic/coding-agent-reliability · active · 2026-07-29

Goal

Make both AWOS execution paths report failure and restore changed files whenever an executed test suite has failures, errors, or a timeout, while preserving explicit syntax-only behavior when no tests are found.

Exit condition: focused outcome-gate tests pass, the existing E2E tests remain green, and the proof command shows failed-test rollback plus passing-test completion.

Atomic implementation steps

Step 1 — Add the legacy test-failure regression.

Run a real legacy Worker → Verifier orchestration against a temporary pytest repository where the valid patch intentionally fails a test.

Exit: the test initially fails against the current implementation, and the test specifies returned failure, failed execution log, and restored source.

Step 2 — Add the ReAct test-failure regression.

Feed the ReAct orchestration a deterministic successful edit plus a failed TestResult, then assert the final task outcome and rollback contract.

Exit: the regression isolates the ReAct bookkeeping path without a live model call.

Step 3 — Gate legacy completion on test evidence.

In _execute_single_task(), compute a task-level outcome after TestRunner. Only record completion, modified files, and successful task evidence when verification passed and any discovered tests passed.

Exit: the legacy failure regression passes and the existing minimal E2E remains green.

Step 4 — Gate ReAct completion on test evidence.

In _execute_task_via_react(), defer completion bookkeeping until after the worker’s test result is consumed. Roll back every reported changed file on test failure.

Exit: the ReAct failure regression passes and no failed run is logged as completed.

Step 5 — Add the human-readable proof guide.

Document one focused pytest command and the exact markers proving a passing edit completes and a failing edit rolls back.

Exit: the proof guide references an executed command and observable output.

Outcome contract

  • Success: verification succeeds and either no tests are found or every discovered test passes without timeout.
  • Failure: worker/verifier fails, or a discovered test has failures, errors, or timeout. Changed files are restored.
  • Evidence: returned result, execution log, live task event, debug evidence, reward success, and performance success agree.

Edge cases

  • No tests found: preserve syntax-only success but retain no_tests_found evidence.
  • Test collection error: fail and roll back because the test command did not establish correctness.
  • Timeout: fail and roll back.
  • Multiple ReAct files: restore every path reported in files_changed.
  • Verifier failure before testing: preserve existing verifier rollback behavior.
