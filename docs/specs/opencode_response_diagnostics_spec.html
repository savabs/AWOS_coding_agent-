Spec: OpenCode Go Response Diagnostics

phase/1 · topic/provider-routing · active · 2026-07-31

Goal

Make planner response failures distinguishable and safely testable without changing the fixed OpenCode Go endpoint, model, prompt contract, or live-trial budget.

Governing documents

Research · Task

Allowed files

  • scaffold/agent/cheap_planner.py
  • tests/test_fixed_opencode_go_agent.py
  • the three provider-response research/spec/task artifacts

Atomic steps

Step 1 — Add a response-shape classifier.

Classify a completion message as content-present, reasoning-only, tool-call-only, empty, or unavailable using structural metadata only.

Exit: mocked response-shape tests distinguish all five cases.

Step 2 — Include bounded structural diagnostics in planner errors.

Attach provider/model and response-shape metadata to malformed-response errors without logging secrets or full response content.

Exit: malformed, reasoning-only, and empty responses produce bounded actionable errors.

Step 3 — Preserve valid JSON parsing behavior.

Keep ordinary JSON content parsing and markdown-fence handling unchanged.

Exit: existing fixed-provider tests and a valid JSON regression pass.

Step 4 — Run offline validation.

Run the fixed-provider suite and diagnostics on the changed planner file.

Exit: tests pass and no new diagnostics are introduced.

Step 5 — Request non-thinking JSON output.

Pass the documented OpenAI-compatible extra_body thinking toggle with type disabled and response_format JSON mode for the one-turn planner request. Do not change endpoint, model, or budget.

Exit: request-shape tests assert both fields and omit temperature.

Edge cases

  • Content is None while reasoning content exists.
  • Content is empty and no auxiliary fields exist.
  • Tool calls exist without content.
  • The fake response omits usage or message fields.
  • Provider exception occurs before a response object exists.
