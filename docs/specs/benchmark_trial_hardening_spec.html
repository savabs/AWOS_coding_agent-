Spec: Benchmark Trial Hardening

Goal: ensure benchmark trials leave no generated test state in the candidate workspace and execute only the bounded task surface.

Atomic steps

  1. Isolate pytest cache state. Add -p no:cacheprovider to pytest commands and provide benchmark subprocesses with a temporary home/cache directory outside the workspace. Exit: a real temporary test command leaves no .pytest_cache, .hypothesis, or __pycache__ in the workspace.
  2. Bound benchmark planning. When Benchmark mode receives exactly one allowed implementation path, collapse planner output to one executable task targeting that path. Exit: the SQLFluff fixture produces one task and Build mode retains multiple tasks.
  3. Run focused regressions. Exit: the prescribed focused suite passes and no new workspace artifacts are created by the cache-isolation test.

Edge cases

  • Requested test paths still execute directly.
  • Existing explicit interpreter propagation remains intact.
  • Unknown or multi-path benchmark plans fail closed rather than silently broadening scope.
