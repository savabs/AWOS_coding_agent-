Spec: Routing Learning System Repair

doc/spec phase/4 topic/routing 2026-07-09

Goal

Fix three bugs that prevent AWOS's LinUCB contextual bandit from learning — weight persistence, ReplayGate over-filtering, and missing warm-start — so the routing system measurably improves over time.

Files Affected

FileChanges
scaffold/agent/ml_router.pyWeight versioning (save/load), warm_start method, logging
scaffold/agent/reward_store.pyReplayGate adaptive threshold, weighted scoring
scaffold/agent/escalation_engine.pyrouting_status() method for observability
scaffold/agent/orchestrator.pyCall warm_start on init; log LinUCB status

Ordered Steps

1 Weight versioning — add format_version to save/load

File: scaffold/agent/ml_router.py

Change _save() to include "format_version": 2. Change _load() to:

  1. Check format_version in loaded payload
  2. If n_actions differs from self.n_actions: pad (more current actions) or truncate (fewer current actions)
  3. Pad: actions 0..stored-1 keep their learned A/b. New actions get identity A (noise) and zero b.
  4. Truncate: only keep first self.n_actions action matrices. Log which were dropped.
  5. Log exact outcome: "loaded v2: 30 updates, padded 4→6 actions"
Unit test: weights survive n_actions change (4→6, 6→4)

2 ReplayGate — adaptive threshold

File: scaffold/agent/reward_store.py

Change ReplayGate:

  1. Add _total_episodes counter to track volume
  2. Compute threshold: max(0.15, self._base_threshold - 0.01 * sqrt(self._total_episodes))
  3. Change scoring from equal weights to: score = informativeness * 0.4 + novelty * 0.2 + boundary * 0.4
  4. Log admit rate periodically (every 100 episodes)
Unit test: threshold decreases with volume; verify scoring weights

3 LinUCB warm_start from RewardStore

File: scaffold/agent/ml_router.py

Add method warm_start(reward_store, max_episodes=100) -> int:

  1. Get prioritized episodes from RewardStore (get_prioritized(max_episodes))
  2. For each episode: extract features + action_id + reward → call update()
  3. Return number of episodes replayed
  4. Skip ReplayGate — these are historical, trusted episodes
Unit test: warm_start loads from mock store, verifies _total_updates > 0

4 Wire warm_start in orchestrator

File: scaffold/agent/orchestrator.py

In Orchestrator.__init__, after creating LinUCBRouter and RewardStore:

replayed = self.ml_router.warm_start(self.reward_store, max_episodes=50)
logger.info("[orchestrator] warm-started LinUCB with %d episodes", replayed)
Unit test: orchestrator init calls warm_start

5 Add routing_status() to EscalationEngine

File: scaffold/agent/escalation_engine.py

Add routing_status() -> dict that returns:

{
  "linucb_ready": bool,
  "linucb_updates": int,
  "actions": {action_name: total_updates},
  "is_cheap_only": bool,
  "dead_providers": list[str]
}
Unit test: routing_status dict shape after known inputs

Live Proof

Demo: python scripts/demo_routing_learn.sh — simulates 200 routing decisions, verifies LinUCB activates within 20 episodes, persists weights across restarts, and shows learned action preferences.

Success markers:

  • Log line: [linucb] loaded v2: X updates, padded Y→Z actions
  • Log line: [orchestrator] warm-started LinUCB with N episodes
  • Log line: [linucb] is_ready=True after ≤20 updates
  • .awos/linucb_weights.pkl updated with format_version: 2
  • Weights file survives N_ACTIONS change test

Edge Cases

  • RewardStore empty on first run → warm_start returns 0, no crash
  • Weights file corrupted → log warning, start fresh, save corrected v2
  • n_actions < 0 or 0 → no-op (shouldn't happen, guarded by init)
  • Action ID out of bounds in warm_start → skip that episode, log warning
  • Concurrent writes to weights file → accept occasional loss (low-impact, next save overwrites)
