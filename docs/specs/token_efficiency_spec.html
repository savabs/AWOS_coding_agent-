Spec: Token Efficiency — Aider + Claude API Setup

doc/spec phase/1 topic/token-efficiency topic/aider active 2026-05-13

Governing Research

See docs/research/token_efficiency.html for full analysis of all strategies, pricing, and caching mechanics.

Objective

Install and configure Aider + Claude API in a token-optimal way, establish a token measurement baseline, and build the tooling to track and improve cost efficiency over time.

Phase 1 — Install & Configure (Steps 1.1–1.5)
Step 1.1 Install Aider and Anthropic SDK Phase 1

Install via pip in the current environment.

pip install aider-chat anthropic python-dotenv
Exit condition: aider --version returns without error. python -c "import anthropic" succeeds.
Step 1.2 Create .env with ANTHROPIC_API_KEY Phase 1

Create .env at project root. This file must never be committed (add to .gitignore).

ANTHROPIC_API_KEY=sk-ant-...
Security: verify .env is in .gitignore before proceeding.
Exit condition: python -c "from dotenv import load_dotenv; import os; load_dotenv(); print(bool(os.getenv('ANTHROPIC_API_KEY')))" prints True.
Step 1.3 Create .aider.conf.yml (token-optimal defaults) Phase 1

Create at project root. These settings apply to every Aider session in this directory.

# .aider.conf.yml — token-optimal configuration
# See docs/specs/token_efficiency_spec.html for rationale

model: claude-sonnet-4-5
weak-model: claude-haiku-3-5      # cheap model for commits + history summarization
cache-prompts: true                # enable Claude prompt caching
cache-keepalive-pings: 3           # ping every 5 min (3 times = 15 min warmth)
map-tokens: 512                    # reduced from default ~1024-2048
map-refresh: files                 # refresh map only when files change
map-multiplier-no-files: 1         # don't double map when no files in context
max-chat-history-tokens: 6144      # summarize history before it gets too large
analytics-disable: true            # no telemetry
llm-history-file: .aider.llm.history   # track all token usage for reporting
dark-mode: true
Exit condition: aider --exit shows "claude-sonnet-4-5" as main model and "prompt cache" in model info line.
Step 1.4 Create .aiderignore (lean repo map) Phase 1

Exclude documentation, HTML, and cache files from the repo map. This reduces ~500–2000 tokens per request.

# .aiderignore — excluded from Aider's repo map to save tokens
# Add these back with --read when needed for context
docs/
wiki/

*.md
__pycache__/
*.pyc
*.pyo
.git/
.aider*
node_modules/
dist/
build/
*.log
Exit condition: aider --show-repo-map --exit output does not include .html or .md files.
Step 1.5 Create CONVENTIONS.md (compressed rules for Aider) Phase 1

Aider doesn't automatically read .github/copilot-instructions.md. Create a concise CONVENTIONS.md (target: ~50–80 lines, dense) to be loaded as a read-only cached file. This file is the system prompt for every Aider session.

Content must include: AWOS workflow rules, project conventions, security checklist summary, memory protocol. Deliberately not verbose — no prose, only rules.

Load it automatically by adding to .aider.conf.yml: read: CONVENTIONS.md

Exit condition: CONVENTIONS.md < 100 lines. aider --show-prompts --exit includes CONVENTIONS.md content in system prompt. Token count of file > 1024 (minimum for caching on sonnet-4-5).
Phase 2 — Token Measurement (Steps 2.1–2.3)
Step 2.1 Create scripts/token_report.py Phase 2

Parse .aider.llm.history to extract per-request token stats and compute: total tokens, cache hit rate, estimated cost.

Output format: table per session + summary line. Accept --history FILE argument, default to .aider.llm.history.

Exit condition: python scripts/token_report.py runs without error and prints a table (even if history file is empty — should print "No history found").
Step 2.2 Create scripts/prewarm_cache.py Phase 2

Call Claude API with max_tokens=0 to write CONVENTIONS.md to cache before the first real request. Prints cache write token count from response usage.

# Usage: python scripts/prewarm_cache.py
# Run this at the start of each work session
Exit condition: Script runs, prints cache_creation_input_tokens > 0 from API response. Subsequent aider session shows cache hits on first message.
Step 2.3 Run baseline session and record token metrics Phase 2

Run one real Aider session (with --no-stream to expose cache stats). Do a representative task. Run token_report.py after. Record: total tokens, cache hit rate, estimated cost. Write to docs/memory/ as a baseline checkpoint.

Exit condition: Baseline metrics recorded in checkpoint. Cache hit rate measured. Cost per session estimated.
Phase 3 — Advanced Optimizations (Steps 3.1–3.2)
Step 3.1 Evaluate architect mode for large refactors Phase 3

Architect mode: Sonnet plans the change, Haiku writes the actual diffs. Output tokens (most expensive) are generated by Haiku at $4/MTok vs Sonnet's $15/MTok.

Test by adding to .aider.conf.yml:

architect: true
editor-model: claude-haiku-3-5

Run same task in both modes. Compare token costs and output quality.

Exit condition: Decision recorded — use architect mode for tasks above N lines of change (fill in N after experiment).
Step 3.2 Add session start alias / Makefile target Phase 3

Create a single command that: pre-warms cache, then launches Aider. Reduces friction and ensures cache is always warm.

# Makefile
dev:
    python scripts/prewarm_cache.py
    aider
Exit condition: make dev (or equivalent) pre-warms cache and starts Aider session in one command.
