Persistent Symbol Index — Spec

Goal: persistent stale-aware symbol index + hierarchical retrieval feeding the ReAct worker, grounded disk-first.

Files affected

  • scaffold/agent/symbol_index.py — persistence, line-numbered bodies, compact map.
  • scaffold/agent/index_retrieval.py — new retrieval layer (disk-grounded, bounded).
  • scaffold/agent/repo_map.py — ingest retrieval into ReAct context.
  • types/tests — new unit tests, demo, proof.

Atomic steps

  1. Extend FileSymbols with symbol_lines (name → (start,end)) recorded by both parsers.
  2. Record per-file mtime during build.
  3. Implement save()/load()/rebuild_changed() (mtime reparse + deleted-file drop, atomic JSON).
  4. Add compact_map() (bounded one-line-per-symbol) and symbol_windows().
  5. Add index_retrieval.py: resolve index entries disk-first; emit compact map + read windows; drop stale.
  6. Wire into enrich_with_repo_map.
  7. Tests + live proof.

Behavior contract

  • Index path never authoritative: every entry grounded via resolve_with_evidence before injection.
  • Rebuild only changed files; deleted files removed.
  • Map bounded (default 40 symbols); windows point to exact lines.
  • Failure to load persist → fallback to fresh build, never crash.

Live proof

Build once, verify .awos/symbol_index.json exists, second build loads from cache, modifies file → reparse happens, stale path resolves to real disk file.
