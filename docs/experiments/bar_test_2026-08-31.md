# Bar Test — pre-registration

**Written before any run. Thresholds fixed here are not to be edited after
results are seen.** If a criterion turns out to be wrong, add a dated note
saying so; do not quietly change the number.

## Why

The project's purpose is to find something revenue-earnable. In June a bar was
written (`docs/product/wedge_v1_coffee_money.md`, retired 2026-07-26, recoverable
at `f8233c9^`) defining the Cursor substitution test, and a `PILOT_PLAN.md` marked
"ready to execute this week". It was never executed, and could not have passed:
`ci_discovery` reported zero failures on every repository and the outcome gate
rolled back correct edits. Both fixed 2026-08-31 (`5f47a3c`).

This measures the harness against that bar for the first time.

## What is being tested

VISION.md claims "models are replaceable; the harness is the asset". The decisive
comparison is therefore not AWOS vs published SOTA — that would mostly measure
model quality. It is:

> **AWOS harness + model X   vs   raw single-shot model X, identical task.**

## Target

| | |
|---|---|
| Repo | `bottlepy/bottle` @ tag `0.12.18`, commit `1d531f7` |
| Runtime | CPython 3.12.14 |
| Provenance | Released third-party code. Nothing authored here. Chosen because old code on a new interpreter is the real "we upgraded and CI went red" scenario. |
| Disclosure | The checkout point was chosen by us; the failures were not. |

### Verified pristine baseline

```
22 collection errors, 0 tests execute
```

Depth confirmed by probing a throwaway copy (since deleted, so no fix leaks into
the run). The agent must rediscover all of this:

1. `inspect.getargspec` removed in 3.11 → 21 modules fail to import
2. `imp` module removed in 3.12 → `test/test_importhook.py` fails to import
3. Underneath: **23 real failures across 7 modules** — `test_stpl` (7),
   `test_sendfile` (5), `test_environ` (4), `test_wsgi` (2), `test_outputfilter`
   (2), `test_config` (2), `test_plugins` (1) — with diverse causes
   (AttributeError, KeyError, AssertionError, TemplateError, FileNotFoundError)

Three distinct layers, not one edit cascading. Full green requires real work.

## Arms

Both arms get the identical goal, repo copy, and model.

- **Arm A** — AWOS harness, unattended.
- **Arm B** — raw single-shot `claude-haiku-4-5-20251001`, same prompt.
- **Model** — `claude-haiku-4-5-20251001` for both. Deliberately the *weaker*
  model: if the harness substitutes for model strength, that is the sharpest
  possible evidence for "the harness is the asset". OpenCode Go was unavailable
  (both ladder models RegionError, account balance empty), so this is also the
  only live option.

## Grading — independent of AWOS

AWOS's own success report is **not** evidence. Grading is:

1. Run `pytest` in the resulting workspace with the target venv directly.
2. Count passed / failed / errors.
3. `git diff --stat` on the workspace.
4. **Cheating check:** assert `test/` is unmodified. Any change there is an
   automatic fail regardless of the suite result.

## Pre-registered decision rule

Let `fixed_A` / `fixed_B` = tests made to pass, graded independently.
Let `lift = fixed_A - fixed_B`.

- **STOP — thesis dead.** `lift <= 0`. The harness adds nothing to the model it
  wraps, which is the one claim the project rests on.
- **STOP — cannot do the work.** `fixed_A == 0`.
- **STOP — integrity failure.** Any file under `test/` modified in Arm A.
- **CONTINUE.** `lift > 0` **and** `fixed_A >= 10` (the June scale bar) **and**
  `test/` untouched.

## Deviation from the June bar, declared in advance

June required "≤50% token cost vs raw API for the same verified outcome". That
criterion assumed the cost advantage came from routing to a cheap model. With
both arms on the same model it cannot be met by construction — a multi-turn
harness always costs more than one single-shot call — and it measures nothing
about the harness.

It is therefore **replaced by cost-per-failure-actually-fixed, reported but not
used as a gate**. The June framing bundled two claims: "we route to a cheap
model" and "our harness is efficient". Only the second is a moat; anyone can
route to a cheap model, and that advantage evaporated the moment the cheap model
was region-blocked — which is exactly what happened on 2026-08-31.

## Power caveat

N=1 repository. This can decisively show failure. It cannot show success. A
positive result buys a larger run, never a pitch.

## Amendment — 2026-08-31, after Arm B, before Arm A

**Disclosure: Arm B had already been run when this amendment was written. Arm A
had not been run at all.** The amendment is symmetric across arms and was forced
by a measurement artifact, not by a preference for any result. Recording it here
rather than silently editing the section above is the whole point of the original
"add a dated note" clause.

### The artifact

A single collection error aborts the entire pytest run. Arm B repaired the
`getargspec` breakage — unblocking 287 tests — but left the `imp` breakage, so
the suite still aborted and the pre-registered metric "tests made to pass" read
**0**. The same run graded with `--continue-on-collection-errors` reads
**287 passed, 23 failed, 1 error**.

A metric that reports 287 as 0 is not measuring capability. Worse, it is
near-binary: any arm that fails to fix *every* import error scores zero, so both
arms could score 0 and trigger "STOP — thesis dead" for a pytest behaviour rather
than a harness property.

### Grader change

`--continue-on-collection-errors` is added to the grading invocation, applied
identically to both arms.

### Metric change

"Tests made to pass" is also a poor scale metric here, in the opposite
direction: from a baseline where nothing collects, one import fix scores 287.
That is not what the June bar meant by "10+ test failures fixed". Three numbers
are therefore reported separately:

| Metric | Meaning |
|---|---|
| `unblocked` | tests that now execute at all — dominated by the 2 import fixes, low information |
| `real_fixed` | of the 23 genuine failures underneath, how many now pass |
| `green` | suite fully passing: 0 failed, 0 errors |

**The June scale bar ("10+ failures fixed") is now assessed against `real_fixed`,
not against `unblocked`.** The decision rule is otherwise unchanged, with
`lift = real_fixed_A - real_fixed_B`.

### Arm B result under the amended grader

```
unblocked   287
real_fixed    0     (23 of 23 genuine failures remain)
green        no     (23 failed, 1 error)
test/ modified: none
2 SEARCH/REPLACE blocks, both applied
4.5s, $0.046
```

Single-shot repaired the one breakage visible at the top of the traceback and
nothing beneath it. That is the expected shape for a single call and is a fair
baseline.

## Result — 2026-08-31

### Numbers

| | Arm A (AWOS harness) | Arm B (raw single-shot) |
|---|---|---|
| `unblocked` | **0** | **287** |
| `real_fixed` (of 23) | **0** | **0** |
| `green` | no | no |
| suite at end | 22 errors, 0 tests run | 287 passed, 23 failed, 1 error |
| `test/` modified | none | none |
| files changed | none (only its own `.awos/`) | `bottle.py` |
| wall time | 248.8 s | 4.5 s |
| cost | $0.527 | $0.046 |

`lift = real_fixed_A - real_fixed_B = 0`

### Decision

**STOP.** Two pre-registered stop conditions fired independently:

- `lift <= 0` — thesis dead
- `fixed_A == 0` — cannot do the work

On the coarser `unblocked` measure the harness did not merely fail to beat the
baseline, it was beaten by it: one API call at $0.046 unblocked 287 tests; the
harness at $0.527 and 249 s unblocked none. **11x the cost, 55x the wall time,
strictly less accomplished.**

Integrity was clean in both arms — no test file was touched.

### Primary cause: the plan was never grounded in the failure output

AWOS planned six tasks:

```
fix_collections_imports        fix_itertools_filter
fix_functools_wraps            fix_pkg_resources_or_importlib
fix_httpserver_imports         fix_string_types
```

The two actual causes are `inspect.getargspec` (21 modules) and `imp` (1
module). **Not one of the six targets either.** The plan was generated from the
wording of the goal, not from running the suite, so every task was a guess about
what "fails on Python 3.12" usually means. A perfectly-executing worker would
still have fixed the wrong things.

This is architectural, not a provider artifact. `ci_discovery` can enumerate the
real failures — but `awos worker start` never consults it, and `awos fix-ci`,
which does, exits early because its parser only matches `FAILED` lines and the
repository's 22 failures are collection `ERROR`s. **The path that knows the real
failures cannot parse them; the path that runs does not ask.**

Secondary: 5 of 6 tasks ended `Exceeded max turns (12) without finish` — the
worker made real edits and reasoned correctly about them, but never converged,
so every edit was rolled back.

### The portability finding

VISION.md: *"models are replaceable; the harness is the asset."* Moving one
provider took five code fixes before a single task could execute:

1. `rich` missing from `requirements.txt` — `awos worker start` crashed on import
2. `planner`, `cheap_planner`, `goal_clarifier` hardcoded `os.getenv("OPENCODE_GO_API_KEY")` and sent that key to the new endpoint
3. `response_format={"type": "json_object"}` rejected — needs `json_schema`
4. planner `max_tokens=4096` truncated the execution graph into unparseable JSON
5. the ReAct loop treats any non-`{` reply as `finish`, so it terminated on turn 1 having taken no action

Number 5 matters most. That fallback is only safe while the *provider* forces
JSON via `response_format`. The loop's control flow depended on a provider-side
guarantee. On a provider without it, the agent stopped after one turn on every
task. The harness is not provider-agnostic; it was load-bearing on OpenCode Go's
API surface.

### A false claim on the dashboard

On an earlier run that failed outright — planning error, zero tasks, $0 spent —
the summary printed:

```
Manual dev time:  ₹1,680  (2 billable hours)
You saved:        ₹1,680.00  (100%)
```

It also reported `Model: DeepSeek V4` when configured for Haiku, and
`Routing providers: 5 (Gemini, DeepSeek, OpenAI, Haiku, Sonnet, OpenRouter)`
when `LADDER` holds two and both were unreachable. A savings figure asserted on
a run that did nothing is the same failure class as the pipeline briefs in the
previous project: the surface claiming value the measurement does not support.

### What this does not show

- **N=1.** As pre-registered, this shows failure, not the absence of capability.
- **Haiku is a weak model.** A stronger one might do better — but Arm B used the
  same model and still beat the harness, so this does not rescue the thesis.
- **Five fixes preceded the run.** Some fragility is swap artifact. The primary
  cause — planning without reading the failures — is not.

### Honest note on process

Six Arm A runs were needed. Five failed on defects listed above; one failed
because of a misconfiguration of ours (`AWOS_CHEAP_ONLY=1`, which silently routed
to `CheapPlanner` instead of the advanced `Planner` and would have been reported
as an AWOS failure had it not been caught). Each fix was made before looking at
any Arm A number, and tuning stopped at the first complete run rather than
continuing until the result improved.
