Vision and product identity

  • AWOS is a learnable operating system for autonomous work.
  • The coding agent is App #1, not the final AWOS product.
  • Reuse and improve the existing kernel; do not build a coding agent from scratch or copy Cursor, Zed, Hermes, or another codebase.
  • Quality is non-negotiable. Speed and cost are tunable only after the quality floor is protected.
  • CI repair is an optional workload/benchmark, not the project identity.
  • OpenCode Go is only the current provider. Dynamic routing is a later learnable allocation policy.
  • Exploration, verification, recovery, evidence, observable parallel work, and failure-driven learning are core capabilities.
  • The interface should be simple and programmer-oriented.

Assistant live-observer plan

  1. Define a versioned event envelope with event_id, monotonic sequence, timestamp, source, type, session/chat/task/trace IDs, payload, and visibility.
  2. Persist stable IDs and sequences in the event ledger.
  3. Emit meaningful UI actions—app/view changes, prompt submitted, session selected, approvals, task controls—without logging every keystroke.
  4. Add assistant-safe payload classification, bounds, redaction, and no hidden chain-of-thought.
  5. Add cursor-based replay for missed events.
  6. Add filtered/resumable SSE using event IDs, keepalives, retry, and Last-Event-ID.
  7. Add a current-state snapshot containing current UI action, session, plan, tools, files, verification, errors, and cursor.
  8. Add a read-only assistant adapter such as awos observe snapshot and awos observe events --follow; keep MCP optional and adapter-level.
  9. Migrate the renderer to the shared observer contract.
  10. Run a live Electron proof with the assistant listener and verify no historical-session confusion.

Why this design

SSE is appropriate for server-to-listener delivery, but it is not enough by itself. A durable ledger, cursor replay, and snapshot are required because the assistant may disconnect between turns. Correlation IDs are required to join UI actions to backend execution. Structured telemetry is the primary truth; screenshots are out of scope for the first observer.
