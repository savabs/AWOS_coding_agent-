## 1. Deep System Architecture & Data Flow

AWOS V3 is structured as a cost-contained, self-evolving system utilizing a feedback loop across execution, performance tracing, routing bandits, and code mutations.

```
       [Task Request]
             │
             ▼
    [EscalationEngine] ──◄─── [LinUCB / Performance Tracker Veto]
             │
             ├──► GEMINI_FLASH (Lite) (Router)
             ├──► DEEPSEEK (Worker)
             └──► CLAUDE_SONNET (Premium / Escalation)
             │
             ▼
     [Worker Execution]  ───►  [Regex Edit Parse]
             │                       │ (on failure)
             │                       ▼
             └──────────────►  [JSON Fallback Parse]
             │
             ▼
     [Verification Loop]
             │
             ▼
     [ObservabilityStore] ───► [.awos/spans.jsonl]
             │
             ▼
    [ReplayGate Filters] ───► [RewardStore (PER)] ───► [LinUCB Update]
```

### Module Responsibilities & Hook Sites

#### 1. Core Orchestration Loop
- **`scaffold/agent/orchestrator.py`**
  - Configures the top-level loop. Receives task requirements, instantiates the sub-agents, and initiates execution.
  - Generates `TaskSpan` instances on entry and completion, saving them using `ObservabilityStore`.
  - Instantiates `VectorMemory` and indexes the codebase.
  - Queries `VectorMemory` for past successful solutions and injects them as extra context blocks into the `Worker`'s prompt.
  - Hooks into self-learning triggers (e.g., checks if a custom helper tool is synthesized, applies prompt evolutions, and triggers scaffold mutations).

#### 2. The Worker (Edit Application & Fallbacks)
- **`scaffold/agent/worker.py`**
  - Receives the task, prompt context, and codebase vectors.
  - Uses a regex parser (`_parse_search_replace`) to parse edits.
  - **JSON Fallback Mechanism:** If regex parsing fails, it invokes `_parse_json_edits` to process structured JSON edits directly. The final code block is sent to `Verifier.verify_and_apply`, which updates the file and checks syntax.

#### 3. Escalation and Model Routing
- **`scaffold/agent/escalation_engine.py`**
  - Declares the model ladder (`LADDER`) composed of `ModelSpec` dataclasses tracking input/output pricing, failure requirements, and minimum complexity.
  - Decides whether to use the default model or escalate based on prior failures.
- **`scaffold/agent/ml_router.py`**
  - Implements a contextual bandit (`LinUCBRouter`) that estimates expected reward per model action based on a 10-dimensional task feature vector.
  - Includes an empirical veto mechanism: if a model's historic success rate for a specific task complexity is low, `ToolPerformanceTracker` vetoes the bandit selection to prevent wasting budget.

#### 4. The Self-Learning Feedback Loop
- **`scaffold/agent/prompt_evolver.py`** (OPRO Optimizer)
  - Triggers every 10 sessions. Analyzes failed vs. successful task runs, refines the worker system prompt, and saves it to `.awos/evolved_prompt.json`.
- **`scaffold/agent/live_tool_synth.py`** (Live Tool Creator)
  - Activates when a task fails 2 or more times. It reflects on the error patterns, writes a custom Python script in `.awos/tools/custom_X.py`, and hooks it into the available tool execution pipeline.
- **`scaffold/agent/scaffold_evolver.py`** (Scaffold Mutation)
  - Triggers when the overall session failure rate exceeds 40%. It patches the scaffold's own framework files, verifies the mutations with a localized test suite run, and commits or rolls them back, recording the output to `.awos/scaffold_mutations.jsonl`.

## 2. Detailed Observability Equations & Metrics

AWOS maintains continuous operational visibility using formal queueing and profiling metrics:

### Queueing Model Equations (`MM1Queue` in `scaffold/agent/core/queue_model.py`)
- **Arrival Rate ($\lambda$):** Average number of tasks arriving per unit time.
- **Service Rate ($\mu$):** Average number of tasks completed per unit time.
- **System Utilization ($\rho$):** $\rho = \frac{\lambda}{\mu}$. If $\rho \geq 0.80$, a critical saturation warning is logged. The system is marked unstable if $\rho \geq 1.0$.
- **Queue Wait Time ($W_q$):** $W_q = \frac{\rho}{\mu - \lambda}$
- **Total Time in System ($W$):** $W = \frac{1}{\mu - \lambda}$
- **Expected Number of Tasks in Queue ($L_q$):** $L_q = \frac{\rho^2}{1 - \rho}$

### Inference Visibility & Cost Savings (`InferenceProfiler` in `scaffold/agent/core/inference_profile.py`)
- **Prefill/Decode Latency Estimation:**
  $$\text{Prefill Ratio} = \frac{\text{input\_tokens}}{\text{input\_tokens} + \text{output\_tokens}}$$
  $$\text{TTFT} \approx \text{worker\_latency} \times \text{Prefill Ratio}$$
  $$\text{TPOT} \approx \frac{\text{worker\_latency} - \text{TTFT}}{\text{output\_tokens}}$$
- **Continuous Batching Acceleration:** Predicts the speedup factor using the batching scaling formula:
  $$T(B) = \frac{B}{1 + 0.15 \times \log_2(B)}$$
- **Prompt Cache Savings:** Tracks the actual dollars saved by computing:
  $$\text{Savings} = 0.90 \times \text{Prefill Ratio} \times \text{cost\_usd}$$

### Async Defenses (`scaffold/agent/core/async_engine.py`)
- **Circuit Breaker:** Tracks rolling failure rates of API calls across a closed window. If failures surpass the threshold (e.g., 50%), the breaker transitions from `CLOSED` to `OPEN`, failing fast on subsequent requests without invoking the API, then transitions to `HALF_OPEN` after a timeout window to test provider recovery.
- **Backpressure Queue:** Instantiates a bounded `asyncio.Queue`. When full, it returns `False` under a reject policy, preventing cascade failures under excessive loads.

## 3. The Flaky PER Test — Diagnostic & Root Cause

### Error Trace
```
AssertionError: 4 != 5
in tests/test_p6_self_learning.py::TestPriorityExperienceReplay::test_alpha_zero_uniform_sampling
```

### Root Cause Code Snippet (`scaffold/agent/reward_store.py`)
```python
    def get_prioritized(self, n: int = 32, alpha: float = 0.6) -> list[Episode]:
        # ...
        weights = [abs(e.reward) ** alpha for e in episodes]
        total_w = sum(weights)
        if total_w == 0:
            import random
            return random.sample(episodes, min(n, len(episodes)))
        import random
        probs = [w / total_w for w in weights]
        chosen: list[Episode] = []
        population = list(range(len(episodes)))
        indices = random.choices(population, weights=probs, k=min(n, len(episodes)))
        seen: set[int] = set()
        for i in indices:
            if i not in seen:
                seen.add(i)
                chosen.append(episodes[i])
        return chosen[:n]
```

### Explanatory Analysis
1. `random.choices(..., k=min(n, len(episodes)))` draws samples *with replacement*.
2. Because it is drawing with replacement, the drawn list of `indices` will often contain duplicate index elements.
3. The method loops through `indices` and deduplicates them using the `seen` set.
4. As a result, if `n` elements are requested, but 1 or more duplicates are drawn, the length of `chosen` drops below `n`.
5. When `alpha` is set to `0.0` (as in `test_alpha_zero_uniform_sampling`), all weights evaluate to `1.0`. Thus, `total_w` is non-zero, the weighted branch is triggered, duplicates are selected, and deduplication returns fewer than 5 unique episodes, violating the test assertions.
