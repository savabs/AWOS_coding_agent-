## The one-line state

## What the problem was

`Worker.execute_task()` made exactly one model call per task and parsed
SEARCH/REPLACE blocks out of the reply. Grepping the real pipeline — `worker`,
`orchestrator`, `planner`, `verifier` — for `tool_use` / `tool_choice` /
`tools=` returned nothing: the executing model had no tools at all. It could
not open a second file, find a caller, or run the tests and react. It had to
emit a correct patch from one blind look at whatever the Planner pre-selected.

`.awos/reward_store.jsonl` put that at 40% success on `bug_fix` and 50–58% on
`new_feature` over 227 episodes.

The scaffolding around it — LinUCB routing, MCTS, the process reward model,
PromptEvolver — all chooses *which model does the guessing*. None of it lets
the agent look. That is why it had not moved the number much.

## What the benchmark measures

Both executors get the identical case and differ only in what they can see.
Six of the twelve cases carry a `context/` directory holding the constant,
renamed field, signature or helper the fix depends on — unreachable for
single-shot by construction, findable by an agent that can open files.

`scripts/validate_bug_cases.py` refuses a case whose tests pass on `buggy.py`
(measures nothing), one that fails even on `fix.py` (unsolvable), and a
multi-file case whose fix uses nothing from `context/` (does not
discriminate). Proven to discriminate offline: an oracle stub scores 12/12, a
do-nothing stub scores 0/12.

## Bugs found and fixed along the way

- `StructBuilder` used the dead tree-sitter ≤0.21 API inside a bare `except`,
  so `langs` was always empty and STRUCT.xml silently extracted **zero symbols**.
- `RewardStore.get_prioritized()` sampled **with** replacement then de-duplicated,
  so ~41% of draws returned a short batch and starved the router's training
  data. Replaced with Efraimidis–Spirakis sampling without replacement.
- `requirements.txt` could not be installed at all: `tree-sitter-rust==0.21.0`
  and `xxhash>=4.4.1` do not exist, `google-generativeai` is the wrong package
  for `from google import genai`, and `openai`/`numpy`/`pytest-timeout` were
  undeclared despite being module-scope imports.
- `DAGExecutor` serialised tasks on their **primary** file only; a multi-file
  task sharing a secondary file with another would have run concurrently, two
  threads writing one file.
- The test suite could not run **at all** — collection aborted on duplicate
  `test_case.py` basenames under `tests/fixtures/`.

## Notes for whoever picks this up

`.awos/` is tracked **deliberately** — it holds the reward store, error
patterns, skills and goals the system compounds on. Do not add it to
`.gitignore`; that was tried in this session and reverted.

Cost estimates live in `PRICES` in `scaffold/agent/agent_loop.py`. An unpriced
model is costed at zero rather than guessed at, so add new ids there before
relying on `--max-cost`.
