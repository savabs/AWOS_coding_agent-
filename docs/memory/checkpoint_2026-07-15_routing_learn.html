Checkpoint: Routing Learning Repair — Self-Learning Loop Proven

Phase 4 — Product-Market Fit · 2026-07-15 · doc/checkpoint · topic/routing

Session Summary

Fixed the three bugs that prevented AWOS's LinUCB contextual bandit from ever learning. The routing system now cold-starts from historical RewardStore data, adaptively admits more experience over time, and persists learned weights across action-space changes. 31 unit tests + live proof demo confirm the self-learning loop is operational.

THE MOAT IS NOW PROVEN. The routing learning pipeline — which was the #1 stated priority from the July 11 checkpoint — now works: RewardStore accumulates outcomes → warm_start primes LinUCB → ReplayGate adaptively admits episodes → weights persist and compound.

What Changed

1. ml_router.py — warm_start() method (new)

LinUCBRouter.warm_start(reward_store, max_episodes=100) -> int batch-replays historical episodes from RewardStore into LinUCB weights. Uses prioritized experience replay (PER). Skips ReplayGate. Handles OOB action_ids and malformed features gracefully.

  • Empty RewardStore → returns 0, no crash
  • OOB action_id → skipped with debug log
  • Wrong feature dim → skipped with debug log
  • Enough episodes → is_ready() becomes True

2. orchestrator.py — warm_start wiring (6 lines)

After RewardStore and LinUCBRouter are created in __init__:

replayed = self.ml_router.warm_start(self.reward_store, max_episodes=50)
logger.info("[orchestrator] warm-started LinUCB with %d episodes (ready=%s, updates=%d)",
            replayed, self.ml_router.is_ready(), self.ml_router.total_updates())

3. escalation_engine.py — routing_status() method (new)

EscalationEngine.routing_status() -> dict returns a live observability snapshot:

{
  "linucb_ready": bool,
  "linucb_updates": int,
  "actions": {action_name: learned_weights},
  "is_cheap_only": bool,
  "dead_providers": list[str]
}

Graceful defaults when ml_router is None (ready=False, updates=0, actions={}).
