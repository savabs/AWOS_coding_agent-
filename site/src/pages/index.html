How it works · 30 seconds

Record, replay, verified

No scripting and no flowchart builder. You do the chore once in your normal browser, with your normal logins.

1 · record

Do it once

Press record and do the chore. AWOS Replay notes each click, field and choice. Passwords and card numbers are replaced with blanks; they are never saved.

2 · replay

It does it again

Run it from the toolbar whenever you need it. If the site moved a button, the local model finds it again. If it is not sure, it stops and asks you.

3 · verified

It checks the result

Every run ends with a check: the page shows the text you expect and the address is right. You see VERIFIED or CHECK, never a silent "done".

Steps that pay, delete or send something stop and wait for your OK, every time.

Install

One command on your Mac

It sets up the small local model and the Chrome extension. Run it in Terminal.

Questions

Fair questions

How is this different from a macro recorder?

Recorders replay exact positions and break when a site changes. AWOS Replay remembers each target by many clues (its label, text, nearby words) and, when the page changed, asks a small local model to pick the right one. When it cannot be sure, it stops instead of clicking the wrong thing. And each run ends with a check, so you know it worked.

How is it different from an AI browser agent?

An agent works the task out from scratch every time, which is slow, costly and different on each run. Replay follows what you showed it and only uses the model where the page changed. It is predictable, and on a local model it costs nothing per run.

Is a shared recipe safe to add?

A recipe is only a list of steps. The recipe page shows every step in plain language before you add it, the extension asks you to confirm, and risky steps (pay, delete, send) still stop for your OK when it runs. Recipes never contain the sender's passwords or data.
