Security and privacy

AWOS is built to run unattended on code you care about. These are the guarantees it makes and how each one works.

Runs on your machine

The worker, the queue, job folders and logs all live on your computer, under ~/.awos/host/ by default. There is no AWOS cloud service holding your code. The only thing that leaves your machine is the context sent to the model provider you chose, and with a local model nothing leaves at all.

Your checkout is never edited

Each job works in its own git worktree at your current commit. The review branch is assembled with git plumbing and a temporary index, so your HEAD, index, working tree and uncommitted changes are not read-modified-written.

Nothing is pushed

Results land on a local branch awos/<id>. The handoff has no network git operation: you decide what to merge and what to push.

Secret scan on every handoff

  • The diff is scanned for credential patterns and for the values of secrets in the job's environment. If it finds one, the branch is blocked and the job is marked as such.
  • A secret found in the report is redacted. Findings name the kind and location, never the secret value.
  • Some paths are never handed off whatever the workspace contains: .env files, *.pem, *.key, id_rsa*, the .awos/ folder, bytecode and test caches.

Local-only jobs

awos submit --privacy local_only runs a job with cloud API keys present but empty in its environment, so a cloud call cannot authenticate. This fails closed: if no local model is available, the job cannot quietly fall back to the cloud. Keys that only authenticate your local model server are kept.

Hard budgets

Every job has a dollar cap (--budget, default 1.0) that bounds all of its attempts. Spend is counted by AWOS from its own model calls.

Keys

  • awos keys checks providers with free, read-only requests and never prints key values.
  • When a key is wrong, revoked or out of credit, jobs pause as blocked instead of retrying against a dead key, and you get one notification.

Reporting a problem

Early-access members have a direct line to the builder. If you find a security issue, use it, or reach us through the access form.
