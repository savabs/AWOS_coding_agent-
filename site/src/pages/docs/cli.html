CLI reference

The commands you use day to day. Run any of them with --help for the same information in your terminal.

awos                              # interactive session in the current repo
awos "GOAL"                       # one task: run it, then review
awos fix URL [--dry-run] [--budget USD] [--pr|--push]   # fix a GitHub issue or a PR's failing checks
awos doctor [--json]              # check your setup (spends nothing)
awos submit --repo PATH [--budget USD] [--privacy local_only|cloud_ok] "GOAL"
awos serve --worker [--once] [--poll SECONDS]
awos status [--digest] [JOB_ID]
awos cancel JOB_ID
awos unblock JOB_ID
awos keys [--json]

awos

Opens an interactive session inside a git repository. Type tasks in plain English; each one is queued and run by the background worker, which AWOS starts for you if it is not already running. Progress appears above the prompt while you keep typing. When a job finishes, press d (diff), m (merge into your current branch), r (reject), f (follow-up from this branch) or o (open report). Slash commands: /status, /diff ID, /merge ID, /reject ID, /follow ID, /open ID, /cancel ID, /watch, /keys, /help, /quit. Ctrl-C leaves the session; background jobs keep running.

awos "GOAL" does the same for a single task: it queues the goal, shows progress until it finishes, and then offers the same review keys. The goal must contain a space, so a mistyped command is never run as a paid job.

awos fix

Run inside your clone of a GitHub repository, with the gh CLI logged in. An issue URL (.../issues/N) becomes a job whose result is the local branch awos/issue-N-<slug>; a pull request URL (.../pull/N) checks out the PR, reads its failing CI logs and puts the fix on awos/pr-N-fix on top of the PR head. Flags: --dry-run (print the goal and commands, run nothing), --budget USD, --pr (issue: push and open a draft PR), --push (PR: push the fix branch), --allow-dirty, --goal TEXT. Nothing is pushed without --pr or --push. See Fix a GitHub issue or PR.

awos doctor

Checks Python, git, your model key (without spending), the local model server, the current repo and its test command, the job folder, and whether the worker is running. Each problem comes with a one-line fix. It exits 0 when everything required is OK.

awos submit

Queue a job and print its id.

awos submit --repo . --budget 0.50 "Add a --dry-run flag to the import command"
ArgumentMeaning
GOALWhat to get done. Quote it if it has spaces.
--repo PATHThe git repository the job works on. Puts the job in the background worker's queue.
--budget USDMost the job may spend, in US dollars. Default 1.0; 0 means no cap.
--privacy local_only|cloud_oklocal_only blanks cloud API keys for this job so it can only use a local model. Default cloud_ok.

awos serve --worker

Run the background worker: take queued jobs one at a time until stopped.

FlagMeaning
--workerRun the queue worker. Without it, awos serve starts the local web dashboard instead.
--onceExit when the queue is empty.
--poll SECONDSSeconds between queue checks. Default 2.

awos status

List the queue's jobs, or show one job when you pass its id.

ArgumentMeaning
JOB_IDShow one job's record.
--digestA short summary for humans: what is running, what is queued, what finished since the last digest, what is blocked (with the action to take), and today's spend.

awos cancel

Cancel a job. A queued job is cancelled at once; a running job stops at its next step. A job that already finished is left as it is.

awos cancel <id>

awos unblock

Re-queue a job that is blocked on credentials, after you fix the key. The attempt the block used is refunded. The worker also does this on its own once the keys check out again.

awos unblock <id>

awos keys

Check each configured model provider without spending anything. Each check is a free, read-only request; key values are never printed.

StatusMeaning
okThe provider answered and accepted the credential.
unauthorized401 or 403: the key is wrong, revoked or out of credit.
unreachableNo answer: offline, DNS, timeout or a server error.
not-configuredNo key set (for a local model: no server and no URL set).

--json prints the same result as JSON.

Environment variables

VariableMeaning

AWOS_PROVIDER=localUse your local model server.
AWOS_HOST_DIRWhere the queue, job folders and reports live. Default ~/.awos/host.
