How it works

From ticket to review branch, without touching your checkout

You describe the change in a sentence. AWOS does the rest in the background and only interrupts you for a real decision.

1 · queue

Submit a ticket

awos submit adds it to a local queue with a budget cap. Queue as many as you like.

2 · isolate

Own workspace

Each job gets a separate git worktree at your current commit. Your files and branches are never edited.

3 · verify

Checked by tests

AWOS writes acceptance tests for the goal, runs your suite, and records what passed. A secret scan runs before handoff.

4 · review

Branch + report

You get awos/<id> with a short report: tests, cost, time, warnings. Merge it or delete it.

Docs

Get started in five minutes

Quickstart

Early-access members receive an install link. AWOS runs on macOS and Linux with Python 3.12, inside any git repository.

# 1. add your model key (Anthropic, or run a local model instead)
export ANTHROPIC_API_KEY=...

# 2. queue a ticket for this repo, with a budget cap
awos submit --repo . --budget 0.50 "Fix the date parser so 2024-02-29 is accepted"

# 3. start the background worker (or install it to run at login)
awos serve --worker

# 4. next morning: see what finished
awos status --digest

# 5. review and merge the branch
git diff main...awos/<id>
git merge --no-ff awos/<id>

Each finished job writes report.md with the goal, the test results, cost, time and anything it was unsure about.

Concepts

  • Job. One ticket: a goal, a repo and a budget. Jobs run one at a time from a local queue and survive restarts.
  • Workspace. A throwaway git worktree at your current commit. Your checkout, uncommitted work and branches are left alone.
  • Verification. AWOS generates acceptance tests from the goal, runs your test suite in the workspace, and reports pass and fail counts. If a repo has no tests, it asks a model to check the result against the goal and says so in the report.
  • Review branch. awos/<id>, created locally from the workspace diff. Bytecode, caches and secrets are never included. Nothing is pushed.
  • Blocked. If a model key stops working, jobs pause as blocked instead of failing, you get one notification, and they resume when the key works again.

Models and cost

You bring your own model provider and pay them directly. AWOS records the cost of every call and stops a job at its budget.

  • Cloud default: Claude Haiku 5.5. Typical small ticket: under one cent. Prompt caching cuts repeated context by about 90%.
  • Local: run an open model such as Qwen3.5 9B on your own machine with AWOS_PROVIDER=local. Free per ticket and fully offline, best for routine fixes.
  • Budgets: --budget per job, plus a daily cap. A job that hits its cap stops and reports where it got to.

CLI reference

awos submit --repo PATH [--budget USD] [--privacy local_only|cloud_ok] "GOAL"
awos serve --worker [--once]      # run queued jobs
awos status [--digest]            # queue, running job, finished, blocked
awos cancel ID                    # stop a queued or running job
awos unblock ID                   # retry a job blocked on credentials
awos keys                         # check model keys without spending

FAQ

  • Does my code leave my machine? Only the context sent to the model provider you choose. With a local model, nothing leaves.
  • Can it break my repo? It never edits your checkout or pushes. All work lands on a separate local branch you review.
  • What kinds of tickets work best? Well-defined bugs, small features, test writing, refactors and migrations with a clear definition of done. Vague product decisions still need you.
  • How is this different from an interactive coding assistant? AWOS is built to run unattended through a queue, verify its own work, and hand you finished branches, instead of pairing with you in a chat.
Security and privacy

Built to run unattended on code you care about

  • Runs on your machineThe worker, queue and logs live on your computer. There is no AWOS cloud holding your code.
  • Never touches your checkoutSeparate worktree per job; results arrive as a local branch.
  • Nothing is pushedYou decide what to merge and push.
  • Secret scan on every handoffA branch is blocked if the diff contains a credential.
  • Local-only mode--privacy local_only blanks cloud keys for that job, so it can only use your local model.
  • Hard budgetsPer-job and daily caps; spending is counted from your own process only.
