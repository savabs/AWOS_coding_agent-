Fix a GitHub issue or PR

Paste a GitHub link into awos fix from your local clone. AWOS reads the issue or the failing CI logs, does the work on a new local branch, runs the tests and tells you what it did. Nothing is pushed unless you ask.

Before you start

  • AWOS is installed and has a model (awos doctor says so).
  • The GitHub CLI is installed and logged in: gh auth login. AWOS uses it to read issues, PRs and check logs.
  • You are inside a clone of the repository the link points to (its origin remote, https or ssh, must match).

Fix an issue

# see exactly what AWOS will be asked to do; runs nothing
awos fix https://github.com/OWNER/REPO/issues/12 --dry-run

# do it, spending at most $0.50
awos fix https://github.com/OWNER/REPO/issues/12 --budget 0.50

AWOS builds a goal from the issue title, description, labels and the most recent human comments (HTML comments, images and bot comments are left out), adds the issue link, and runs it as a normal AWOS job starting from your current commit. Your working tree must be clean; pass --allow-dirty to run anyway (uncommitted changes are not part of the job).

When it finishes you get a short report:

awos fix: done
  Branch:  awos/issue-12-crash-on-empty-input
  Files:   widget/cli.py, tests/test_cli.py
  Tests:   12 passed
  Cost:    $0.0123
Next:
  git diff main...awos/issue-12-crash-on-empty-input
  Open a draft PR (pushes the branch):
    git push -u origin awos/issue-12-crash-on-empty-input
    gh pr create --draft ...

Add --pr to have AWOS push the branch and open a draft pull request whose body holds the report and Fixes #12. It only does this when the job finished with a reviewable branch.

Fix a PR's failing checks

Typical case: a dependency bump whose CI went red.

awos fix https://github.com/OWNER/REPO/pull/34 --dry-run
awos fix https://github.com/OWNER/REPO/pull/34

AWOS lists the PR's checks, and for each failing GitHub Actions run reads the failed-step log (trimmed to the end of the log plus the error lines). If nothing is failing it says so and stops. Otherwise it checks out the PR into your clone (gh pr checkout; your tree must be clean), and asks the agent to make the failing checks pass without reverting the PR's intent. The result is a new local branch awos/pr-34-fix on top of the PR head; review it with git diff <pr-branch>...awos/pr-34-fix.

Add --push to push awos/pr-34-fix to origin. The report also prints the commands to update the PR branch itself and to leave a comment with gh pr comment. Use --goal "..." to add instructions, or to work on a PR whose checks are green.

Flags

FlagMeaning
--dry-runPrint the goal text and the commands it would run. Reads from GitHub, changes nothing, spends nothing.
--budget USDMost the job may spend. Default 1.0 (or AWOS_APP_BUDGET); 0 means no cap.
--prIssues only: push the branch and open a draft PR.
--pushPRs only: push awos/pr-N-fix to origin.
--allow-dirtyIssues only: run even with uncommitted changes.
--goal TEXTExtra instructions for the agent.

If something goes wrong

  • gh is not installed / not logged in: install it, then gh auth login.
  • origin is X, but the URL is for Y: run the command from a clone of the repository in the link.
  • Ctrl-C while it runs: you only stop watching; the job keeps running. Check it with awos or awos status.
  • A failed job still leaves its work on a branch ending in -failed so you can salvage it; no PR is opened and nothing is pushed for it.
