How it works

From issue to review branch, on your machine

You describe the change in a sentence. AWOS does the work locally and only interrupts you for a real decision.

1 · model

Run a local model

Start an open model on your computer (we test with Qwen3.5 9B on a laptop) and set AWOS_PROVIDER=local.

2 · isolate

Own workspace

Each task gets a separate git worktree at your current commit. Your checkout is never edited.

3 · verify

Checked by tests

AWOS runs your tests on the change and records what passed. A secret scan runs before handoff.

4 · review

Branch + report

You get awos/<id> with a short report: tests, steps, time. Merge it or delete it.

Local · pre-registered · not run yet

We do not claim that AWOS beats other agents on local models. A small local model is slower and weaker than a frontier cloud model. Today AWOS suits routine, well-tested changes where privacy or cost matters more than speed.

Private by design

Your code stays on your computer

  • Runs on your machineThe agent, model, queue and logs live on your computer. There is no AWOS cloud holding your code.
  • Local-only mode--privacy local_only blanks cloud keys for that task, so it can only use your local model.
  • Works offlineWith a local model, a task needs no network at all.
  • Never touches your checkoutA separate worktree for each task. Results arrive as a local branch.
  • Nothing is pushedYou decide what to merge and push.
  • Secret scan on every handoffA branch is blocked if the diff contains a credential.
